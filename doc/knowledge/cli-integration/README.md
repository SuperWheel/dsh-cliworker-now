# CLI 接入索引

本分类回答“增加一种 CLI 时，需要在哪些层接入”。按 v0.8.1 当前源码整理；12 种 CLI 的真实支持范围仍以安装版协议、测试及 [实际验证记录](../../tasks.md) 为准。

**完整执行流程**：[新 CLI 接入流程](new-cli-onboarding.md)把下列笔记串成逐项可核对的 18 个阶段，列出每一步要改的文件、国内版与国际版的形态判定、测试与真实验收清单。接入新 CLI 时先读该文，再按需进入下面的原子笔记。首次按此流程实施的是 [v0.8.8 PRD](../../prd/2026-11-07-v0.8.8-PRD.md)。

## 2、接入完成核对表

- 身份与视觉：稳定 CLI ID、用户名称、自动命名短名、图标、主题和设置入口齐全。
- 发现与启动：macOS/Windows 均能解释安装位置；手动路径优先级、安装损坏、缺运行时和取消能够区分。
- 协议与会话：明确握手、真实模型 ID、session ID、恢复、事件、终态和 transport 兼容规则。
- 原生数据：分别声明账号、目录、响应账单、本轮账单、会话累计、积分、上下文与公开过程的来源；没有公开的数据保持未知。
- 宿主集成：Host/Gateway/Client 契约、原生子会话、权限、运行中输入、互斥、工具桥和生命周期都有对应处理。
- 验证与文档：关联回归、必要类型检查、隔离构建和目标平台验收分别留证；同步协议文档、README、设计和实际验证记录。

此表是实施检查入口，不代表每个 CLI 都具有全部可选能力。缺少原生能力时，应声明限制并拒绝不支持的操作。
