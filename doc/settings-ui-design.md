# 设置页统一设计规范

适用版本：v0.7.8 起；适用范围：CLI Worker 设置中的「CLI Worker 设置」通用页、各 CLI 连接页及以后新增的设置内容。以“账号与登录”“项目默认设置”的文字层级、原生控件，以及模型行的 16px 内容留白为基准。macOS 与 Windows 使用同一套样式。

本文记录当前约定，不另设产品版本号。修改参数时，同步实现与本文；实际检查结果写入 `doc/tasks.md`。

## 1. 文字层级

字体统一使用 Harness 的 `--dsw-font-family`。字号使用宿主对应主题 token；下表 px 指 CSS 像素，截图受系统缩放影响，不能直接拿物理像素当 CSS 像素。

| 层级 | 示例 | 字号 / 行高 | 字重 | 颜色与格式 |
| --- | --- | --- | --- | --- |
| CLI 页标题 | ZCode、Claude Code | 24px / 32px | 600 | 主文字色；h2；无默认 margin |
| 分区标题 | 账号与登录、项目默认设置、高级设置 | 14px token / 22px | 500 | 主文字色；h3；无默认 margin |
| 设置项标签 | 模型、思考强度、运行中发送、CLI 路径管理 | 14px token / 22px | 400 | 主文字色；普通 label/span，不再使用 h3/h4 |
| 设置项说明 | 新对话沿用的默认模型 | 12px token / 18px | 400 | 次级说明色 `--dsw-alias-label-tertiary` |
| 操作反馈 | 正在保存、保存成功、失败原因 | 12px token / 20px | 400 | 保持可读、允许换行；使用 status 语义 |

“高级设置”与前两个分区同级；其内部的“运行中发送”“CLI 路径管理”与“模型”“思考强度”同级。不要靠加粗、放大或重复标签制造额外层级。

## 2. 间距与分隔线

距离以元素行框/内容框为测量边界，而非某个汉字的墨迹边缘；同一行中标签与控件保持垂直居中，多行文字正常增加高度。

| 参数 | 统一值 | 使用位置 |
| --- | --- | --- |
| 内容行上下留白 | 16px / 16px | 模型、强度、账号内容及展开后的路径内容 |
| 分隔线后的分区留白 | 16px | 线到下一个分区标题行容器外框 |
| 分区标题行容器最小高度 | 36px | 标题与刷新/展开按钮同排，22px 文字行框垂直居中 |
| 标题行后的间距 | 8px | 标题行到内容行外框 |
| 设置标签到说明 | 4px | 同一文字组内部 |
| 纵向文字组到输入框 | 16px | 路径等需要整行输入的设置 |
| 输入框到操作行 | 8px | 路径刷新/恢复自动识别 |
| 同排操作按钮之间 | 8px | 各设置操作行 |
| 左侧文字与右侧控件 | 24px；窄屏 12px | 模型、强度等左右布局 |
| 分隔线 | 0.5px，`--dsw-alias-border-l2` | 相邻设置项、相邻分区 |

必须遵守以下组合规则：

- 内容到分隔线由内容行自己的 16px 留白负责，分区之间不再叠加额外外边距。
- 相邻两个设置项之间只有一条线；最后一项与下一分区的边界也只有一条线，不能同时画末行底边和分区顶边。
- 36px 标题行容器底部到首个内容组外框为 **8 + 16 = 24px**。模型/路径对应文字组，账号对应 36px 控件行；普通分区与高级设置必须一致。同排文字在各自容器内居中，不把容器内部的居中留白误作边距差异。
- 模型文字组底部到分隔线为 **16px**，线到下一项文字组顶部也为 **16px**。长说明自然换行，仍保留相同上下 padding。
- 保存反馈只在保存中或失败时出现；保存成功不显示“已保存”之类文字，结果由控件自身的值体现（2026-10-25 用户要求删除全部保存后小字，含默认设置、发送方式、同时对话数、界面语言与智能体预设）。反馈与前一内容行之间复用已有留白，反馈底部距下一分隔线为 16px；空提示不保留空白行。
- 折叠容器外层不放内容 padding；留白随内部内容一起收起，避免高级设置折叠后留下额外空间。

## 3. 控件与对齐

| 控件 | 约定 |
| --- | --- |
| 模型 / 强度 / 运行中发送选择框 | 原生 md Button；宽度 `min(240px, 48%)`；靠右对齐 |
| 下拉菜单 | 原生 Menu；宽度实时跟随对应选择框，左右边缘对齐；最大高度 300px，内容可滚动 |
| 刷新 / 展开按钮 | 原生 md Button；36 × 36px；只按钮本身显示交互效果 |
| 路径输入框 | 原生 Input；占满当前内容宽度；与标签、分区线左侧和右侧对齐 |
| 路径操作行 | 靠右对齐；空间不足时允许换行；不挤压或截断输入框 |
| 开关 | 使用原生 Switch 的尺寸与交互，不改造成自定义图形 |

不同设置内容使用横向或纵向布局，但复用同一文字、内容留白及分隔线规则。不要给某个 CLI 单独写字号或修补 margin。

## 4. 交互与状态

- 模型与思考强度选择仅立即更新本地草稿；离开当前 CLI 页（切换其他 CLI 或智能体设置）或以叉号、点击窗口外侧、原生 Esc 等任何方式关闭设置窗口时，后台保存最后的完整组合，不等待保存再导航。关闭不取消已提交的保存；快速重开保留未完成选择，后续离页写入按 CLI 串行，旧回执不覆盖新草稿。失败保留选择和短错误，重开对应页可查看，后续离页或关闭时重试。页面初读、无修改的导航或刷新目录不写偏好；来源刷新清除旧草稿。
- “调用前询问模型”位于「CLI Worker 设置」通用页「任务调度」分区、“同目录写任务并行”之后，复用 `cwn-setting-row` 横向布局：左侧标签与说明，右侧原生 Switch，与上一项共用一条分隔线。全局保存于通用设置，默认开启；切换后立即保存，保存中显示进度，失败恢复原值并显示短错误。按用户要求不显示“已保存”之类的成功提示。
- 以下“运行中发送”偏好用于历史兼容消息路径；v0.8.1 原生子会话的运行中输入遵循文末的原生 Inbox 规则。“运行中发送”置于高级设置内、CLI 路径管理之前，使用同一行布局与单条分隔线。下拉选项仅为“引导、插队、排队”，按项目和 CLI 独立自动保存；能力和已保存值来自 Host，初次展开只读。当前确认支持原生引导的 Codex、Hermes、Pi、OMP 默认引导，其余默认排队且引导选项禁用。按本次用户授权，原 policy 1 项目设置一次性更新为对应能力默认值，后续手动选择以 policy 2 保存。旧 Worker 的原有 transport 未接通引导时，在该对话明确显示排队及原因，不暗改其历史执行协议。
- 运行中发送的说明随选择变化：引导立即交给 CLI 在当前运行中处理，不保证打断正在生成的内容；插队先停止当前轮，确认停止后沿原对话优先发送；排队等待当前轮正常结束后沿原对话按顺序发送。不支持引导时在说明补充原因。读取失败不展示猜测的默认值，并提供重试；保存失败保留选择和错误，允许重选同一项重试。关闭或切换 CLI 后忽略旧请求结果。
- 高级设置初始折叠，仅右侧箭头负责展开/收起；标题文本不是整行按钮。
- 折叠采用 220ms 高度过渡、180ms 透明度过渡；箭头旋转 220ms。减少动态效果偏好下关闭过渡。
- 收起内容不可被键盘聚焦；输入保留可访问名称，说明与输入建立关联。
- 路径管理保留说明、输入、恢复自动识别和刷新，不重复显示“CLI 路径”或单独的来源标签。
- 颜色、圆角、悬停和焦点使用 Harness 主题与原生组件，不写死浅色背景或系统专属字体。
- 设置窗口左侧导航与右侧内容的滚动条平时隐藏（Harness `--dsh-scrollbar-thumb` 置透明），滚动时显示，最后一次滚动 900ms 后隐藏；指针移到滑块上时也显示。滚动标记由布局容器上的捕获监听写入 `data-scrolling`，随窗口卸载清理。
- 开关类设置的说明保持一行；开关本身显示保存后的状态，保存成功不再另显确认文字，只保留保存中与失败反馈。

## 5. 实现入口与扩展步骤

- `src/client/styles.ts` 的 `settingsStyles`：公共排版参数、标题、内容行、账号、模型菜单与反馈。
- `src/client/management-styles.ts`：高级设置折叠与纵向路径布局，使用公共参数。
- `src/client/settings-dialog.tsx` / `cli-executable-settings.tsx`：分区结构、标签、原生控件与可访问交互；`native-settings-choice.tsx` 统一选择框，`running-message-settings.tsx` 管理运行中发送的读取和保存。

新增内容时：

1. 先确定是分区标题还是普通设置项，不凭视觉感觉新增标题级别。
2. 复用公共分区、文字组、内容行及间距变量；需要纵向输入时沿用路径区域的结构。
3. 明确唯一的分隔线归属，不用空元素、空反馈或额外 margin 补位置。
4. 只针对改动做最小检查：实际界面对齐、展开/折叠、溢出，以及必要的相关回归和隔离构建；纯样式不增加只检查 class 字符串的测试。
5. macOS 与 Windows 的布局应一致；未检查的平台或状态如实写入验证记录。全量验收仍只在获准的版本发布时执行。

本规范约束设置表单的共同基础；智能体角色卡片和原生账号终端有各自内容结构，扩展其设置表单时仍复用上述文字层级与间距，不将 CLI 表单排版直接套到终端画面。

插件绘制的登录/退出窗口（`.cwn-login-*`，`src/client/account-login/login-window.tsx`）替代 Antigravity、Codex、Claude Code、Qoder / Qoder CN、Grok、ZCode、MiMo，以及 OpenCode / Hermes 指定服务商时的终端画面，按 Host 给出的模板绘制：`trust`（信任文件夹）、`choice`（菜单选项按钮）、`browser`（重新打开 / 复制登录链接 + 等待）、`browserCode`（链接 + 授权码输入）、`deviceCode`（22px 600 等宽验证码块，一层背景，复制 / 打开验证页 + 等待）、`secret`（密码型 API Key 输入，提交后清空）、`waiting`、`result`、`native`（警示色块并展开原生终端，终端自动获得键盘焦点）、`terms`（CLI 自带的服务条款：说明文字、sm ghost「服务条款」「隐私政策」链接按钮、一行默认不勾的复选框（次级色文字，复选框 accent 为主文字色，与文字顶端对齐），以及 md primary「同意并继续」和 md ghost「取消」）。纵向步骤列表：28px 圆形序号（待办三级边框、当前主按钮填充色、完成成功色勾），步骤间 0.5px 二级边框竖线；步骤标题 14px/22px（当前 500），说明为次级色，提示 12px/18px 三级色；步骤内元素间距 12px，按钮间距 8px，主操作用 md primary，次要操作用 sm outline/ghost。粘贴后的提醒为淡绿色色块（成功色 12% 混合背景，圆角，无左侧色条与键帽），带成功色勾图标与加粗的「按回车键完成登录」；警告为同样形式的淡警示色块。结果页居中：40px 成功图标、18px/26px 600 标题、次级说明，按钮在下方 12px；单账号 CLI 已登录时不启动原生终端，改为与「账号」窗口相同的卡片页：顶部 14px 500「当前已登录 <CLI>」与 12px 三级色说明，一张当前账号卡片（左侧 32px 方块内为 CLI 品牌图标，中间服务商或 CLI 名与「登录方式 · 邮箱」，右侧成功色 12px 圆点「已登录」），下方右对齐 ghost「关闭」与 primary「切换账号」（不能切换时只有 primary「关闭」），无「显示原生终端」底栏。底部以 0.5px 分隔线隔开，同一行左侧为 12px 三级色的终端状态（如「账号终端已关闭」），右侧为「显示原生终端」。文案只来自插件固定词条与 Host 引导。账号弹窗默认宽 480px（不超过 90vw），用于登录窗口、「账号」窗口及退出来源等选择；弹窗内有可见原生终端时恢复 720px。其他 CLI 仍使用 `.cwn-account-guide` 横幅规则（一层背景、14px、3px 语气色左条）。

「账号」窗口（`.cwn-accounts-*`，`account-login/accounts-window.tsx`）用于 OpenCode、Pi、Kimi、ZCode、Hermes、OMP：设置页这几个 CLI 只有「账号 / 登录账号」与「账号终端」两个按钮，摘要行不再放「退出」。账号弹窗正文与标题之间只留 Modal 头部 12px + 4px（`.cwn-account-dialog-content>:last-child`），不叠加 Modal 默认的 20px；所有块贴齐同一内容边线（弹窗左右 24px），块内不再额外缩进。浅色主题下 `bg-layer-1` 与弹窗底色几乎相同，卡片、面板与空状态统一用与下拉框相同的淡灰 `--dsw-alias-interactive-bg-hover` 作底，卡片内按钮悬停改用 `interactive-bg-active`。窗口内块间距 20px。每个账号为一张卡片：圆角、内边距 10px 8px 10px 12px，卡片间距 8px，无边框；左侧 32px 圆角方块显示服务商首字母（二层背景、0.5px 二级描边、次级色 13px 600），中间为 14px 500 服务商名，下方 12px/18px 三级色「登录方式 · 邮箱」（API Key / 账号登录；同服务商多个 OAuth 账号靠邮箱区分），右侧 ghost「退出」。点击后在卡片内以 0.5px 分隔线隔开展开确认：左侧 12px 次级色说明，右侧 ghost「取消」与 primary「确认退出」，不另开弹窗。账号存放在多个位置（Pi、OMP）时按位置分组：组头为 12px/18px 500 次级色组名「<CLI> 原生目录 / 插件目录 / 其他配置」，同行 12px 三级色说明（直接运行 <CLI> 时也会使用 / 只在 CLI Worker 中使用 / 来自环境变量或配置文件），组头到卡片 8px；每张卡片只在自己的位置退出。无法单独退出的卡片显示「在原生终端中退出」；来自环境变量或配置文件的卡片说明「在原配置中管理」，不提供退出按钮。空列表为淡灰底居中次级色提示。旧版 Host 不给行级位置时，退回列表下方按来源的 outline 按钮。底部右侧为带加号图标的 outline「添加账号」。「添加账号」页：顶部 14px 500「选择要登录的服务商」与下方 12px 三级色说明；服务商为两列卡片单选（`role=radio`，间距 8px，最小高 56px，最多约 312px 高后滚动），卡片含首字母方块、14px 500 名称（溢出省略），已登录者下方为成功色 12px「已登录」；选中卡片为 1px 强调色描边、8% 强调色混合底，首字母方块转强调色；最后一张为「其他服务商 / 在原生终端中选择」（ZCode 只有两家无此项）。已登录的单凭据服务商在卡片下方显示淡警示色块「继续会替换现有凭据」；可多凭据的服务商显示淡灰面板内的「添加另一个凭据 / 替换 <邮箱或第 N 个>」单选（行距 8px）；最下方右对齐 ghost「返回」与 primary「继续」。运行中的窗口上方为次级色 500 的一行标题（如「登录到 DeepSeek」），关闭后回到列表并刷新。

## v0.8.1 原生对话中的设置入口

当前 Worker 对话留在右侧 CLI Worker 栏，正文使用真实 DSH conversation.content 的 embedded 布局。实际 InputBar、QueueDock、菜单、统计与弹层保留宿主组件、样式、键盘及交互，不自行绘制输入框、操作图标、排队条或统计区；管理栏沿用原版本的返回、Worker 名称/标题和任务选项，不增加父面包屑、对话/轨迹页签、标准模式或原生主页面页头按钮。原生 continuable 子 Agent 的停止/发送布局保持原样。

模型与强度使用实际原生 ModelSelect，目录来自对应 CLI，选择提交到该 Worker 的真实选型接口。权限和规划使用实际原生 PermissionSelect、PlanChip，其可选项与写入权限以 Host 返回的当前 CLI 能力为准。原生公开数据合同允许映射 CLI 设置，不将子会话伪装成根会话，也不替换原生 Inbox 或 keyboard。

CLI 规划/编辑在 PermissionSelect 的公开数据中映射为原生 read-only/workspace-write preset，保存再转回 CLI 模式。图标、按钮、菜单与窄栏文字收起均由原生组件负责；不传自定义 preset 造成内置图标缺失，也不手绘替代图标或增加全权限选项。

运行、消息准入、停止清理期间，以及存在任何原生 next-turn/next-step 消息或历史兼容队列项（含 paused）时，模型、强度与权限设置均不可修改，并在原生位置说明原因。身份不匹配、能力未知、不可写或读取失败时不展示猜测的可用操作。普通主对话保留自己的原生目录、权限与行为；每个 CLI 子会话按明确的 parent/child/Worker 身份读取和保存。父权限或规划状态变化时，公开投影订阅立即使旧可写回执失效并重新询问 Host，取消旧请求，不需关闭再打开侧栏。

ContextMeter、StatsPills 及其菜单接匹配 Worker 的可核查遥测。缺失上下文或用量字段遵循原生隐藏规则；不把 DSH 显示估算、累计用量或补零分类当成 CLI 实际窗口，不增加替代统计按钮或详情区。

原生发送、编辑/移除排队、停止和快捷键由 DSH Session/Inbox 处理；Host 在接收边界桥接 CLI。已接通且就绪的真实运行中 steer 使用原生 CLI 回执；未接通该通路的协议在完整 CLI run 结束清理后的下一执行步接收。两条路径分开说明，不把整轮后续接称为实时引导，也不将原生 next-step 箭头解释为先停止旧轮。已接通 Codex app-server、Hermes HTTP、Pi RPC 和 OMP RPC 并通过模拟协议与真实 Inbox 回归，真实模型范围另见实施记录。旧兼容队列保持历史，不因新一轮自动恢复或执行。

尚未接通的附件、分支等控件保留原位原因和宿主 Tooltip，附件不可用不禁用仍可用的原生指令菜单。没有对应控件的功能放在任务选项详情中，不新增一排按钮。只读旧历史不带输入框。

## v0.8.1 跨平台设置预加载

macOS 与 Windows 共用展示缓存，不改变本规范的字号、控件及间距。首次打开按当前 CLI 优先、最多两个任务预加载全部已启用 CLI 的账号摘要和模型/强度；一个任务内部顺序读取，禁用项不探测。关闭取消未完成工作，保留完成结果，重开只补缺项。每次打开先读取轻量宿主代际、项目、来源版本、目录绑定可用性和最新默认值，不以旧缓存填充不同来源。

账号刷新先完成账号再强制读取该 CLI 模型；模型刷新独立执行。登录/退出、账号管理、路径与开关变化只影响相关 CLI。刷新中保留原有账号摘要但禁用选择，刷新失败清除旧可选目录并保留短错误，不退回先前成功值。项目默认值只由明确选择产生草稿，离开当前 CLI 页或关闭时后台保存；首次预热、无修改的切换及重开不保存默认值。展示缓存仅保存安全摘要和选项，不缓存凭据或执行授权；外部原生账号变化仍由刷新及保存/执行前检查确认。

## 通用页「语言」分区（add-client-i18n，未发布）

面板标题栏的设置按钮打开弹窗时默认进入「CLI Worker 设置」通用页，选中具体 CLI 前不读取任何 CLI 的模型目录；任务详情里的「默认设置」仍直接打开该任务所用 CLI 的页面。「CLI Worker 设置」通用页按「语言」「任务调度」顺序排列两个分区，沿用第 1–3 节的分区标题、内容行、单条分隔线及 `NativeChoice`，不新增字号或间距参数。页头（40px 图标、标题与副标题）下没有 CLI 页的开关状态行，第一分区标题与页头之间补同样的 28px（状态行 20px + 上下各 4px，`.cwn-cli-identity+.cwn-settings-section`），两类页面标题到第一分区的距离一致。「界面语言」一行的说明是「跟随 DSH 时与 DeepSeek Harness 当前语言一致；只影响 CLI Worker 界面。」；选项为「跟随 DSH / 中文 / English」，后两项始终用各自语言书写，切换后仍能认出。读取进度点放在第一分区（语言）标题右侧，读取失败的说明与「重试读取通用设置」放在任务调度分区末尾。

每个字段各自显示保存反馈（正在保存 / 未保存，请重新选择重试；成功不显示文字），反馈仍是行下的同一 `cwn-settings-save` 槽。保存语言成功后整个插件立即重绘为新语言，包括设置窗口本身；其他已打开的面板和窗口由 Worker 快照同步。英文文案通常更长：设置行文字可换行，选择框宽度不随语言变化。新增设置项时，在 `src/client/i18n-messages.ts` 同时补上英文，未补齐的键无法通过类型检查。

## 通用页「任务时限」分区（configure-worker-time-limit，未发布）

「CLI Worker 设置」通用页在「任务调度」之后新增「任务时限」分区，沿用第 1–3 节的分区标题、`cwn-setting-row` 横向布局、单条分隔线与 `NativeChoice`，不新增字号、间距或样式参数。两行依次为：

- 「总时限」：说明「从任务开始计时，到时停止任务；修改只影响之后开始的任务」。选项为 30 分钟、1 / 2 / 4 / 8 小时与「不限制（最长 24 小时）」，按时长升序；部署默认值（插件配置 `timeoutMs`，默认 30 分钟）与当前值不在列表中时一并列出，部署默认值后缀「（默认）」。整小时显示「N 小时」，整分钟显示「N 分钟」，其余显示「N 秒」。
- 「空闲时限」：说明「CLI 连续这段时间没有任何事件（回复、工具、思考）时停止任务」。选项为「不启用」与 5 / 10 / 30 分钟；不用「关闭」，因该词条已表示关闭按钮。

保存反馈与其他字段相同：每行下方同一 `cwn-settings-save` 槽只显示保存中与失败（「总时限未保存，请重新选择重试」等），成功不显示文字；读取失败的说明与重试按钮仍在任务调度分区末尾。
