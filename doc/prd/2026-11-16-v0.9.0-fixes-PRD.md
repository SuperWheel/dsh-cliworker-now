# v0.9.0 适配与修复合集（双通道下载、DSH rc.3、Grok、Hermes、Pi、ZCode 自有 Key 等 9 项）

- 需求编号：REQ-0135
- 来源：技术优化　类型：技术　目标版本：0.9.0（已于 2026-11-16 发布）

## 一、背景与问题

1. v0.9.0 于 2026-11-16 发布。除「更新 CLI」页（REQ-0133）和 Qoder SDK daemon 适配（REQ-0134）外，还有 9 个 pmspec 变更随版本上线，此前没有登记到面板。
2. 「更新 CLI」页上线后，自带更新器的 CLI 没有进度条；2026-11-14 Windows 经代理更新时，长下载在 18–153 MB 处断流后不再恢复，官方更新器也不续传，一直挂到插件 10 分钟的上限。
3. 宿主与 CLI 升级后旧适配失效：DeepSeek Harness 0.2.2-rc.3 于 2026-11-13 发布，插件 SDK 仍锁 rc.2；Pi 升到 1.5.2，兼容名单只到 1.1.0；Grok 1.0.77 已登录，派遣前却报「当前 CLI 未支持账号模型」；Hermes 0.23.1 的共享状态写入新增必需参数，插件报「登录暂时无法续期」。
4. 2026-11-15 用户提供 Windows 磁盘耗尽证据：catalog/query-*、OMP identity 与 Qoder CN metadata 临时目录持续遗留，OMP 每个隔离 HOME 约 128 MB。
5. Mac 候选版验收发现：OMP 在嵌套 Worker 项目里把文件写到仓库根目录；工具错误显示为 [object Object]。
6. 用户的 ZCode 订阅过期后无法改用自有 API Key：ZCode 0.17.1 的运行偏好校验让每次派遣失败，自有服务商的模型被全部隐藏，模型标签显示服务商 UUID。
7. 2026-11-15 用户报告：Windows 上在 OpenCode 账号窗口替换 DeepSeek Key，前两次显示「登录窗口已结束」，Key 实际已保存。

## 二、目标用户与使用场景

1. 经代理或国内网络更新 CLI 的用户：需要看到下载进度，断流后能自动续传。
2. 跟随宿主与 CLI 新版本的用户：升级 DSH 0.2.2-rc.3、Pi 1.5.2、Grok 1.0.77、Hermes 0.23.1 后，Worker 仍能派遣、续期和读取模型。
3. 长期运行 DSH 的 Windows 用户：插件临时目录不会持续占用 C 盘。
4. 在嵌套项目里派遣写任务的用户：文件写在所选的项目目录。
5. ZCode 订阅过期、想用自己 API Key 的用户。
6. 在账号窗口替换同一服务商 Key 的用户。

## 三、目标与成功指标

1. 升级宿主或 CLI 后，Worker 的派遣、续期和模型目录保持可用。
2. CLI 更新全部显示进度；官方渠道失败时改由插件接管下载并续传。
3. 插件临时目录用完即删，并定期清扫过期目录。
4. 替换 Key、填自有 Key 等账号操作的结果与实际状态一致。

成功指标：其他（以各变更的验收结果为准，无数值基线）。

## 四、方案概述

1. CLI 更新双通道：先走官方渠道，失败或停滞时改由插件统一下载器接管，支持续传和换源；某 CLI 在本机官方渠道失败后，7 天内直接走接管。
2. 宿主与 CLI 适配：SDK 与原生界面包升到 0.2.2-rc.3；按本机两个版本的原生接口核对后，支持 Pi 1.5.2；Grok 动态目录按账号返回的模型判断，不再只认旧构建号；Hermes 续期改用新签名，并提前拒绝不兼容接口。
3. 临时目录回收：删除失败时重试；失败路径也删除；新增过期清扫，删除异常不再掩盖任务结果。
4. Worker 工作目录与错误文本：工具调用固定在所选项目目录，工具错误与停止原因统一转成可读文字。
5. ZCode 自有 Key：修正运行偏好答复，允许自有服务商在 /models 不可用时显示模型，模型标签显示服务商名称，并提供不改桌面端配置的添加入口。
6. 替换 Key 登录确认：按凭据是否变化确认登录，不再只认新登录 ID 或退出码 0。

## 五、需求明细

### 1. CLI 更新双通道

系统应当在官方更新渠道失败或停滞时改由插件接管下载，显示进度并从已下载位置续传。

- 当官方更新器下载停滞超过阈值，那么插件接管下载，保留已收字节续传，界面显示进度。
- 当某 CLI 的官方渠道在本机失败后 7 天内再次更新，那么直接走插件接管。

### 2. 适配 DSH 0.2.2-rc.3

系统应当在 DeepSeek Harness 0.2.2-rc.3 下正常加载插件、显示输入框并读取规划模式。

- 当在 DSH 0.2.2-rc.3 Desktop 打开 CLI Worker，那么插件加载，输入框正常显示，派遣遵循规划模式。

### 3. Grok 动态模型目录

系统应当按账号实际返回的模型显示 Grok 1.0.77 的模型目录。

- 当Grok 1.0.77 已登录且账号只返回 grok-4.7，那么模型列表显示 grok-4.7，派遣不再报「当前 CLI 未支持账号模型」。

### 4. Hermes 自动续期

系统应当用 Hermes 0.23.1 的新签名完成续期，并在接口不兼容时提前拒绝。

- 当Hermes 0.23.1 的登录需要续期，那么续期成功，模型与强度正常加载。
- 当Hermes 接口与插件不兼容，那么兑换前提示不兼容，不写入状态。

### 5. 适配 Pi 1.5.2

系统应当在核对原生接口后支持 Pi 1.5.2，并在 Windows 上找到 Git Bash。

- 当本机 Pi 为 1.5.2，那么安装检查通过，可正常派遣。
- 当Windows 上 Pi 任务结束，那么不再暂停后续派遣。

### 6. 临时目录回收

系统应当在任务成功或失败后删除插件临时目录，并定期清扫过期目录。

- 当模型目录查询失败，那么本次查询的临时目录被删除。
- 当存在超过保留期的遗留目录，那么清扫时删除，不影响正在运行的任务。

### 7. Worker 工作目录与错误文本

系统应当把 Worker 的工具调用限定在所选项目目录，并把工具错误显示为可读文字。

- 当在嵌套项目中派遣写任务，那么文件写在所选项目目录，而不是仓库根目录。
- 当工具返回对象类型的错误，那么界面显示可读的错误文字，不显示 [object Object]。

### 8. ZCode 自有 API Key

系统应当允许用户在订阅过期后用自己的 API Key 通过 CLI Worker 使用 ZCode。

- 当用户在账号窗口添加自有服务商与 Key，那么模型列表显示该服务商的模型，标签显示服务商名称。
- 当自有服务商的 /models 返回 404 或 405，那么仍显示用户配置的模型，派遣成功。

### 9. 替换 Key 登录确认

系统应当在替换同一服务商的 Key 后，按凭据是否变化确认登录。

- 当用户替换同一服务商的 Key 且新 Key 已保存，那么显示登录成功，不再显示「登录窗口已结束」。

## 六、范围外事项

- 新增 CLI 或新的设置页：不在本合集内。
- 豆包等暂不接入的 CLI：见 v0.8.8 的决定。

## 七、风险与依赖

1. ZCode 自有 Key 的 Windows 实机与无界面派遣尚未验证（变更 v0.9.0-zcode-custom-key-leeyl 任务 5.3）。
2. Windows 上 OpenCode 替换 Key 的实机复测尚未完成（变更 v0.9.0-account-key-confirm-leeyl 任务 2.1）。
3. 宿主与 CLI 版本更新频繁，适配需随新版本持续核对。
