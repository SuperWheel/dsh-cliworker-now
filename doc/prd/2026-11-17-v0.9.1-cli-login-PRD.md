# v0.9.1：逐一排查并修复各 CLI 更新后的登录问题

- 来源：用户反馈　类型：缺陷　目标版本：0.9.1　期望日期：2026-11-20

## 问题

v0.9.0 起插件会自动把各 CLI 更新到最新版。CLI 更新可能改变登录的存放位置或格式，插件按旧位置读取时会把已登录判成未登录，账号绑定失败，模型列表为空。已出现的例子：Antigravity 1.5.x 改存令牌文件（GitHub issue #13）、Claude Code 2.1.311 换用带后缀的钥匙串条目（v0.9.0 已修）。需要对全部 17 个 CLI 逐一排查。

## 一、背景与问题

1. v0.9.0（2026-11-16 发布）上线「更新 CLI」页，并按 2026-11-13 的决定让全部 CLI 自动更新，不再保留手动更新。
2. 2026-11-16 GitHub issue #13（v0.9.0，Windows）：Antigravity 实际已登录，账号窗口显示「当前已登录」，设置页却显示「未登录」，模型与强度为空，提示「Antigravity 无法确认当前自身账号」。原因是 agy 1.5.x 在凭据管理器超时或写入失败时改把登录存进 ~/.gemini/jetski-standalone-oauth-token，插件只读凭据管理器。修复已在本地提交，尚未发布。
3. 同类问题此前出现过：Claude Code 2.1.311 设置 CLAUDE_CONFIG_DIR 后改用带后缀的钥匙串条目，插件登录后不认（v0.9.0 修复）；Hermes 0.23.1 续期接口签名变化导致「登录暂时无法续期」（v0.9.0 修复）。
4. 各 CLI 判断登录的方式不同（凭据文件、系统凭据库、原生状态命令、SDK 守护进程），任何一个 CLI 更新都可能让插件读错。目前没有系统核对过各 CLI 最新版的登录存放方式。

## 二、目标用户与使用场景

1. 开启自动更新的全部插件用户：CLI 更新后，已登录的账号在设置页仍显示已登录，派遣和续聊不受影响。
2. Windows 用户：凭据管理器在代理、安全软件或远程会话下更容易超时，CLI 改用文件存放的概率更高。
3. 同时使用多个 CLI 的用户：一个 CLI 读错登录不应影响其他 CLI。

## 三、目标与成功指标

1. 全部 17 个 CLI 更新到当前最新版后，插件的登录状态与 CLI 自己的判断一致。
2. 每个 CLI 都有排查结论：无问题、已修复，或阻塞及原因。
3. 发现的问题在 0.9.1 内修复，并在 Mac 与 Windows 上验证；无法验证的写明原因。

成功指标：Issue 解决时长（以 GitHub issue #13 及本版本排查中新发现问题的关闭时间计，无历史基线）。

## 四、方案概述

1. 以 issue #13 的修复为模板：先确认 CLI 自己读取登录的顺序和位置，再让插件按同样顺序读取，同一账号的绑定不因存放位置变化而改变。
2. 按 17 个 CLI 逐一排查：记录版本、插件的登录来源、新版的实际存放方式，在 Mac 与 Windows 上验证设置页、账号窗口、模型目录、派遣、续聊和退出。
3. 有问题的 CLI 在同一变更内修复并补模拟测试；排查结论写入变更 tasks.md。
4. 随版本发布 issue #13 的修复。

## 五、需求明细

### 1. 统一排查方法与记录

1. 每个 CLI 记录排查时的版本号，以及插件读取登录状态与账号绑定的来源（凭据文件、系统凭据库、原生状态命令或 SDK）。

2. 对照新版 CLI 的实际存放位置与格式：只读键名、文件名和凭据库目标名，不输出凭据值。

3. 在 Mac 与 Windows 上各验一次：设置页状态、账号窗口、模型目录、派遣与续聊、退出后状态。

4. 发现不一致时，先确认 CLI 自己的读取顺序，再改插件；每个 CLI 的结论（无问题、已修复、阻塞及原因）写进变更 tasks.md。

- 当某个 CLI 排查完成：tasks.md 记录版本号、登录来源、Mac 与 Windows 的实际结果；未能验证的写明原因
- 当新版 CLI 改了登录存放位置：插件按 CLI 自己的读取顺序读取，同一账号的绑定不因存放位置变化而改变

### 2. Antigravity 更新后登录排查

现状：Windows 读凭据管理器 gemini:antigravity，macOS 读钥匙串；agy 1.5.x 超时或写入失败时改存 ~/.gemini/jetski-standalone-oauth-token。GitHub issue #13 的修复已在本地提交，尚未发布。

需核对：凭据库无项、只有令牌文件时，Windows 实机显示已登录；agy 自己在凭据库无项时是否读文件（目前由程序文本推断）。

- 当把 Antigravity 更新到「更新 CLI」页给出的最新版本，账号保持登录：设置页显示已登录及账号标签，模型与思考强度可选，派遣一个只读任务成功
- 当更新后在 Antigravity 中退出登录：设置页显示未登录，派遣与续聊提示先登录，不使用旧凭据
- 当Windows 凭据管理器中没有 gemini:antigravity，令牌文件中有有效登录：设置页显示已登录，模型可选，与 agy 自己的判断一致

## 六、范围外事项

1. 不改变各 CLI 的登录流程，不替用户迁移、写入或删除凭据。
2. 不新增 CLI。
3. 账号终端关闭时停在「正在关闭终端…」（issue #13 截图 3）尚未复现，不在本需求内；复现后另立缺陷。
4. 付费额度、积分与订阅状态不在本次排查范围。

## 七、风险与依赖

1. 部分 CLI 需要真实账号与订阅才能验证；没有账号或订阅的写明阻塞，不勾选。
2. 按此前约定，一个账号登录成功即视为其他账号或站点可登录；退出、切换账号仍需按证据验证。
3. 自动更新会在排查期间继续升级 CLI，排查结论以记录的版本号为准。
4. 探测 Kimi 时须设 KIMI_CODE_NO_AUTO_UPDATE=1；Windows 凭据管理器通过 SSH 不可见，须在交互桌面会话中验证。

## 八、上线与验证计划

1. 每个 CLI 先在 Mac 本机核对，再用 Windows 测试机验证；结论逐条写入变更 tasks.md。
2. 发布前跑相关模拟测试、类型检查、Windows 隔离测试，并只对有改动的 CLI 做真实验收。
3. 发布后在 GitHub issue #13 回复版本号，请报告者确认。
