# v0.9.2：拆分 Host 主服务 src/host/index.ts，按领域分模块（行为不变）

- 来源：技术优化　类型：技术
- 问题：插件 Host 的全部对外接口集中在 src/host/index.ts 一个文件（3768 行），其中 CliWorkerService 一个类约 3490 行，含 74 个 @Remote 接口方法和约 1370 行内部辅助逻辑。账号、设置、CLI 更新、Worker 管理、消息与续聊等不相干的改动都要改同一个文件，并行开发时频繁冲突，审查与定位问题困难。2026-11-18 目录结构审查（Fable）把它列为长期维护的首要结构问题。

## 一、背景与问题

1. src/host/index.ts 共 3768 行，是仓库最大的源文件；第二大的 src/host/runtime.ts 为 3188 行。
2. CliWorkerService 承担 Cordis 注册、74 个 @Remote 接口（DSH 客户端通过 Typert 生成的契约调用）以及账号、设置、CLI 更新、Worker 管理、消息队列等全部领域的方法体。
3. 同一文件被不同功能反复修改：v0.8.x 到 v0.9.1 的多数变更都改过它，并行 worktree 合并时最容易在这里冲突。
4. vitest.config.ts 只对 /src/host/index.ts 做装饰器转换，Typert 生成器也从这个入口生成 lib/typert.remote-client.d.ts，因此拆分时入口路径和接口签名必须保持不变。

## 二、目标用户与使用场景

1. 插件维护者与协助开发的 Agent：改某一领域（例如账号或 CLI 更新）时只需读写对应模块。
2. 并行开发：多个 worktree 分别改不同领域时不再在同一个文件冲突。
3. 插件用户不受影响：界面、接口与行为保持不变。

## 三、目标与成功指标

在不改变任何用户可见行为和接口契约的前提下，把 CliWorkerService 的方法体按领域移到独立模块，index.ts 只保留 Cordis 注册、Remote 门面和生命周期。成功指标：src/host/index.ts 行数从 3768 降到 1000 以下，拆出的每个模块不超过 1000 行；Typert 生成的远程契约与拆分前逐字节一致。

成功指标：其他，基线 3768，目标 1000（index.ts 行数）

## 四、方案概述

1. 保持 src/host/index.ts 为 Host 入口，CliWorkerService 的 74 个 @Remote 方法名称、参数与返回类型不变，方法体改为一行或几行委托。
2. 按领域新建不带装饰器的普通模块，例如：Harness 会话与子 Agent、历史与设置及角色预设、Worker 管理（改名、目标、删除、恢复、分叉）、CLI 管理与更新、账号与连接状态、模型目录与选型及权限、消息发送与续聊队列。具体切分在 OpenSpec 设计中确定。
3. 共享状态（运行时、存储、订阅）通过显式传入的上下文对象访问，不新增全局单例。
4. 每拆一个领域单独提交，每步都跑类型检查和全量测试。
5. 用拆分前后 Typert 生成的 lib/typert.remote-client.d.ts 和预览包产物对比确认契约不变。

## 五、需求明细

### 1. 接口契约不变

系统应当保持 CliWorkerService 全部 74 个 @Remote 接口的名称、参数、返回类型与调用模式不变，Typert 生成的远程契约与拆分前逐字节一致。

- 当拆分完成后执行 pnpm build:preview，那么lib/typert.remote-client.d.ts 与拆分前的预览包逐字节一致，lib/ 文件清单除新增的内部模块外没有增删
- 当DSH 客户端按原接口名调用任一 Remote 方法，那么返回结果与拆分前一致，现有客户端代码无需修改

### 2. 按领域拆出模块

系统应当把 CliWorkerService 的方法体按领域移入独立模块，index.ts 只保留注册、Remote 门面与生命周期，行数低于 1000，拆出的每个模块不超过 1000 行。

- 当统计 src/host/index.ts 与新模块的行数，那么index.ts 少于 1000 行，任一新模块不超过 1000 行
- 当运行 pnpm lint，那么error 为 0，新模块之间以及与 index.ts 之间不新增 import 循环警告

### 3. 行为与测试不变

系统应当在拆分后通过现有全部测试，用户可见行为（设置页、派遣、续聊、停止、CLI 更新、账号窗口）不变。

- 当在 macOS 运行 pnpm typecheck 与全量 vitest，那么类型检查通过，测试通过数不少于拆分前（8841），失败为 0
- 当Windows 远程隔离运行 Windows CI 测试文件，那么全部通过，结果与拆分前一致
- 当在 DSH Desktop 打开 CLI Worker 设置页、派遣一个 Worker 并续聊、停止，那么界面与流程与拆分前一致，无报错

## 六、范围外事项

- src/host/runtime.ts（WorkerRuntime）的拆分：另立需求。
- src 目录化（按 CLI 或平台建子目录）、tests 与 scripts 目录搬迁、整仓 Prettier：属于结构整理第二批，另行安排。
- 任何功能新增、文案或界面调整。
- lib/ 输出布局、cordis.patch.yml、package.json 的 exports 与 files：保持不变，避免 DSH 加载白屏。

## 七、风险与依赖

1. 装饰器转换只作用于 index.ts：新模块不能使用装饰器，Remote 定义必须留在 index.ts。
2. 方法间隐式共享 this 上的状态：拆分时需梳理字段依赖，通过上下文对象显式传入；遗漏会造成运行期错误，由全量测试与 Desktop 实测兜底。
3. 与进行中的其他改动冲突：拆分期间暂停其他对 index.ts 的修改；仓库内仍有一个进行中的变更（vnext-plan-exit-agy-background-leeyl，代码已完成）。
4. 0.9.2 为热修复版本：本需求只做内部结构调整，不影响用户行为，可随 0.9.2 发布。

## 八、上线与验证计划

1. 先建 OpenSpec 变更，设计中确定领域切分与上下文对象。
2. 记录拆分前预览包的 Typert 契约与文件清单作为基线。
3. 按领域逐个拆分，每步类型检查与全量测试通过后本地提交。
4. 全部完成后对比契约与预览包，Windows 远程跑 Windows CI 测试，Mac Desktop 做一次设置页、派遣、续聊、停止的实测。
5. 随 0.9.2 发布，发布前按发布验收规范执行。
