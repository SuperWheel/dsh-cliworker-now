# worker-management Specification

## Purpose

让用户在 CLI Worker 卡片中明确管理智能体名称和聊天标题，安全删除与恢复自己的任务，并在历史记录缺少账号证据时有可执行的新对话入口，同时保证宿主后台任务菜单与侧栏共存而不丢失原生交互。

## Requirements

### Requirement: 简短默认名称与兼容
默认智能体名 SHALL 使用 CLI 短名和递增序号，Antigravity 为 agy。升级 SHALL 只转换可确认的旧自动名，保留用户自定义名和旧名称引用兼容；同父会话名称 MUST 保持无歧义，隐藏任务的名称不被无意复用。

#### Scenario: 新任务与旧自动名
- **WHEN** 创建无自定义名的任务或加载旧自动命名记录
- **THEN** 使用如 agy-1、codex-1 的短名称；原 Worker ID、角色和历史保持，旧名称可以精确定位原任务

#### Scenario: 自定义与冲突
- **WHEN** 用户自定义名称或短名称已有占用
- **THEN** 保留自定义名，自动选择未占用序号，不将重名匹配到其他任务

### Requirement: 强度展示大小写
插件所有面向用户的思考强度 SHALL 使用首字母大写；协议default统一显示为“默认”。显示 label MUST 映射回原始支持的协议值，不通过字符串猜测或改写模型 ID。

#### Scenario: 展示与保存
- **WHEN** 显示模型菜单、卡片、设置或选型/沿用卡片
- **THEN** low 显示为 Low，选中后保存和执行仍使用原生 low 值

#### Scenario: 默认标签
- **WHEN** 展示默认思考强度
- **THEN** 卡片、设置、菜单及选型询问均显示默认，保存和执行仍使用default，不推断模型能力

### Requirement: 原生后台菜单可见
CLI Worker 侧栏显示时，宿主后台任务菜单 SHALL 完整可见、可点击且保持原生内容和交互。兼容调整 MUST 只在需要时生效，关闭菜单或卸载插件后恢复布局与生命周期资源。

#### Scenario: 菜单与右侧栏共存
- **WHEN** 右侧 CLI Worker 打开且用户展开宿主后台任务菜单
- **THEN** 菜单不被侧栏遮挡或中央列裁剪，关闭后聊天裁剪和原生层级恢复

### Requirement: 缺失账号历史的新对话入口
缺少账号绑定的历史任务 SHALL 在标题下通过紧凑圆角提示条显示简短阻塞原因及新建入口，不允许旧会话续聊。用户明确新建时 SHALL 保留旧记录和草稿、沿用原 CLI/模型/强度/角色并重新核对当前自身账号；新对话 MUST 使用新 Worker/原生会话，不伪造旧账号身份。

#### Scenario: 查看与新建
- **WHEN** 旧任务有会话 ID 但缺少账号证据
- **THEN** 历史仍可查看，续聊被阻止，用户可通过新建对话操作发送到新的同 CLI Worker

#### Scenario: 新建失败或账号变化
- **WHEN** 新建时账号未登录、模型失效、账号改变、权限不允许或请求取消
- **THEN** 不启动或继续旧会话、不静默换模型或账号，草稿与旧记录保持

#### Scenario: 提示位置
- **WHEN** 打开缺账号证据的旧对话或进入新建状态
- **THEN** 提示及对应操作保持在标题下方，输入区不再重复显示；新建和取消行为保持

#### Scenario: 状态条高度
- **WHEN** 展开侧栏查看历史账号阻塞提示或新建状态
- **THEN** 标题下单行提示条与宿主展开侧栏的新会话按钮高度一致，文本与操作垂直居中

### Requirement: 卡片管理与可恢复删除
卡片 SHALL 提供原生右键菜单及可访问的键盘入口，区分聊天标题与智能体名称；不显示额外省略号按钮，右侧打开箭头在整个任务行上下居中。删除 SHALL 仅隐藏当前父会话的该 Worker 并提供持久恢复入口，保留账号、原生会话和历史。运行、排队、停止或进程清理未确认时 MUST 拒绝删除；跨父会话操作必须拒绝。

#### Scenario: 标题与名称
- **WHEN** 用户修改聊天标题或名称
- **THEN** 仅修改对应字段并在持久化成功后发布，名称引用保持正确，失败可继续编辑

#### Scenario: 删除与恢复
- **WHEN** 用户删除空闲任务并随后恢复，或重启后恢复
- **THEN** 正常列表隐藏任务，已删除入口可恢复同一 Worker 和历史，不删除凭据或原生数据

#### Scenario: 活动任务与归属
- **WHEN** 任务仍活动、清理未确认或请求来自其他父会话
- **THEN** 管理删除被拒绝，不产生部分删除或丢失历史

#### Scenario: 清理阻塞经历重启
- **WHEN** Host 已记录进程清理未确认，并在恢复前重启
- **THEN** 保留私有阻塞记录，继续拒绝删除、恢复、新建任务及账号修改；损坏的记录不得当作已完成清理

#### Scenario: 简洁卡片与管理访问
- **WHEN** 查看卡片或使用右键、ContextMenu或Shift+F10
- **THEN** 无可见省略号按钮，原生管理菜单可用；关闭菜单恢复可访问焦点，复制名称不会打开对话

### Requirement: 名称复制
智能体名称 SHALL 独立显示悬停及聚焦反馈，点击或键盘激活复制确切名称且不打开卡片；不显示复制图标或保留其占位，扩大按钮左右留白时名称文字起点 MUST 保持；名称末端与模型起点到细分隔线的距离 SHALL 相等，按钮边缘到线仍有小间隙。成功后按钮文字 MUST 显示已复制，鼠标离开或键盘失焦约一秒后恢复名称。复制失败 MUST 如实提示，结果状态与定时器随组件销毁清理。

#### Scenario: 独立复制
- **WHEN** 用户悬停名称并点击或键盘激活
- **THEN** 显示复制反馈、复制短名称，卡片仍停留原页面；失败时保留可选择文本

#### Scenario: 文字反馈时机
- **WHEN** 复制成功后仍悬停，随后移开鼠标或完成键盘操作后失焦
- **THEN** 悬停期间保持已复制，离开约一秒后恢复；多次进入离开、名称变化和销毁不遗留计时器或过期反馈

#### Scenario: 文字距离及窄栏
- **WHEN** 查看普通或窄栏中的短名、长名卡片
- **THEN** 名称按钮左右包住可见文字，分隔线两侧文字距离相等；长名可省略且控件不越界，复制仍使用确切完整名称

### Requirement: 紧凑管理弹窗
智能体名称和聊天标题编辑 SHALL 共用紧凑布局，输入铺满内容宽度，与保存按钮右缘对齐。错误及保存中反馈 MUST 保持可读，正常状态不为空错误块保留额外高度。

#### Scenario: 名称与标题编辑
- **WHEN** 打开任意编辑弹窗
- **THEN** 输入框与保存按钮右缘对齐，标题到输入、输入到操作的留白收紧，窄屏仍可完整操作

### Requirement: 固定总览控件和回收入口
搜索及全部、进行中、已完成、异常四个筛选 SHALL 固定在总览上方，仅下方任务列表滚动；筛选区 MUST 不显示匹配数量、没有匹配的任务或清除筛选文字。已删除入口 SHALL 为异常右侧的淡红色垃圾桶按钮，具有可访问名称，按下可切换已删除列表及返回，再次按下返回时保留原筛选和搜索状态；点击任意普通筛选必须退出已删除视图并应用该筛选。回收站激活时四筛选均为灰色未选，垃圾桶为深红底白图标。列表顶部 MUST 为首卡描边保留空间，首卡位于列表顶部时完整露出。

#### Scenario: 滚动和回收查看
- **WHEN** 用户滚动长任务列表或切换查看已删除对话
- **THEN** 搜索、四筛选及垃圾桶位置不变，滚动条起于控件下方，原筛选保留，已删除任务仍可恢复

#### Scenario: 回收站切回筛选
- **WHEN** 已删除视图开启后点击任一普通筛选
- **THEN** 回到正常任务列表并显示对应筛选结果，搜索保持，只有对应普通筛选为选中态；垃圾桶恢复淡红色

#### Scenario: 首卡边界
- **WHEN** 列表位于顶部，包括由子对话返回到该位置
- **THEN** 首卡顶缘不被固定控件及滚动边界遮住，固定控件仍不随列表滚动

#### Scenario: 简洁筛选信息
- **WHEN** 选择任一状态或使用搜索，包括无匹配结果
- **THEN** 不生成额外匹配说明和清除筛选操作，空结果列表保持空白；搜索和四筛选可正常切换，清空搜索并选全部后恢复相应卡片

### Requirement: 简洁初始空页
无任务的初始页 SHALL 使用温和的短标题及一句操作提示，不显示图标、CLI列举、大块示例或多段说明。筛选无结果和无已删除任务的状态 MUST 与初始空页区分。

#### Scenario: 首次等待任务
- **WHEN** 主会话尚无Worker且不在配置或断线状态
- **THEN** 显示简洁文字启动页，提示在主对话发起任务，任务到来后正常替换为列表

### Requirement: 简洁模型名称展示
模型展示 SHALL 去掉提供商和组织路径前缀，卡片、详情、菜单和设置只显示简洁名称。清理 MUST 只影响显示文字，保留确切CLI模型ID、强度、账号来源和不同模型身份；同名标签不得导致误选或合并权限。

#### Scenario: Hermes多层模型路径
- **WHEN** Hermes历史或目录的模型包含提供商及组织路径
- **THEN** 展示如ling-3.1-flash，实际选择、保存和执行保留原始完整ID

#### Scenario: 清理后的同名模型
- **WHEN** 不同原生模型清理后名称相同
- **THEN** 仍可区分选择，保留各自ID和能力，不把名称用于执行或授权

### Requirement: 简洁的无会话输入区
结束后没有原生会话ID的任务 SHALL 保留历史、错误与草稿，但不在输入框上方显示无法续聊的说明小字。输入及提交 MUST 继续被禁用，不恢复账号或伪造可续聊状态。

#### Scenario: 无原生会话
- **WHEN** 任务结束且没有会话ID
- **THEN** 无输入区说明小字，原有运行错误仍可见；键盘、按钮或强制表单提交均不能启动续聊或新建，历史与草稿保持

### Requirement: 项目 CLI 默认模型自动保存
Client SHALL 在用户选择有效模型或思考强度时立即更新本地完整草稿，不立即调用保存接口；离开当前 CLI 页面或关闭设置时 SHALL 后台提交最终组合，不等待保存完成再导航，且关闭不取消已提交的保存，不要求点击保存按钮。每项目和 CLI 的写入 SHALL 串行，只有模型真实声明的强度可被保存，保存仍执行原有原生账号与模型权益核验。初始化、没有明确选择的导航及刷新目录 MUST 只读取、不写入偏好。模型与思考强度下拉菜单 SHALL 与各自选择框等宽，并保持左右边缘对齐。

#### Scenario: 选择后自动保存
- **WHEN** 用户在一个 CLI 页连续选择有效模型和思考强度，然后切换到其他 CLI 或智能体设置页
- **THEN** 选择期间只更新本地草稿，离页提交最终完整组合且目标页立即打开；新模型不支持旧强度时采用该模型已声明的有效选项，不发送不兼容组合。

#### Scenario: 初始读取
- **WHEN** 用户打开设置、没有明确修改就切换 CLI 或刷新模型列表
- **THEN** 显示已保存或可选候选，不自动调用保存，不以默认展示当作用户选择。

#### Scenario: 关闭并快速重开
- **WHEN** 用户修改选型后通过叉号、窗口外侧、原生 Esc 或外部状态变更使设置关闭，保存仍在进行时重新打开并再次选择或离页
- **THEN** 关闭触发保存且不取消该请求，重开显示未完成选择；同 CLI 写入串行且后续离页保存最终组合，旧回执不覆盖新草稿，仍在页内的新草稿不因旧写入结束而提前提交。读取请求开始后完成的保存回执不被迟到旧快照覆盖，保存完成后发起的新读取仍接收当前默认值。

#### Scenario: 保存失败与页面离开
- **WHEN** 后台保存失败后用户重新打开对应 CLI 页
- **THEN** 保留选择和错误供查看，不能报告已保存，后续离页或关闭时可重试；读取本身不重试保存。

#### Scenario: 连续选择
- **WHEN** 前一次后台保存尚未结束而用户返回继续选择
- **THEN** 保留最新完整草稿，直到再次离页才提交；请求按 CLI 串行，不并发乱序，旧成功或错误不能覆盖最新选择。

#### Scenario: 来源变化
- **WHEN** 账号、模型目录、路径、CLI 开关来源失效或 Host 换代
- **THEN** 清除旧来源草稿并取消旧来源写入，迟到结果不能更新新来源；展示缓存不能替代实际保存的实时核验。

#### Scenario: 下拉菜单宽度
- **WHEN** 用户打开模型或思考强度菜单
- **THEN** 菜单宽度跟随对应选择框，不因列表内容长短变宽，左右边缘与选择框对齐。

### Requirement: 任务时限可配置
CLI Worker 设置 SHALL 提供任务总时限与空闲时限，总时限默认 30 分钟并允许更长或不限制，空闲时限默认关闭。Host SHALL 为每个任务计算一次截止时间并由所有计时点共用；空闲时限 SHALL 在收到任何原生事件时续期。设置变更 MUST 只作用于此后启动的任务。超时停止 SHALL 沿用既有停止流程，进程范围退出后才报告超时。

#### Scenario: 长任务超过 30 分钟
- **WHEN** 用户把总时限设为 2 小时，任务持续运行 45 分钟
- **THEN** 任务继续运行，不报告超时

#### Scenario: 空闲时限
- **WHEN** 启用 10 分钟空闲时限，CLI 连续 10 分钟没有任何原生事件
- **THEN** 任务按超时停止，说明为空闲超时，进程范围退出后才报告

#### Scenario: 运行中修改设置
- **WHEN** 任务运行中用户缩短总时限
- **THEN** 正在运行的任务保持启动时的截止时间，新任务使用新设置

#### Scenario: 旧配置
- **WHEN** 用户此前在插件配置文件中设置过 `timeoutMs`
- **THEN** 该值作为总时限初始值显示，不被默认值覆盖

### Requirement: 超长工具命令不阻止加载历史
Host SHALL 把工具事件的 `toolCall.command` 截到 32768 个 UTF-16 码元以内再写入事件日志，且 MUST NOT 拆开代理对；读取事件日志时，已有的超长 `toolCall.command` SHALL 同样截断后加载，MUST NOT 因此让历史读取或插件启动失败。

#### Scenario: 写入超长命令
- **WHEN** CLI 报告一个命令长度超过 32768 字符的工具调用
- **THEN** 事件日志中该事件的 `toolCall.command` 只保留前 32768 个字符，下次启动可正常读取

#### Scenario: 旧版本写入的超长记录
- **WHEN** 旧版本已在事件日志中写入超过 32768 字符的 `toolCall.command`
- **THEN** 启动时该事件截断后加载，插件正常激活，其余字段不变

### Requirement: 发起关系标注
由子 Agent 发起的 Worker SHALL 在 CLI Worker 窗口与其他 Worker 同级显示，并在标题行、标题之后以分隔线加文字标注「由 <发起者名称> 发起」（状态之前，过长时省略号截断）；发起者已删除时保留名称。列表 MUST NOT 以缩进、折叠或下级列表表示发起关系。

#### Scenario: 显示发起者
- **WHEN** 用户查看由 Codex-1 发起的 Claude Code Worker
- **THEN** 卡片与 Codex-1 同级，标题行显示「标题｜由 Codex-1 发起」

### Requirement: DSH 子 Agent 在 CLI Worker 窗口统一显示
开关开启时，CLI Worker 窗口 SHALL 列出当前主对话中 DSH 原生调用的直接子 Agent，作为「DSH」分组与各 CLI 分组同级，分组标题 SHALL 像 CLI 分组一样带图标（DSH 官方单色标志）；CLI Worker 自身对应的子会话 MUST NOT 重复列出。条目 SHALL 采用与 CLI Worker 卡片相同的版式：标题与状态一行，下方为插件名称、模型（有公开信息时），右侧箭头，「打开对话 / 删除」放在右键菜单；状态由 DSH 原生事件得出，并参与搜索与「全部 / 进行中 / 已完成 / 异常」筛选。状态 MUST 来自 DSH 原生公开数据，不伪造进度。

#### Scenario: 主 Agent 调用 DSH 子 Agent
- **WHEN** 主 Agent 在当前主对话启动一个 DSH 原生子 Agent
- **THEN** CLI Worker 窗口出现「DSH」分组和对应条目，运行结束后状态随原生事件更新

#### Scenario: CLI Worker 不重复
- **WHEN** 当前主对话同时有 CLI Worker 与 DSH 原生子 Agent
- **THEN** 每个 CLI Worker 只出现在其 CLI 分组，「DSH」分组只含 DSH 原生子 Agent

### Requirement: DSH 子 Agent 打开方式与操作
用户点开 DSH 子 Agent 条目时，插件 SHALL 打开与 CLI Worker 子会话相同样式的窗口，显示其原生记录与统计。可续聊模式（continuable）的子 Agent SHALL 提供续聊与停止，分别调用 DSH 原生 `prompt` 与 `interruptByParent`；一次性或未知模式的子 Agent 只读，输入区与停止不可用。停止 MUST 在原生确认结束后才报告成功。

#### Scenario: 打开已完成的一次性子 Agent
- **WHEN** 用户点开一个已完成的一次性 DSH 子 Agent
- **THEN** 显示其记录与统计，输入区不可用

#### Scenario: 停止运行中的可续聊子 Agent
- **WHEN** 用户在窗口中停止一个运行中的可续聊 DSH 子 Agent
- **THEN** 插件调用原生中断，子会话结束后状态改为已停止；中断失败时显示错误，不报告成功

### Requirement: DSH 子 Agent 名称与按名续聊
插件 SHALL 为每个 DSH 原生子 Agent 分配主对话内唯一的名称 `dsh-<n>`：按插件首次看到的顺序（同批按创建时间）递增，持久保存在插件私有文件（目录 0700、文件 0600）中，隐藏后不复用、不重新编号，不同主对话分别编号。CLI Worker 的名称 MUST NOT 使用 `dsh-<n>` 格式。主 Agent SHALL 能通过 `cliworker_followup` 的 `worker_name` 按该名称（不区分大小写）续聊可续聊模式的 DSH 子 Agent，请求经 DSH 原生 `prompt` 排队送达，回复以 DSH 子 Agent 消息回到主对话；`cliworker_status` SHALL 列出这些名称并可按名称只读查询。名称先匹配 CLI Worker；只有未匹配时才查找 DSH 子 Agent。显示开关关闭、条目已隐藏、名称不存在或子 Agent 为只读时 MUST NOT 发送，并返回明确错误。

#### Scenario: 按名称续聊
- **WHEN** 用户让主 Agent「继续 dsh-1，补充 X」
- **THEN** 主 Agent 调用 `cliworker_followup`，worker_name 为 dsh-1，DSH 子 Agent 收到消息并在其子会话中回复

#### Scenario: 名称稳定
- **WHEN** 用户隐藏 dsh-2 后主 Agent 又启动一个 DSH 子 Agent
- **THEN** 新子 Agent 名为 dsh-4（已有 dsh-1 至 dsh-3），dsh-1 与 dsh-3 的名称不变

#### Scenario: 保留名称
- **WHEN** 用户把某个 CLI Worker 改名为 dsh-2
- **THEN** 插件拒绝并提示该格式保留给 DSH 子 Agent

### Requirement: DSH 子 Agent 显示开关
「CLI Worker 设置 → CLI Worker 设置」SHALL 提供「在 CLI Worker 窗口显示 DSH 子 Agent」开关，默认开启。关闭后 CLI Worker 窗口 MUST 不再列出 DSH 子 Agent，但 DSH 子 Agent 的运行与 DSH 原生入口不受影响；重新开启后立即恢复。「CLI 连接」列表 MUST NOT 为 DSH 新增连接或设置页。

#### Scenario: 默认值
- **WHEN** 用户升级后首次打开设置
- **THEN** 开关为开启

#### Scenario: 关闭开关
- **WHEN** 用户关闭开关
- **THEN** 「DSH」分组立即从 CLI Worker 窗口消失，DSH 子 Agent 照常运行

### Requirement: DSH 子 Agent 数据边界
插件 SHALL 只读取 DSH 原生子 Agent 的公开目录、状态与记录，MUST NOT 复制或改写其会话数据。在 CLI Worker 窗口删除 DSH 子 Agent 条目 SHALL 只在插件内隐藏该条目，并提示不影响 DSH 原生会话。

#### Scenario: 删除 DSH 条目
- **WHEN** 用户在 CLI Worker 窗口删除一个 DSH 子 Agent 条目
- **THEN** 条目从列表隐藏，DSH 原生会话与记录保持不变
