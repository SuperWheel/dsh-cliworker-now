# cli-connection-health Specification

## Purpose

让用户在插件设置和账号信息中清楚区分尚未配置、已读取配置以及明确的配置或认证错误；状态必须来自实际可观察证据，不能将本地凭据存在或模型目录查询成功等同于远端服务可用。

## Requirements

### Requirement: 灰色未配置状态
CLI 未安装、没有账号配置或从未登录时 SHALL 显示灰色指示点和未配置原因；关闭、尚未检查或无法确认时 SHALL 显示灰点并保留其不同含义。未配置 CLI 的空模型目录 MUST 不使指示点变红。

#### Scenario: 从未配置
- **WHEN** 账号文件不存在或原生 CLI 明确报告未登录且没有失效证据
- **THEN** 导航和账号摘要都显示灰点及未配置说明

#### Scenario: 未配置且目录为空
- **WHEN** 未配置 CLI 的模型目录探测无法返回模型
- **THEN** 保持灰点，不标记为配置失败

### Requirement: 红色错误状态
已知凭据过期且不能续用、CLI 明确拒绝认证、已配置数据损坏、安全读取失败或配置探测失败 SHALL 显示红点和可解释原因。用户显式配置了无效执行路径 SHALL 显示配置错误；默认 CLI 缺安装 SHALL 显示未配置。

#### Scenario: 登录失效
- **WHEN** 已有凭据已过期且没有有效续用信息，或原生状态明确表示失效
- **THEN** 显示红点和失效说明

#### Scenario: 配置损坏
- **WHEN** 已有配置文件损坏或读取触发安全检查拒绝
- **THEN** 显示红点，错误文本不包含密钥

#### Scenario: 显式执行路径错误
- **WHEN** 用户配置的 CLI 执行路径不存在或不能执行
- **THEN** 显示红点并说明执行路径配置失败

### Requirement: 状态一致和证据范围
设置导航和账号摘要 SHALL 只依据本 CLI 的账号证据；模型目录的等待或失败 MUST 不覆盖已确认的登录状态。CLI 状态报告、可续用的原生登录会话或原生当前账号的精确凭据绑定 SHALL 正确显示已登录和绿点，不能因读取来源为本地就降级。自身有效 API 配置 SHALL 明确显示 API 登录和服务商，不冒充原生 OAuth 账号登录；只有配置声明、孤立凭据或共享 Host 引用 MUST 不冒充认证；刷新恢复后 SHALL 更新显示，不修改账号或既有项目偏好。登录状态不替代单独的模型权限筛选。

#### Scenario: 刷新恢复
- **WHEN** 用户修复原生账号配置后刷新
- **THEN** 导航和账号摘要一致更新，并保留原有会话与模型偏好

#### Scenario: 本地账号可读
- **WHEN** 本地账号或 API 配置读取成功但没有远端调用证据
- **THEN** 按原生结构区分账号登录、绑定服务商的自身 API 登录和仅配置声明，不要求通过模型生成证明登录，也不将该状态当成远端生成验收

#### Scenario: 本地凭据不冒充登录
- **WHEN** CLI 只有配置声明、孤立 key 或共享 Host 引用，没有原生会话或当前服务商精确凭据绑定
- **THEN** 保持已配置或未登录状态，不显示原生登录成功；Host 引用不能覆盖原生账号状态

#### Scenario: Antigravity 原生会话
- **WHEN** 已知原生 consumer 会话有未过期 access 或可续用 refresh
- **THEN** 显示已登录，读取来源为 local 不使其降级；没有可用或续用凭据则保持登录失效

#### Scenario: ZCode 当前原生账号
- **WHEN** 受支持的当前原生 provider、原生用户记录和当前 identity 一致，且 identity 与对应 coding-plan key 精确绑定
- **THEN** 显示已登录；旧 identity、孤立 key 或未知 provider 不能替代该证据

#### Scenario: 已登录但模型查询失败
- **WHEN** Antigravity、MiMo 或其他 CLI 的自身账号已确认登录，模型查询仍在进行或失败
- **THEN** 导航与账号行保持登录状态，模型区域单独显示进度或错误并禁用未确认模型

#### Scenario: MiMo 自身网页登录
- **WHEN** MiMo 原生网页登录把认证写入自己的 auth.json，或项目模型配置发生错误
- **THEN** 按原生认证结构识别当前账号，模型配置错误不阻止独立的账号检查及原生登录入口

### Requirement: 账号与模型刷新生命周期
设置 SHALL 对所有 CLI 使用一致的加载中、未配置、待验证和失败语义；新账号检查或账号操作后 MUST 使旧模型结果失效并重新核对，过期或跨 CLI 的异步响应不得覆盖当前面板。重复的在途账号查询 SHALL 合并，已完成账号结果不得作为执行授权缓存。打开设置和只读查询 MUST 不自动提交登录或模型任务。

#### Scenario: 刷新中和失败
- **WHEN** 用户刷新账号或模型，随后查询失败
- **THEN** 立即禁用旧模型；账号刷新期间保留已有登录信息并单独提示正在刷新，新的账号读取失败才清除旧登录；模型查询失败只更新模型区域

#### Scenario: 重复查询与独立取消
- **WHEN** 同一 CLI 和项目收到重叠的状态查询，其中部分调用取消
- **THEN** 共用一次在途读取且其余调用继续；最后调用取消时等待进程范围清理，后续刷新重新读取当前账号

#### Scenario: 切换或关闭
- **WHEN** 查询尚未完成时切换 CLI 或关闭设置
- **THEN** 取消对应查询，迟到结果不能写入其他 CLI，既有偏好保持不变

### Requirement: 简洁账号信息
所有 CLI 设置 SHALL 用一行必要状态、账号身份或短原因表达账号情况；正常状态 MUST 不附加重复的远端验证、凭据有效性或隐私免责声明。账号终端 SHALL 保留必要操作指导和短错误，不重复冗长声明；不能仅截断原有长段落来完成精简。configured 状态 SHALL 在导航状态说明与账号摘要保留 Host 提供的具体摘要，缺失摘要才回退「已配置」；绑定未确认、需检查登录、待续期或缺少有效凭据 MUST 不被泛化文字掩盖。短原因在空间不足时 SHALL 自然换行并沿用统一文字层级及中性状态。

#### Scenario: 正常设置
- **WHEN** CLI 已登录、已配置或未登录
- **THEN** 账号区只显示对应短状态及必要身份，不拼接第二段防御性说明

#### Scenario: 错误和终端
- **WHEN** 安装、认证、读取或关闭终端失败
- **THEN** 保留简短原因及必要重试动作，不删除实际错误或堆叠免责声明

#### Scenario: ZCode 退出后残留绑定
- **WHEN** OAuth 记录已清除但原生身份和对应绑定密钥仍在，Host 返回 configured 和绑定未确认提示
- **THEN** 设置导航状态说明与账号摘要显示需重新登录原因，不显示泛化「已配置」或已登录，不通过只读刷新删除绑定

#### Scenario: ZCode 退出后只剩 API 配置
- **WHEN** OAuth 已退出且仅剩明确的 API Key 配置或匹配指纹的原生 API 绑定
- **THEN** 设置显示「已配置 ZCode API」类摘要和中性灰点，不冒充 OAuth 登录，不删除 API 配置

#### Scenario: ZCode 退出后无绑定和 API
- **WHEN** OAuth、绑定与 API 配置均不存在
- **THEN** 设置显示未登录和灰点，账号窗口不保留旧账号行

#### Scenario: 其他 CLI 配置尚不可确认
- **WHEN** MiMo、Pi、OMP、OpenCode、Hermes 或其他 CLI 返回 configured 及检查登录、缺少凭据或等待续期的摘要
- **THEN** 导航与账号摘要一致保留该原因，不因模型目录成功而改写为泛化配置成功

#### Scenario: 旧 Host 缺少摘要
- **WHEN** configured 的摘要为空
- **THEN** 使用「已配置」作为回退，不显示空白状态

### Requirement: 可操作的原生登录入口
CLI 登录和管理动作 SHALL 打开当前安装版本支持的原生账号流程，并提供该流程所需的最小运行目录权限。登录入口 MUST 不因模型任务的账号前置条件而形成无法建立自身账号的死锁；已有账号不得被插件自动退出或删除。

#### Scenario: Kimi 已有登录
- **WHEN** Kimi 自身当前 OAuth 引用指向有效或可续用且未撤销的令牌
- **THEN** 显示已登录；登录管理入口允许用户明确操作退出和重登，不将原生命令直接复用账号误报为未登录或登录失败

#### Scenario: Kimi 只有配置引用
- **WHEN** Kimi provider 有 OAuth 引用但对应令牌不存在或已撤销
- **THEN** 显示未登录或明确失效，不以 provider 配置存在证明已登录

#### Scenario: OMP 原生日志
- **WHEN** 用户打开 OMP 登录菜单，原生程序写入自身运行日志
- **THEN** 登录菜单正常出现，写入限定该 CLI 的账号和日志目录；其他账号和同级目录仍受保护

#### Scenario: Hermes 外部账号配置
- **WHEN** Hermes 全局配置启用了其他工具登录导入或含外部来源账号，而用户打开自身登录设置
- **THEN** 通过独立自身账号上下文打开原生菜单，不读取或导入外部账号，也不修改全局账号与配置

#### Scenario: Grok 原生登录
- **WHEN** Grok 自身官方 OIDC 账号有有效 access 或可续用 refresh 与完整原生身份记录
- **THEN** 按原生账号证据显示登录状态；模型列表为空不能被解释为账号没有模型权限的证据

#### Scenario: 取消原生菜单
- **WHEN** 用户关闭登录菜单或插件卸载
- **THEN** 等待整个进程范围退出后清理临时运行目录，持久账号保留；清理失败保持错误并禁止冲突操作

#### Scenario: Kimi 账号操作不读取用户项目
- **WHEN** 打开任一 Kimi 原生账号操作
- **THEN** 使用独立空账号运行目录，阻断向父项目查找 MCP；原生 Trust 由用户决定，插件不自动写入信任记录或选择 Trust

### Requirement: 多提供商认证摘要
OMP、Pi、Hermes 和 OpenCode SHALL 根据各自真实有效认证显示绿色状态，以及服务商的账号登录或 API 登录。存在多个自身认证时 MUST 在详情中分别保留服务商与登录方式；可见摘要有账号登录时仅显示去重后的账号登录服务商，不拼接 API 提供商和邮箱；仅 API 登录时显示对应 API 服务商。API 摘要不得显示密钥或密钥片段，账号行保持单行，兼容旧 Host 的简短摘要。

#### Scenario: 自身 API 登录
- **WHEN** 本 CLI 的当前有效来源含明确服务商及可用格式的 API Key，且没有已知撤销或禁用证据
- **THEN** 显示对应服务商 API 登录和绿点，例如 zai.cn API 登录；不使用模型目录或其他 CLI 的凭据推断认证

#### Scenario: 多种登录方式
- **WHEN** 本 CLI 同时存在服务商账号登录与其他服务商 API 登录
- **THEN** 可见行只显示账号登录服务商，例如 OpenAI账号登录；完整安全认证方式保留在详情，不把 API 项当成订阅身份，也不改变实际账号来源

#### Scenario: 缺失或失效
- **WHEN** 只有模型/provider 声明、模板、未解析引用，或凭据过期/撤销/禁用
- **THEN** 未配置或失效保持原有灰/红状态，不因为显示文案改动而升为已登录

#### Scenario: 登录与模型范围不同
- **WHEN** 自身登录确认但模型目录未知、查询失败或原生执行方式尚不支持
- **THEN** 保留真实登录信息，模型单独给出短原因并禁用未经确认选项

### Requirement: 一致的原生退出入口
OMP、Pi 和 Hermes 已登录时 SHALL 提供与其他 CLI 一致的退出入口，并接入各自当前原生支持的退出流程。仅打开设置 MUST 不退出账号；用户明确选择退出后才进入对应原生操作，不能用禁用占位按钮伪装成可用功能。退出和取消 SHALL 保持现有自身来源、账号互斥、模型失效与进程清理语义。多账号 CLI 的退出入口为「账号」窗口中的逐行退出。

#### Scenario: 自身账号退出
- **WHEN** 用户在 OMP、Pi 或 Hermes 的账号窗口退出某一行
- **THEN** 进入该 CLI 原生退出流程；不使用另一 CLI 的命令、不自动退出其他来源或删除账号目录

#### Scenario: 多个自身来源
- **WHEN** CLI 同时有原生目录与插件目录中的账号
- **THEN** 账号窗口按来源分组列出账号行，每行退出只操作其所在来源；不删除合并副本后再从原来源恢复，其他来源仍有效时如实保留登录状态

#### Scenario: 账号使用中或关闭终端
- **WHEN** 账号正被任务占用，或用户取消退出界面
- **THEN** 冲突操作被拒绝；关闭需等待进程范围清理，未提交退出时原有账号保留

#### Scenario: 原生抑制保留的配置
- **WHEN** Hermes 的原生退出将当前配置来源标为 suppressed 而保留其原值
- **THEN** Host 按当前同源标记停止将其用于认证、目录和执行，不从保留值恢复已退出账号；其他未抑制来源仍按原生规则核对

### Requirement: Kimi 当前账号身份
Kimi 登录状态 SHALL 在原生自身来源提供可确认身份时显示简短账号标识；来源须绑定当前账号，不能使用旧缓存、其他 CLI 身份或凭据片段。缺失身份 MUST 不编造邮箱或用户名，不影响已确认的登录状态；身份读取不得启动生成或自动续期。

#### Scenario: 身份可读
- **WHEN** 当前 Kimi 原生认证包含可安全显示的账号身份
- **THEN** 设置显示该账号标识，并在换号或退出后重新核对

#### Scenario: 身份缺失或不安全
- **WHEN** 原生身份缺失、损坏或含敏感凭据形态
- **THEN** 不显示伪造身份或原始凭据，保持简短登录状态；旧账号标识不能继续显示

### Requirement: 桌面存在与 CLI 未找到的诊断
ZCode/OpenCode 的默认入口发现失败 SHALL 区分未找到 CLI、桌面已存在但无可用 CLI、多个可用安装及安装信息探测失败。MUST 保留简短操作指引及对应 executable 配置字段，不将桌面或账号痕迹描述为已安装可执行 CLI 或已登录。

#### Scenario: 桌面存在但 CLI 缺失
- **WHEN** 相应桌面安装存在，但该版本未附独立 CLI 或其必要文件损坏
- **THEN** 显示桌面存在、CLI 不可用及配置独立 CLI 的短原因，不返回笼统的尚未安装，也不启动桌面 GUI

#### Scenario: 入口恢复
- **WHEN** 用户补齐相应 CLI 或明确配置路径后刷新
- **THEN** 重新解析当前入口再执行既有账号检查，不修改旧账号、会话或项目选型

#### Scenario: 未找到 CLI
- **WHEN** 默认位置、PATH 及登记/快捷方式均不能定位有效 CLI
- **THEN** 显示未找到 CLI 和对应 executable 配置指引，不声称整个桌面软件未安装

### Requirement: 账号终端关闭可确认可重试
所有账号终端关闭入口 SHALL 等待受管进程范围退出；清理失败 MUST 保留可重试入口和短诊断，不丢失终端身份、不放行冲突登录。Windows 下界面消失不得成为清理成功证据。

#### Scenario: 外层关闭
- **WHEN** 用户通过弹窗关闭、终端关闭或取消关闭账号操作
- **THEN** 正在关闭时禁止重复动作，确认退出后再卸载；失败保留终端和重试入口

#### Scenario: Windows 后代存活
- **WHEN** 账号终端的受管后代没有退出
- **THEN** 按可核验归属清理并复查；不能确认则明确失败，不按进程名终止其他用户程序

### Requirement: 原生登录能力与诊断一致
登录和管理动作 SHALL 对应当前安装版本实际支持的原生命令与服务商；不支持的能力和原生退出 MUST 提供不含凭据的可行动原因，不用泛化错误掩盖已知限制。

#### Scenario: ZCode 选择原生授权来源
- **WHEN** 用户明确选择中国 BigModel 或海外 Z.AI 并发起 ZCode 登录
- **THEN** Host 验证来源枚举和当前原生能力后只启动该来源的原生授权；两平台使用同一设置组件，不静默回退到另一来源

#### Scenario: ZCode 原生能力不足
- **WHEN** 当前安装未声明用户选择的原生授权能力
- **THEN** 提供明确兼容原因和可执行修复指引，不发送不存在的参数、不构造 OAuth URL、不改写既有账号，也不声称已登录

#### Scenario: 原生立即退出
- **WHEN** 已启动账号终端立即以错误状态结束
- **THEN** 显示安全退出状态及原生修复指引；不得输出凭据或伪装完成登录

### Requirement: 账号终端轻量外观与原生粘贴
所有 CLI 账号终端 SHALL 共用不含粗黑焦点外框的主题化容器，保留可见块状光标与键盘焦点；用户主动粘贴 SHALL 可靠送达当前活动的账号终端，保留 Unicode、换行及原生括号粘贴语义。剪贴板内容 MUST 不进入日志、持久化或未选中终端。

#### Scenario: Windows 系统剪贴板
- **WHEN** 用户在已就绪账号终端通过 Windows 粘贴快捷键或右键粘贴提交复制文本
- **THEN** 文本恰好发送一次，经现有输入上限和 Gateway 到当前终端；不将 Ctrl+V 当作普通控制字符吞掉，也不额外提交回车

#### Scenario: 关闭期间和不可用剪贴板
- **WHEN** 读取剪贴板时账号终端已关闭或切换，或宿主不允许读取
- **THEN** 不向过期或其他终端发送，给不含内容的短提示；不后台读取、不把内容输出到诊断

#### Scenario: 聚焦与粘贴验收
- **WHEN** 账号终端获得焦点并以受控非秘密剪贴板文本测试
- **THEN** 实际 Desktop 外框无粗黑描边，光标仍可见，系统粘贴结果可核对；键盘模拟输入不替代剪贴板验收

### Requirement: 两平台共用账号终端
macOS 和 Windows SHALL 共用账号终端的 React/xterm 渲染、主题、输入、剪贴板与 Gateway 生命周期；仅必要的原生入口和进程差异允许平台适配。

- **WHEN** Mac 用户使用 Cmd+V 或 Windows 用户使用 Ctrl+V，以及两平台无选区时右键粘贴

### Requirement: ZCode 原生授权链接完整传递
当 Windows 原生 ZCode 浏览器启动器截断 OAuth 查询参数时，插件 SHALL 仅使用该 CLI 声明的 no-browser 能力并保留原生授权协议；受限的当前原生登录网址 SHALL 自动打开一次，用户亦可点击终端内该网址重开；两种入口 MUST 通过宿主原生跨平台外部链接机制传递完整 URL，不拼接 shell、不构造 OAuth 参数。

#### Scenario: 完整授权链接
- **WHEN** 当前 ZCode login 终端输出固定登录提示后的完整白名单 HTTPS URL
- **THEN** 浏览器自动一次收到原始完整参数，同网址不重复自动打开；点击终端原生网址可重新打开；原生 CLI 继续负责授权轮询和凭据保存；不得仅凭打开网页声称登录成功

#### Scenario: 不可信或过期终端链接

### Requirement: 简洁终端与选择复制

#### Scenario: 选择复制与中断
- **WHEN** 用户选择终端文字并使用复制快捷键或右键
- **THEN** 只复制选区内容，不发送 CLI 中断；无选区 Ctrl+C 仍发送原生中断，无选区右键粘贴

#### Scenario: 原生网址手动恢复
- **WHEN** 浏览器未正常打开，当前 ZCode 登录终端仍有有效完整原生授权网址
- **THEN** 用户可点击终端中的该网址或选择复制到浏览器；终端结束或链接变更后旧点击回调失效

### Requirement: Hermes 原生依赖与账号目录分离
Windows 和 macOS 的 Hermes 隔离账号终端 SHALL 复用官方当前安装记录中已提交的依赖环境，保持自身账号目录。插件 MUST 不因账号目录隔离而重装依赖、猜测其他环境，或导入全局账号配置。

#### Scenario: Windows 官方安装已完成
- **WHEN** Windows 官方入口记录了可核验 checkout，且当前 facts 指向有效的已提交依赖环境

#### Scenario: 安装选择发生变化
- **WHEN** 依赖记录无效、环境不匹配或启动前被原生更新改变
- **THEN** 明确拒绝或提示重试，不按目录新旧猜测环境，不回退到全局账号，也不自动安装

### Requirement: Windows 查询与嵌入式登录不弹额外控制台
插件 SHALL 在 Windows 隐藏自身启动的查询和账号 CLI 的额外控制台窗口，同时保留共享嵌入式终端、原生浏览器授权及受管范围退出确认。

#### Scenario: OpenCode 登录与模型刷新
- **WHEN** 用户打开 OpenCode 登录或刷新模型
- **THEN** 插件后台查询不弹额外 Windows 控制台，登录输出及输入留在共享终端，原生浏览器授权仍可打开

#### Scenario: 设置页后台检测及短暂窗口
- **WHEN** 用户首次打开或重新打开设置，后台逐个检测已启用 CLI，或切换和刷新模型
- **THEN** 插件自有查询和嵌套启动均不显示额外 Windows 控制台；可见窗口事件及进程归属用于实际核验，正常授权浏览器保持可用

#### Scenario: 首次检测暂时失败
- **WHEN** CLI 查询超时、被取消或读取失败，尚无已确认的缺失安装证据
- **THEN** 界面显示检测失败/可重试，而非声称 CLI 未安装；后续刷新可重试原生检测

### Requirement: Antigravity 账号终端引导与自动退出
Antigravity 的登录与退出 SHALL 使用插件绘制的分步窗口，原生账号终端在后台运行、默认隐藏并可由用户显示；Host 根据原生终端输出识别步骤，窗口文案由插件固定提供；引导 MUST 不转发或渲染 CLI 输出，MUST 不记录或回显用户输入的授权码。退出动作 SHALL 在识别到已登录主界面后由 Host 一次性写入 `/logout` 与回车，并以原生账号状态确认结果；除这一条命令和首次运行配色页的一次回车（采用默认配色）外，Host MUST 不向任何 CLI 账号终端写入内容；窗口只在用户点击对应操作时写入回车、方向键或所粘贴的授权码；服务条款 MUST 只在用户点击「同意并继续」后确认，数据收集选项默认不勾。登录和退出成功与否 MUST 以原生账号状态确认，不以终端文字推断。

#### Scenario: 点击退出登录

- **THEN** 窗口显示正在退出，Host 写入一次 `/logout` 与回车；原生账号状态变为未登录后显示「已退出 Antigravity」，并在进程范围清理确认后关闭终端、解除占用

- **THEN** 不判为未登录，进入主界面后照常自动退出；`/logout` 未生效且画面未出现登录菜单时最多再按一次回车，出现登录菜单后不再写入

#### Scenario: 退出时遇到文件夹信任询问
- **WHEN** 退出终端启动后 agy 询问是否信任当前项目文件夹
- **THEN** 窗口显示该询问及「信任并继续」「取消」；用户确认前不写入任何内容，确认后识别到主界面再自动退出

#### Scenario: 首次运行的配色页
- **WHEN** agy 首次运行，显示配色列表、`[Next]` 与按键提示
- **THEN** Host 按一次回车采用预选的默认配色，窗口显示正在完成首次运行设置；之后配色页再次出现时不再写入，画面静止仍停在配色页才提示用户在原生终端完成

#### Scenario: 首次运行的服务条款
- **WHEN** agy 显示「Terms of Service & Data Use」页，且能读出数据收集勾选框的状态
- **THEN** 窗口显示安全风险说明、服务条款与隐私政策链接、默认不勾的数据收集选项，以及「同意并继续」「取消」；用户点击前不写入任何内容，也不读取账号状态或输入 `/logout`

#### Scenario: 用户同意服务条款
- **WHEN** 用户点击「同意并继续」
- **THEN** 勾选框状态与用户选择不同时先写入一次回车切换，再写入 ↓ →；只有画面显示 `[Done]` 已选中才写入回车，随后照常识别主界面并退出或继续登录

#### Scenario: 无法跟随的首次运行画面
- **WHEN** 读不出勾选框状态、选中 `[Done]` 之前画面已静止，或首次设置期间画面静止在未知向导步骤
- **THEN** 不再写入，转为提示用户在原生终端完成剩余设置，并自动展开原生终端、获得键盘焦点；用户回车后再继续识别

#### Scenario: 未登录时退出
- **WHEN** 退出终端启动后显示登录方式菜单或画面静止，且原生账号状态为未登录；或显示文件夹信任询问
- **THEN** 不写入任何内容；未登录时提示无需退出并关闭终端，信任询问时提示由用户选择

#### Scenario: 已登录时出现登录菜单

- **THEN** 不判为未登录、不写入任何内容，也不关闭终端；窗口提示未能确认当前未登录，由用户在原生终端查看

#### Scenario: 退出未确认
- **WHEN** 写入命令后限定时间内原生账号仍为已登录
- **THEN** 不再写入，提示用户查看终端，终端保持打开由用户处理

#### Scenario: 登录分步窗口
- **WHEN** 用户点击「登录账号」，后台原生终端依次显示登录方式菜单和授权码输入
- **THEN** 窗口依次显示「选择登录方式」「在浏览器中授权」「粘贴授权码，按回车登录」三步；用户点「使用 Google 账号登录」后才向原生菜单写入回车；菜单重绘不使步骤后退

#### Scenario: 授权码提示不被挤出屏幕
- **WHEN** 原生终端隐藏运行
- **THEN** Host 以足够大的终端尺寸运行 agy，授权码输入提示出现在原生输出中，窗口能进入粘贴步骤；隐藏期间不按弹窗尺寸缩小终端

#### Scenario: 重新打开登录页面
- **WHEN** 原生输出包含登录地址超链接
- **THEN** 仅当地址为 `https://accounts.google.com` 时提供「重新打开登录页面」与「复制登录链接」；其他地址不提供、不打开

#### Scenario: 粘贴授权码
- **WHEN** 用户在窗口的授权码输入框中粘贴内容
- **THEN** 醒目显示「授权码已粘贴」与「按回车键完成登录」；按回车或点「完成登录」后以括号粘贴写入原生终端再写回车；引导帧与事件中不含授权码

#### Scenario: 确认登录
- **WHEN** 授权码已提交
- **THEN** 显示正在确认，原生账号状态变为已登录后显示「已登录 Antigravity」并结束原生终端、解除占用；限定时间内未确认则说明可能原因并提供「重新开始登录」与「显示原生终端」

#### Scenario: 原生终端后备
- **WHEN** 用户点击「显示原生终端」
- **THEN** 显示正在运行的原生终端并按可见尺寸适配，可直接操作（如 Google Cloud 项目登录）

#### Scenario: 关闭终端中止确认
- **WHEN** 确认过程中用户关闭终端或插件卸载
- **THEN** 立即停止状态轮询与任何后续写入

#### Scenario: 退出后续聊
- **WHEN** Antigravity 已退出（macOS 钥匙串无登录条目或 Windows 身份为未配置），用户续聊已有任务
- **THEN** 拒绝启动并说明「尚未登录 Antigravity」及在「CLI Worker 设置 → Antigravity」点击「登录账号」，不启动进程、不改动会话与绑定

#### Scenario: 其他 CLI 与管理动作
- **WHEN** 打开其他 CLI 的账号终端，或 Antigravity 的管理动作
- **THEN** 不显示该引导、不写入任何内容

### Requirement: 可复用登录模板窗口
各 CLI 的登录与退出 SHALL 使用插件绘制的分步窗口，由可复用模板组合而成（信任文件夹、选项、浏览器授权、浏览器授权加授权码、设备码、API Key/PAT、确认中、结果）；原生终端在后台运行、默认隐藏并可由用户显示。Host SHALL 按每个 CLI 的流程定义识别原生画面，窗口文案与选项标签由插件固定提供，MUST 不转发或渲染 CLI 输出；用户提交的授权码与密钥 MUST 只写入原生终端，不进入事件、日志或引导帧。登录与退出结果 MUST 以原生账号状态确认。「账号终端」保持原生终端。

#### Scenario: 浏览器授权自动完成
- **WHEN** 原生流程显示登录地址并等待浏览器完成授权
- **THEN** 窗口显示「在浏览器中授权」及（白名单地址才有的）重新打开/复制链接，原生账号状态变为已登录后显示成功并结束终端

#### Scenario: 设备码
- **WHEN** 原生流程显示验证地址与设备码
- **THEN** 窗口大字显示设备码并可复制、打开白名单地址，等待原生状态确认

#### Scenario: 密钥输入
- **WHEN** 原生流程请求 API Key 或 PAT
- **THEN** 窗口显示密码型输入框；提交后经 Host 写入原生终端并清空输入框，密钥不出现在引导帧和事件中

#### Scenario: 选项由用户决定
- **WHEN** 原生流程显示登录方式或平台菜单
- **THEN** 窗口显示插件固定标签的选项，用户点击后 Host 才写入对应按键；Host 拒绝不属于当前步骤的回应

#### Scenario: 授权后原生进程不退出
- **WHEN** 原生流程在浏览器或设备授权后继续运行而不自行退出（如 Pi、OMP）
- **THEN** Host 在等待授权期间于后台持续核对原生账号状态（最长 15 分钟），确认后显示成功并结束终端；超时按确认超时处理

#### Scenario: 无法识别的画面
- **WHEN** 画面静止 8 秒仍未匹配任何步骤且不在等待授权
- **THEN** 窗口提示在原生终端继续，此后不再自动写入；登录时展开终端，退出时终端保持隐藏，由用户点「显示原生终端」接手

#### Scenario: 结果页
- **WHEN** 登录或退出已显示结果，之后终端关闭或连接中断
- **THEN** 窗口只显示结果与「显示原生终端」，不显示终端状态、连接中断或启动失败提示，也不自动展开终端

#### Scenario: 确认超时
- **WHEN** 提交后限定时间内原生账号状态未变化
- **THEN** 显示未确认原因，提供重新开始与显示原生终端，不以终端文字判定成功

### Requirement: 登录来源选择
有多个可登录服务商的 CLI SHALL 在「添加账号」页提供「登录到」服务商选择（两列卡片单选，`role=radio`；最初设计为窗口顶部下拉框，2026-10-27 按用户反馈改为卡片），选项由 Host 按当前安装版本提供并标注已登录者。Host SHALL 只用 CLI 自身参数定位所选服务商（命令行参数，或原生斜杠命令的参数，如 OMP 的 `/login <服务商>`）；没有对应参数的服务商 MUST 不由插件在原生菜单中代选，改为在原生终端中由用户选择。ZCode 的 BigModel/Z.AI 选择并入同一组卡片。

#### Scenario: 以参数定位
- **WHEN** 用户选择的服务商可由原生参数指定
- **THEN** 以该参数启动原生登录，不先显示原生服务商菜单

#### Scenario: Hermes 的 Nous
- **WHEN** 用户在 Hermes 的「登录到」中选择 Nous
- **THEN** 以 `hermes auth add nous --type oauth` 启动原生登录，不进入 API Key 输入：Hermes 询问是否导入该目录已保存的共享 Nous 登录时由插件确认，否则窗口显示设备码与 Nous Portal 授权链接，全程不展开原生终端；Nous 登录不因当前选用的推理服务商是其他服务商而显示为未登录，确认以重新读取的原生 Nous 凭据为准
- **AND** 登录窗口运行期间的核对 MUST 直接读取该目录的原生账号存储，不得因窗口自身挡住 Nous 续期而把已保存的登录判为未完成
- **AND** 登录确认后，若插件账号目录的推理服务商为 `auto` 或未设置（如 Hermes 原生退出 Nous 后的状态），插件以 Hermes 原生 `config set model.provider nous` 选定 Nous（同时由 Hermes 清除上一服务商的路由），再报告登录成功；已明确选择的服务商保持不变，用户自己的 Hermes 目录不被改动
- **AND** Nous 模型列表按所登录账号读取，不要求目录里已有默认模型

#### Scenario: 退出 Hermes 的 Nous
- **WHEN** 用户在账号窗口退出 Nous 登录（无论凭据池是否已有条目）
- **THEN** 以 `hermes logout --provider nous` 一并清除该目录的 Nous 凭据、凭据池与共享登录，Hermes 下次启动不会把共享登录重新采用回来

#### Scenario: Windows Nous 目录经过系统代理
- **WHEN** Nous 登录已确认且 Host 模型目录请求经过 Windows 系统代理
- **THEN** 代理请求 SHALL 在调用方没有显式提供 User-Agent 时保留 Node fetch 的默认客户端标识；模型与强度仍只来自当前账号目录，不依赖默认模型是否存在或属于该目录
- **AND** HTML 403 或明确的 Cloudflare challenge 403 SHALL 提示网络拦截，不当作登录失效；不增加认证续期、重试、公共目录回退或模型调用，JSON 权限拒绝继续报账号权限错误

#### Scenario: Kimi、Pi、OMP 的服务商
- **WHEN** 用户在 Kimi、Pi 或 OMP 的「登录到」中选择服务商
- **THEN** Kimi 以 `kimi login --region mainland-cn|global` 启动设备码登录，Pi 以 `login <服务商>` 启动，OMP 在原生界面输入 `/login <服务商>`；之后的登录方式、平台选项与密钥由用户在窗口中回应

#### Scenario: 原生菜单由用户选择
- **WHEN** 服务商只能在原生菜单中选择（卡片中的「其他服务商」，或尚无参数的 CLI）
- **THEN** 启动原生登录并显示原生终端，由用户在菜单中选择；插件不写入方向键或回车代选

### Requirement: 多账号登录与切换
单账号 CLI 已登录时，登录窗口 SHALL 显示当前账号并提供「切换账号」，先自动退出并经原生状态确认后才进入登录；退出未确认 MUST 不继续登录。多服务商 CLI 选择已登录服务商时 SHALL 提示将替换其现有凭据；支持同服务商多凭据的 CLI SHALL 让用户选择添加另一个账号或替换。插件 MUST 不替任务挑选具体凭据。

#### Scenario: 切换单账号
- **WHEN** 用户在已登录的单账号 CLI 点击「切换账号」
- **THEN** 自动退出确认后进入登录向导；旧任务按换号续接规则处理

#### Scenario: 同服务商添加账号
- **WHEN** 用户在 Hermes 选择已登录服务商并选「添加另一个凭据」
- **THEN** 保留原凭据并新增一个，确认以该服务商凭据数增加为准

#### Scenario: 替换确认
- **WHEN** 用户选择已登录服务商且操作会替换其凭据
- **THEN** 先显示替换提示，用户确认后才启动原生登录

### Requirement: 账号窗口与逐个退出
多账号 CLI SHALL 提供「账号」窗口，列出已登录账号（服务商、登录方式、可安全显示的邮箱），原生支持单项退出的每行可单独退出，并提供「添加账号」。逐个退出 SHALL 先行内确认，再由 Host 以该 CLI 支持的单项退出方式自动完成，并以目标条目从原生状态中消失为准；MUST 不提供一键全部退出，其他账号保持不变。原生不支持单项退出时 SHALL 如实说明并交给原生终端。

#### Scenario: 退出一个账号
- **WHEN** 用户在账号窗口确认退出某一行
- **THEN** Host 只退出该条目，确认消失后该行移除，其他行不变

#### Scenario: 只能一起退出
- **WHEN** 原生只能同时退出一组账号（如 ZCode 的 BigModel 与 Z.AI）
- **THEN** 该组显示为一行并写明会一起退出

#### Scenario: 在原生列表中核对后选中
- **WHEN** 单条退出只能在原生列表中选择（OMP 的 `/logout` 列表、Kimi Code 的托管 OAuth 登录、MiMo `auth logout` 的凭据列表）
- **THEN** Host 逐行移动，只有高亮行可核对为目标（OMP 凭据行的唯一编号、Kimi 的 Kimi Code 行、MiMo 的 Xiaomi 行）时才按回车；Kimi Code 行带有当前模型标记（`← current`）时仍按 Kimi Code 行核对；列表走完、重复、超过上限，或画面静止仍未见目标时转原生终端，MUST 不在其他行上按回车

#### Scenario: 退出前核对目标仍在
- **WHEN** 用户确认退出某一行，Host 已为该 CLI 的账号目录保留账号终端
- **THEN** Host 在本地原生状态中核对该行仍在后才启动退出；核对 MUST 不因同一目录的续期（如 Hermes Nous）被保留挡住而把仍在的行误报为不存在；目标确已不在时提示刷新后重试，不启动原生退出

#### Scenario: 按所在位置分组
- **WHEN** Pi 或 OMP 同时有原生目录与插件目录中的凭据
- **THEN** 账号以卡片按所在位置分组（原生目录：直接运行该 CLI 时也会使用；插件目录：只在 CLI Worker 中使用），只列出任务实际使用的有效凭据（后加载位置覆盖同一服务商）；同服务商的多个 OAuth 账号以可安全显示的邮箱区分；来自环境变量或配置文件的行说明在原配置中管理，不显示退出按钮

#### Scenario: OMP 已退出的凭据
- **WHEN** OMP 退出后将凭据行标记为用户删除而保留该行
- **THEN** 该行视为已退出，不覆盖其他位置的同一服务商，也不显示为失效；因其他原因（如续期失败）停用的行仍占有该服务商、遮蔽较早位置的同名凭据且不列为可用账号。账号列表、任务快照与共享续期缓存 MUST 使用同一归属规则

#### Scenario: 退出未确认
- **WHEN** 限定时间内目标条目仍在
- **THEN** 该行显示未确认并提供显示原生终端，不重复写入

### Requirement: Windows 账号登录窗口的终端解析
登录窗口的引导 SHALL 按账号终端的「当前屏幕」判断步骤：解释光标移动、擦除、折行与备用屏幕，屏幕行数和列数有上限；登录链接 SHALL 取自当前屏幕上完整的网址或 OSC 8 链接目标，且只接受该 CLI 在共享白名单中登记的登录域名；设备码 MUST 是当前屏幕上完整的一段，MUST NOT 把被分块输出截断的前缀当作验证码。客户端隐藏的终端 SHALL 按 Host 返回的尺寸初始化，尺寸变化 SHALL 同步给引导。CLI 尚未画出任何文字时，引导 MUST NOT 判定为需要改用原生终端。

#### Scenario: 链接被折行或缩短显示
- **WHEN** Pi 或 OMP 在 ConPTY 中把 OAuth 链接折成多行，或用 OSC 8 只显示缩短的文字
- **THEN** 登录窗口打开的是完整链接，且该链接位于此 CLI 登记的登录域名下

#### Scenario: 设备码分块到达
- **WHEN** Kimi 的 `enter code:` 行在一次读取中只到达验证码前半段
- **THEN** 登录窗口不显示该前缀，直到整行完整后才显示验证码

#### Scenario: OpenCode 与 Hermes Nous 的登录页
- **WHEN** OpenCode 选择 ChatGPT 浏览器登录，或 Hermes 选择 Nous 设备登录
- **THEN** 登录窗口显示并可打开 `auth.openai.com`、`portal.nousresearch.com` 上的页面；其他域名不显示为可打开的链接

### Requirement: Windows 账号终端启动
Windows 账号终端 SHALL 在 CLI 启动前完成控制台归属与父进程校验；父进程校验 SHALL 持有被校验进程的句柄，读取失败、进程已退出或父进程不是 Host 时 MUST 拒绝启动。ConPTY 在客户端接上之前发出的首个主设备属性查询 SHALL 由 Host 以账号窗口终端的身份回应一次，并从回放给客户端的输出中去掉该查询；之后的查询与其他字节 MUST 原样传递。

#### Scenario: 打开登录窗口
- **WHEN** 用户在 Windows 上打开任一 CLI 的登录窗口
- **THEN** 引导脚本不必等待客户端回应设备属性查询即开始执行，CLI 只收到一次回应

#### Scenario: 父进程校验失败
- **WHEN** 控制台宿主进程已退出或其父进程不是 Host
- **THEN** 账号终端启动失败并清理已启动的进程，不运行 CLI

### Requirement: 各 CLI 登录步骤与原生提示一致
登录窗口 SHALL 按已安装 CLI 实际打印的提示推进，MUST 在 CLI 确认保存后才进入「确认登录」，MUST NOT 回显原生错误或请求网址。

#### Scenario: Hermes 先问 Key 后问名称
- **WHEN** Hermes `auth add <provider> --type api-key` 在粘贴 Key 后询问可选名称
- **THEN** 插件回车保留原生默认名称，看到 `Added … credential #N` 后才确认登录

#### Scenario: Grok 回调未自动完成
- **WHEN** Grok 提示粘贴浏览器跳转网址
- **THEN** 输入框标为「回调网址」，提示粘贴浏览器最后跳转的完整网址

#### Scenario: Grok 连不上登录服务
- **WHEN** Grok 在打印网址前报告请求超时或 TCP 连接失败
- **THEN** 登录窗口结束并提示检查网络或代理，不显示原生错误原文

#### Scenario: OpenCode 的 OpenAI 登录方式
- **WHEN** OpenCode 为 OpenAI 显示登录方式菜单
- **THEN** 登录窗口提供浏览器、设备码、API Key 三种选择；其他服务商的方式菜单交给原生终端

#### Scenario: OpenCode 退出单个服务商
- **WHEN** 用户在账号窗口退出 OpenCode 的某个服务商，且该服务商只在一处 `auth.json` 中有凭据
- **THEN** 插件用 OpenCode 自己的 `auth logout` 作用于那一处凭据；凭据同时存在于多处或来自 `opencode.json` 时拒绝并说明请在原生配置中管理

#### Scenario: OMP 18.x 授权码输入框
- **WHEN** OMP 18.x 在登录对话框中等待授权码或完整跳转网址
- **THEN** 登录窗口提供粘贴框，粘贴后提交给该输入框，并继续观察登录结果

#### Scenario: ZCode 账号绑定未确认
- **WHEN** ZCode 插件凭据目录中只有身份或令牌、无法确认账号绑定
- **THEN** 摘要提示「账号绑定未确认，请重新登录」，不显示为已登录

### Requirement: 账号确认阶段的清理未确认
账号窗口在确认登录、退出或识别当前画面时读取原生账号；读取进程范围无法确认退出时，插件 SHALL 登记该 CLI 的清理保护并停止本次确认轮询，账号窗口显示未能确认，MUST NOT 吞掉该错误后继续启动新的读取进程。普通读取失败仍按原逻辑继续轮询直至超时。处于清理暂停的 CLI，账号状态 SHALL 以结构化的不可用状态返回（含暂停原因和可解除标记），不得提示重启应用即可解决。

#### Scenario: 确认退出时读取未清理
- **WHEN** 用户在账号窗口退出 Antigravity，插件确认退出结果的身份读取报告进程清理未确认
- **THEN** 登记 Antigravity 的清理保护，停止后续读取，窗口显示退出未能确认；设置页随后显示暂停原因和解除入口

#### Scenario: 普通读取失败
- **WHEN** 确认轮询中的一次身份读取因普通错误失败
- **THEN** 继续按原间隔轮询，直到账号变化被证实或超时

#### Scenario: 暂停中的账号状态
- **WHEN** 设置页读取一个处于按 CLI 清理暂停的 CLI 的账号状态
- **THEN** 返回不可用状态、暂停原因和可解除标记，不启动新的读取进程，也不以异常替代状态

### Requirement: Grok 续期失败与读取失败的账号状态
Grok 账号状态 SHALL 与续期结果一致。若原生续期已被 Grok 明确拒绝、需要手动登录，在原生凭据文件发生变化之前，账号状态 SHALL 显示为登录已失效，不再显示绿色「已登录」。该记录 MUST 只保存在 Host 内存中，以不含秘密的凭据指纹为键，Host 重启或凭据文件变化后失效。网络或服务暂不可用导致的续期失败 MUST NOT 降级账号状态。

读取原生凭据失败时，SHALL 区分文件缺失、格式不受支持、文件安全检查未通过和读取失败四种情况，并给出脱敏后的简短原因；MUST NOT 把非缺失类故障统一说成「请先登录 Grok」。续期相关提示 SHALL 指向设置中实际存在的「账号终端」入口。

#### Scenario: 续期被拒绝后状态一致
- **WHEN** Grok 原生续期明确失败且需要重新登录
- **THEN** 导航和账号行显示登录已失效，模型区域提示在账号终端重新登录；用户重新登录、凭据文件变化后，刷新即恢复为已登录

#### Scenario: 续期因网络失败
- **WHEN** 续期因网络或服务错误失败
- **THEN** 账号状态保持已登录，只在模型区域显示续期暂时失败

#### Scenario: Host 重启
- **WHEN** Host 重启后尚未再次尝试续期
- **THEN** 按原生凭据证据显示状态，不沿用重启前的失败记录

#### Scenario: 凭据文件缺失
- **WHEN** Grok 原生凭据文件不存在
- **THEN** 显示尚未登录 Grok，并提供账号终端登录入口

#### Scenario: 凭据格式或安全检查异常
- **WHEN** 凭据文件存在，但格式不受支持、是符号链接或多重硬链接、读取期间被替换，或读取失败
- **THEN** 分别显示对应的简短原因，不显示为尚未登录，不输出文件内容或凭据片段

### Requirement: 安装驱动的 Pi 和 OMP 登录选项
Pi 与 OMP 的登录选项 SHALL 来自当前所选安装的原生可登录服务商注册表，完整保留当前平台可用的原生 ID，并区分智谱国内 BigModel 与国际 Z.AI。未知或读取失败 MUST 不回退猜测列表，仍提供原生终端入口；启动所选登录前 MUST 再确认该安装支持该 ID。

#### Scenario: 安装包含额外提供商
- **WHEN** 当前 Pi 或 OMP 注册表包含固定列表遗漏的 API Key 或 OAuth 服务商
- **THEN** 添加账号列表展示全部原生可用项，使用其自身登录参数；原生未支持的另一 CLI 的 ID 不得混入

#### Scenario: 平台或版本不同
- **WHEN** macOS 与 Windows 的已安装版本提供不同选项，或用户切换 CLI 路径
- **THEN** 选项按当前安装读取，旧安装缓存不得用于新安装；不可用方式不显示为可直接登录

#### Scenario: 发现失败
- **WHEN** 原生注册表不可读或查询进程未确认退出
- **THEN** 不展示编造的直接登录项；进程清理未确认时继续暂停该 CLI，其他失败保留原生终端入口

### Requirement: Pi 和 OMP 按来源与凭据确认退出
Pi/OMP 退出 SHALL 仅作用于明确选择的来源和原生凭据；OMP 同服务商多凭据 MUST 按稳定凭据 ID 定位，不按邮箱、密钥、排序或当前高亮猜测。原生调用及目标存储回读确认删除后才报告成功；无法识别、读取失败、取消或进程清理未确认 MUST 不报告成功。其他来源、同服务商其他凭据和配置凭据 SHALL 保留。

#### Scenario: OMP 新旧 key 共存
- **WHEN** 用户退出同 provider 的旧凭据 id=1，另有新凭据 id=2
- **THEN** 只向原生流程提交 id=1，确认 id=1 消失且 id=2 保留后报告成功

#### Scenario: 新版有边框菜单
- **WHEN** OMP 的凭据选择行含原生面板边框
- **THEN** 精确识别选中凭据 ID；无法确认高亮或行被截断时停止自动选择，绝不猜测回车

#### Scenario: Pi 无交互退出
- **WHEN** 用户退出 Pi 某一服务商
- **THEN** 原生 SDK 仅操作所选 auth 存储并回读，不因无关会话/工具/交互 UI 初始化阻塞退出

#### Scenario: 替换未完成
- **WHEN** 新凭据已保存但指定旧凭据的原生退出未确认
- **THEN** 不宣称替换完成，明确保留失败状态，不自动删除其他凭据或放宽模型交集规则

#### Scenario: Distinguish OMP credentials without exposing keys
- **WHEN** 同来源同 provider 有多条 OMP 凭据
- **THEN** 账号行和替换选项 SHALL 展示原生凭据编号，退出请求保留完整来源/provider/id，不能按列表顺序猜测目标或显示 API key。

### Requirement: CodeBuddy 单入口图形账号流程
CodeBuddy Code SHALL 保持 `codebuddy` 单入口，将中国站、国际站、企业域与 iOA 作为原生账号站点。插件 SHALL 通过安装版 TUI 的 `/login` 和 `/logout` 引导登录及退出，不编造非交互登录子命令。未识别画面、企业自定义流程或未核实的站点选择 MUST 保留原生接手。

#### Scenario: 进入登录与选择站点
- **WHEN** 用户启动 CodeBuddy 登录，原生画面已显示可核对的输入就绪状态或站点菜单
- **THEN** 插件只在就绪状态输入一次 `/login`，或直接绘制已出现的站点选项；只根据用户当前选择响应匹配菜单，不默认选择中国站或国际站，不重复发起登录

#### Scenario: 无法安全定位选项
- **WHEN** 菜单不完整、重绘后高亮无法核对，或企业域/iOA 步骤尚未支持
- **THEN** 提示并转入原生终端，不凭选项顺序猜测按键，不把企业账号拆成另一 CLI

#### Scenario: 账号读取边界
- **WHEN** 图形流程确认 CodeBuddy 状态或显示站点
- **THEN** 仅沿用自身本地登录状态与获准的站点投影；认证文件内容只取 `auth.domain`，不读 token，不调用返回访问令牌的用户信息接口，不用文件修改时间或站点标签证明换号

### Requirement: TRAE CN 单账号登录方式选择
TRAE CN SHALL 保持单账号，复用两列卡片让用户明确选择个人、企业 SSO 或企业 PAT。个人方式 SHALL 使用 `traecli --enable personal_user_login login --personal`，SSO 使用 `traecli login --enterprise`，PAT 使用 `traecli login --with-trae-pat`；登录特性开关 MUST 只作用于本次个人登录，不写配置或附加到任务启动。

#### Scenario: 个人登录
- **WHEN** 用户选择个人登录并继续
- **THEN** 以个人 argv 启动，说明其依赖开发中特性；只对真实画面已核实的步骤提供浏览器、设备码或回调模板，未知画面可显示原生终端

#### Scenario: 企业登录
- **WHEN** 用户选择企业 SSO 或企业 PAT
- **THEN** 进入对应原生流程并提供原生接手；不猜测 SSO 域名或协议，不在插件中收集企业 PAT，不读取/显示其环境变量值；原生 CLI 继续按自身规则读取环境或 stdin

#### Scenario: 没有选择或方式失效
- **WHEN** 用户取消选择，或请求携带未知方式，或当前 Host 不支持方式选择
- **THEN** 不启动默认登录、不回退个人账号，显示可理解的原因

#### Scenario: 套餐或状态未知
- **WHEN** TRAE 状态报告套餐不支持、未知输出或查询失败
- **THEN** 保留对应原因，不显示登录成功，不推断个人/企业身份；登录确认以新的 `login status` 状态及对应退出结果为准

### Requirement: 新增单账号向导的自动退出与切换
CodeBuddy 和 TRAE CN 已登录时 SHALL 先显示当前账号卡片，打开卡片不启动登录进程。用户明确点击「切换账号」后 SHALL 自动执行本 CLI 已核实的退出流程，确认账号已退出并确认所属进程范围已清理后才进入新的登录向导；读取错误、未知状态或清理失败 MUST 阻止后续登录。TRAE 退出使用 `traecli logout`。

#### Scenario: 切换成功进入向导
- **WHEN** 用户点击切换，原生退出已确认且进程清理成功
- **THEN** CodeBuddy 进入新的站点/授权流程，TRAE 进入登录方式选择；旧目录结果失效，重新核对账号与模型，不自动保存新模型偏好

#### Scenario: 退出未确认
- **WHEN** 原生退出码为零但账号仍登录，或查询不可用/未知/读取被拒绝
- **THEN** 显示未确认原因及重试/原生接手，不以终端文字、零退出码或非 authenticated 的泛化判断认定退出

#### Scenario: 原生信任或未知确认屏
- **WHEN** 自动退出遇到未授权的 trust/条款或未识别菜单
- **THEN** 保留用户决定或原生回退，不自动同意、不无限补 Enter，也不删除原生账号文件

### Requirement: WorkBuddy 桌面端账号图形引导
`workbuddycn` 与 `workbuddy` SHALL 提供复用步骤窗口的桌面账号管理指引。用户点击打开桌面端后，Host MUST 只打开与当前 CliId 身份一致的已安装应用；登录、退出和换号由用户在该桌面应用完成。插件 MUST 不运行虚构的 CLI login/logout、不提供伪账号终端、不删除凭据或自动退出桌面账号。

#### Scenario: 未登录打开桌面端
- **WHEN** 用户在 WorkBuddy 引导页点击打开桌面端
- **THEN** 打开已核实版本的应用，显示等待用户登录及状态刷新操作；打开成功本身不表示已登录

#### Scenario: 已登录管理账号
- **WHEN** 用户查看已登录的 WorkBuddy 账号页或点击桌面管理
- **THEN** 显示可确认的当前状态与站点，明确在桌面端退出或换号；不展示“插件将先自动退出”的承诺，不提供凭空生成的账号邮箱

#### Scenario: 安装不匹配或打开失败
- **WHEN** 应用缺失、安装身份不符、路径属于另一版或打开失败
- **THEN** 保留原因及重试/手动打开指引，不回退另一版、PATH CodeBuddy 或任意外部程序

### Requirement: WorkBuddy 有界状态观察
WorkBuddy 图形管理页 SHALL 在显式打开后以单个在途查询、有限间隔和总时限观察本版原生元数据状态，允许手动刷新。查询 MUST 不发模型 prompt、不新增凭据读取或持久化，不把安装/站点绑定当作账号主体。仅确定的认证缺失可证明退出，普通探测失败 MUST 保持不可用；观察结束或关闭后不得继续自动查询。

#### Scenario: 桌面登录后自动确认
- **WHEN** 同一引导会话先确认未登录，用户在桌面端登录后元数据查询成功
- **THEN** 窗口自动显示当前已登录并刷新相关目录，停止自动观察；不得宣称真实模型任务已验收

#### Scenario: 同站点换号不可辨认
- **WHEN** 元数据在操作前后都为已登录且没有稳定账号主体
- **THEN** 只显示当前已登录，保留手动刷新或继续观察，不报告“已切换到新账号”；若观察到确定退出再登录，可报告这一状态转换但不捏造新身份

#### Scenario: 退出、失败和超时
- **WHEN** 用户在桌面端退出，或探测失败，或观察到达时限
- **THEN** 确定未登录时显示当前未登录；普通错误保留失败类别；超时停止自动查询并允许手动刷新，不把错误或超时当作已退出

#### Scenario: 查询副作用和清理
- **WHEN** 状态观察触发原生空会话查询或用户关闭窗口
- **THEN** 账号和模型复用同一周期的查询，不重叠启动；关闭取消本次观察并确认插件查询进程/助手退出，不关闭用户桌面应用，不声称原生空会话已删除

### Requirement: 新图形引导的呈现与链接边界
新增账号引导 SHALL 复用 480px 窄窗口、主题 token、淡色提示、浅灰账号卡片、两列选择和右对齐操作，状态文字与相应按钮同排；提供中英文固定文案。CLI 文本 MUST 作为不可信终端内容处理，浏览器链接必须为本 CLI 已核实的 HTTPS 主机且无 userinfo。桌面管理页 SHALL 隐藏不存在的终端回退按钮。

#### Scenario: 非白名单或企业地址
- **WHEN** 终端给出相似恶意域名、未核实子域、含 userinfo 或非 HTTPS 地址
- **THEN** 图形页不提供打开/复制该地址的登录按钮，保留原生接手，不通过扩大企业域通配来绕过校验

#### Scenario: 原生终端回退
- **WHEN** CodeBuddy 或 TRAE 出现未知步骤
- **THEN** 登录与退出 MUST NOT 自动展开原生终端：窗口只显示“无法识别当前步骤”、「显示原生终端」及关闭后重新登录的提示；只有需要用户在终端里作答的已录制步骤（企业域地址、iOA、TRAE 企业流程等）才自动展开并聚焦；结果页不被迟到关闭消息覆盖

#### Scenario: CodeBuddy 授权未完成
- **WHEN** 浏览器授权超时（5 分钟，TimeoutError）、无法打开或被取消，CodeBuddy 显示 `Failed to login. Press esc to return to login`，或在已输入过 `/login` 后回到输入界面
- **THEN** 窗口 SHALL 显示警告与「重新登录」，不显示原生错误原因；点击后分别按 Esc 回到站点菜单或重新输入 `/login`，不自动重复发起登录

#### Scenario: 桌面管理与旧 Host
- **WHEN** WorkBuddy 没有 PTY，或旧 Host 未声明桌面管理能力
- **THEN** 前者显示桌面管理/刷新操作而无终端按钮；后者只保留原有指引，不发送未知 RPC 或创建虚假运行状态

### Requirement: 新引导的权限与会话生命周期
新增账号操作 SHALL 沿用父会话归属、CLI 启用检查、宿主执行权限与同 CLI 互斥。取消、关闭、父会话结束或插件卸载 MUST 中止写键、观察和订阅，并回收插件拥有的进程范围；清理未确认时保持阻塞，不自动重启登录。所有敏感输入 MUST 不进入引导帧、Worker 日志或持久化。

#### Scenario: 权限拒绝或任务占用
- **WHEN** 父会话不能执行账号动作，或同 CLI 有活动任务/账号操作
- **THEN** 拒绝启动登录、退出或桌面管理动作，保留现有账号与会话，不自行放宽权限

#### Scenario: 取消与迟到结果
- **WHEN** 用户取消等待中的启动/查询，随后旧请求返回终端或状态
- **THEN** 回收迟到资源并丢弃旧结果，不写入新的 CLI 窗口或开始下一步登录

#### Scenario: 清理失败后恢复
- **WHEN** 进程范围清理无法确认
- **THEN** 保留明确失败与既有清理保护，不能将停止报告为成功或放行新的冲突操作；按已有解除暂停流程恢复

### Requirement: 新图形登录的证据分层
该变更的交付记录 SHALL 分开列出文档、Host、Client、模拟测试、未提交授权的真实画面采集及 Desktop 验收。新 marker MUST 来自可核查的安装版画面；不能取得的步骤保留未完成。规格严格校验、模拟状态和构建通过 MUST 不替代真实登录/退出、Windows 或 Desktop 证据。

#### Scenario: 只完成文档
- **WHEN** 方案与指南通过严格规格校验，但没有实施代码或采集屏幕
- **THEN** 只勾文档及实际校验，Host/Client/测试/采集/Desktop 任务保持未完成，不归档隐藏缺口

#### Scenario: 采集不提交授权
- **WHEN** 在隔离 HOME 中采集新 CLI 的授权前画面
- **THEN** 不提交账号凭据、浏览器授权或模型请求；必须经过真实授权才能看到的后续画面记为缺失，模拟夹具明确标为模拟
