# cli-model-discovery Specification

## Purpose

为用户提供与各外部 CLI 原生目录和已有配置一致的模型与服务商选择，避免将一次验收采用的模型误当成完整支持范围；同时保留原生标识、账号隔离、参数能力证据和远端可用性边界。

## Requirements

### Requirement: 原生模型和服务商发现
全部 11 个活跃 CLI SHALL 从各自原生目录或已有配置发现候选模型，不得固定为 GLM-5.3-Flash。所有 CLI 的可选模型 MUST 经过当前账号和 Worker 路由的可用性筛选，不能直接呈现提供商大全；Claude 自身显式网关配置仅按下述网关规则作为带证据说明的候选。模型 SHALL 保留 provider 与原生 model 标识，区分可选项与隐藏、无效或缺乏账号支持证据的条目。目录读取失败 MUST 提供错误，不得用编造模型填补。Worker 续聊菜单可按「Worker 使用保存目录延后实际选型」复用原账号绑定的已核验目录，仅在实际执行前重新验证当前可用性。

#### Scenario: ZCode 多账号目录
- **WHEN** 原生目录与当前账号支持范围相交后包含多个可见服务商及 GLM-5.3、GLM-5.3-Flash、GLM-5.2 等模型
- **THEN** 可选择各有效条目，隐藏服务商不作为用户选项

#### Scenario: Pi 和 OMP 多接口
- **WHEN** CLI 的已有配置包含多个有账号支持证据的服务商模型或有效自定义模型
- **THEN** 列表保留通过筛选的原生模型，禁止补入 Host 账号模型；未登录提供商和无账号支持证据的通用条目不展示

#### Scenario: 目录损坏
- **WHEN** 原生目录或配置无法读取、解析或探测失败
- **THEN** 模型区域显示可解释错误，不能虚构成功目录；账号状态灯保持账号检查的真实结果

#### Scenario: Antigravity 原生账号目录
- **WHEN** Antigravity 自身 consumer 登录有效，原生 models 命令返回当前账号可选模型
- **THEN** 使用本次原生目录并按实际报告的变体生成强度，不因为没有通用服务商模型接口而封锁原生目录；退出或自定义来源改变时重新检查

### Requirement: 原生选型执行与账号隔离
选择的原生模型和服务商 SHALL 传递至对应 CLI 执行与观察模型核验；模型及推理参数 MUST 有原生能力证据。所有 CLI SHALL 只识别并使用自身原生或插件内自身账号；旧 Host 智谱引用只兼容解析且不再生效，禁止注入其他账号或改写原生账号。

#### Scenario: 使用非 GLM 模型
- **WHEN** 用户选择原生已配置的非 GLM 服务商模型
- **THEN** 执行参数与桥接环境指向该模型及原生账号，观察核验不强制 GLM-5.3-Flash

#### Scenario: 同会话结束后改选
- **WHEN** 用户在一轮结束后修改同一 CLI 会话的模型或强度并续聊
- **THEN** 保留原生会话 ID，通过原生选型机制应用该选择并在任务开始前核验；拒绝或不匹配必须失败，不得继续使用旧模型

#### Scenario: 原生自定义模型
- **WHEN** ZCode 的个人配置包含有效的自定义 provider 与手动模型规则
- **THEN** 目录与执行采用原生合并后的配置，保持原文件不变，不仅列出 builtin 模型

#### Scenario: 旧智谱引用
- **WHEN** 项目沿用旧 Host 智谱引用和已有 GLM-5.3-Flash 偏好
- **THEN** 保留旧偏好供查看，禁用 Host 来源路由并要求重新选择本 CLI 自身账号模型，不自动映射其他 provider

#### Scenario: 推理选项
- **WHEN** 原生模型未提供可映射的强度或只支持启用／关闭推理
- **THEN** 仅展示有证据的原生默认或对应选项，不能套用其他模型强度

### Requirement: 目录证据和生命周期边界
目录发现 SHALL 是有超时、取消和进程清理的非模型任务查询；目录和本地凭据存在 MUST 不被描述为已通过远端授权或真实任务验收。查询数据不得含密钥，临时状态使用私有权限。可归属的元数据查询失败 SHALL 按 CLI 隔离；无法确认清理时仅暂停对应 CLI 的后续查询、账号变更和任务准入，保留持久保护，并在界面说明中附上经脱敏、截断的原始原因；持久记录 MUST 不保存原因、路径、输出或账号。查询正常结束时 SHALL 先在短宽限内等待进程范围自然退出，仍未退出才终止并等待确认；取消与失败路径仍立即终止。按 CLI 的保护 MUST 不在无人确认时自动清除；用户在该 CLI 没有运行或排队任务、账号终端及在途查询时明确确认后，SHALL 清除该 CLI 的保护并重新读取。真实任务范围清理失败及旧无归属保护记录 MUST 保留全局拒绝，不提供此恢复入口。

#### Scenario: 查询被取消
- **WHEN** 用户关闭或取消模型查询
- **THEN** 相关进程和账号 HTTP 元数据请求均取消并清理，不产生模型任务或遗留账号终端；确认清理后不封锁其他查询

#### Scenario: 查询正常结束
- **WHEN** 元数据查询读完输出且原生命令正常退出
- **THEN** 先等待进程范围自然退出；在宽限内退出则不再发送终止，超过宽限才终止并等待确认，任一结果都不能把直接命令退出当作整个范围已退出

#### Scenario: 准备查询未确认退出
- **WHEN** 可明确归属 CLI 的元数据进程范围无法确认已经退出
- **THEN** 不报告停止成功，阻止该 CLI 的进一步查询、账号变更和任务准入，并持久保留保护及仍可能被使用的私有状态；暂停说明附带脱敏的原始原因，其他 CLI 的刷新与任务准入保持可用

#### Scenario: 远端未验证
- **WHEN** 本地模型目录和账号信息读取成功
- **THEN** 界面说明该证据范围，仍保留实际调用可能出现订阅或认证失败的结果

#### Scenario: 十二 CLI 中任意刷新失败
- **WHEN** 任一活跃 CLI 刷新遇到认证续期、拒绝、目录格式错误、网络超时或已确认清理的取消
- **THEN** 只显示该 CLI 的真实失败，不污染其他 CLI 的账号、模型目录、缓存、偏好或准入，也不发送模型请求

#### Scenario: 按 CLI 保护冷恢复
- **WHEN** Host 重启且存在一个或多个有效的 CLI 元数据清理保护记录
- **THEN** 仅继续阻止这些 CLI，不能自动清除保护或将其他 CLI 一并封锁；损坏的按 CLI 记录同样只对其 CLI 拒绝

#### Scenario: 用户确认解除按 CLI 暂停
- **WHEN** 某 CLI 处于按 CLI 的元数据或账号查询清理暂停，且该 CLI 没有运行或排队任务、打开的账号终端或在途查询，用户在设置中确认解除
- **THEN** 删除该 CLI 的保护记录并清除对应内存占用，之后重新读取账号和模型目录；其他 CLI 的保护不变，重启后不再因已清除的记录暂停

#### Scenario: 解除被拒绝
- **WHEN** 该 CLI 仍有运行或排队任务、打开的账号终端或在途查询，或存在全局任务清理保护
- **THEN** 拒绝解除并说明原因，保护记录和占用保持不变

#### Scenario: 任务清理或旧无归属保护
- **WHEN** 真实任务进程范围无法确认退出，或存在不能确定 CLI 的旧全局保护记录
- **THEN** 继续全局阻止后续冲突工作，不将未知范围静默缩小为某一个 CLI，也不提供按 CLI 的解除入口

### Requirement: 按账号与执行路由筛选
全部 11 个活跃 CLI SHALL 结合当前认证有效性、原生账号模型范围、原生候选配置及绑定当前账号的可核查路由证据筛选可选模型。未登录、已知失效、账号不支持、仅在公共大全或自定义配置中存在但没有账号支持证据、或已知不适用于 Worker 的模型 MUST 不进入设置、首次派遣和 Worker 改选选项。无法确认账号范围时 SHALL 隐藏未经确认的候选并说明证据边界，不通过批量计费任务猜测；Claude 自身显式网关配置按专门规则处理，不描述为已通过远端调用。服务商明确拒绝凭据认证导致目录为空时，SHALL 说明是认证失败及处理方式，MUST NOT 只显示泛化的空目录提示。

#### Scenario: OAuth 账号模型范围
- **WHEN** 已登录 OAuth 账号只公布一部分可用模型
- **THEN** 只展示该账号支持且认证有效的部分，不把提供商通用目录的其他模型一并展示

#### Scenario: 原生多账号池
- **WHEN** 同一提供商原生执行可能选用多个已登录账号
- **THEN** 发现与执行采用相同账号来源，并仅展示每个可能执行账号均支持的模型；任一账号范围未知不得通过其他账号的结果扩大清单

#### Scenario: 多账号池中有凭据被拒绝认证
- **WHEN** Pi 或 OMP 同一提供商的多条凭据中，部分凭据被服务商明确拒绝认证（401/403 或认证错误码），其余凭据的范围全部确认支持
- **THEN** 被拒绝的凭据不参与交集，按其余凭据的交集展示模型，并提示已跳过几条认证失败的凭据、可在账号窗口退出；不自动退出或修改任何凭据

#### Scenario: 全部凭据被拒绝认证
- **WHEN** Pi、OMP 或 OpenCode 所有可用于执行的凭据都被服务商明确拒绝认证，目录因此为空
- **THEN** 提示该 CLI 账号认证失败，请在账号窗口重新登录或退出失效凭据后刷新；不显示为「暂无可用模型」

#### Scenario: 公共端点与当前额度
- **WHEN** 提供商通用 models 端点不体现账号限制，或 OAuth 当前额度不允许调用
- **THEN** 使用账号专属范围与额度元数据筛选；公共目录和已耗尽或无法确认的 OAuth 额度不得充当可执行证据

#### Scenario: 无账号或已失效
- **WHEN** 一个提供商未配置、凭据已知失效或账号模型范围无法确认
- **THEN** 其未经支持证据确认的模型不作为选项；界面说明空列表或收窄原因

#### Scenario: 原生 API 与配置证据
- **WHEN** 原生 API 模型列表或绑定当前账号的可核查路由证据确认对应账号支持原生或自定义模型
- **THEN** 保留该模型的确切路由，但不将它外推成所有同提供商模型都可用

#### Scenario: 配置不能替代账号权限
- **WHEN** 用户写入自定义模型或旧 Host 引用，但账号模型端点不存在或当前账号范围无法确认
- **THEN** 不以配置本身或未绑定当前账号的旧成功记录证明可用，隐藏该候选并保留旧偏好供后续重新核对；Claude 当前自身显式网关模型仅按专门规则显示配置候选

#### Scenario: 公共免费目录但 Worker 不可用
- **WHEN** 原生公共目录包含免费模型但该模型已知拒绝当前 Worker 执行方式
- **THEN** 不把它作为可用或免费优先的选项，不静默替换其他模型

#### Scenario: 仅公共或默认目录
- **WHEN** Grok ACP 返回公共目录，Hermes 只有默认 provider/model，或 ZCode 只有内置目录且无对应账号支持证据
- **THEN** 不作为可调用模型展示；保留登录、配置和刷新入口，不能用其他 CLI 的账号证明可用

#### Scenario: 刷新失效与返回身份不符
- **WHEN** 设置或 Worker 改选重新查询期间、查询失败，或返回的 CLI 与所选 CLI 不同
- **THEN** 旧目录不可继续选择；原有存储偏好不变，派遣必须重新验证精确模型及强度

#### Scenario: 前五 CLI 候选与匿名免费模型
- **WHEN** 只有 Codex 旧缓存、Claude 固定别名、Kimi/MiMo 配置候选或匿名免费公共入口，没有本 CLI 当前账号支持证据
- **THEN** 不展示也不允许调用；使用同 CLI 原生账号范围或支持的只读服务商查询确认，无法确认则空目录和短原因；Claude 当前自身显式网关模型按专门规则处理

### Requirement: 简化名称与模型去重
设置、首次派遣、Worker 改选和任务卡片 SHALL 仅显示模型名称，去除 provider／account 前缀及括号附注，内部完整原生 ID SHALL 保留。相同原生模型 SHALL 在可见选项中去重，不能仅凭相似显示名称合并不同型号或将不同路由的能力合并。有效的既有选择 SHALL 保持精确路由，不可用时请求重新选择而非静默切换。

#### Scenario: 长路由历史记录
- **WHEN** 历史模型 ID 为 account:bigmodel-individual-coding-plan/GLM-5.3-Flash
- **THEN** 卡片显示 GLM-5.3-Flash，存储与执行 ID 保持原值

#### Scenario: 菜单附注与重复路由
- **WHEN** 多个可用路由指向相同原生模型且名称附有 provider 括号
- **THEN** 可见菜单只保留该模型一项并删除括号附注，不篡改选中路由及其强度

#### Scenario: 名称相似的不同模型
- **WHEN** 候选包含 GLM-5.3 和 GLM-5.3-Flash 或不同原生版本
- **THEN** 分别保留，不以名称清洗为由误合并

### Requirement: 免费模型优先
通过可用性筛选且有明确免费价格或免费额度证据的模型 SHALL 在新选择中优先排列，并在重复模型路由中优先作为新选择。未知价格、缺失成本被 SDK 填成零或付费订阅 MUST 不被当作免费。免费优先 SHALL 不自动改写现有偏好、不跳过首次选择，也不因免费模型失败而自动改用付费路由。

#### Scenario: 已证实免费与付费重复
- **WHEN** 同一模型的可用路由分别具有明确免费和付费成本证据
- **THEN** 新选择优先免费路由，显式已保存的有效付费路由保持不变

#### Scenario: 成本未知
- **WHEN** 自定义模型没有成本信息或只有 SDK 缺省的零值
- **THEN** 价格视作未知，不放入免费优先分组

#### Scenario: 多账号成本不同
- **WHEN** 同一原生模型在可能执行的账号中具有不同费用或未知费用
- **THEN** 仅在所有可能账号都具有明确免费证据时标为免费，不用任一账号的免费结果替代执行成本

### Requirement: Grok 自身账号模型目录
Grok 的可选模型 SHALL 在当前自身账号明确通过官方 Build 访问门禁后，由该账号认证的官方模型目录与当前原生能力精确求交。目录 HTTP 200、登录成功、匿名、内置或缓存 fallback MUST 不独立证明调用权限；门禁拒绝、门禁未知、成功空响应、认证拒绝、网络失败和插件尚未支持 SHALL 保持不同的诊断含义，详细解释不堆叠到设置页。

#### Scenario: 有效账号目录
- **WHEN** 自身 Grok 官方 Build 访问门禁明确允许、模型请求成功，且模型与强度被当前原生 CLI 明确支持
- **THEN** 显示模型及强度交集，不能因曾缺少实现而无条件清空，也不能用匿名静态 fallback 否定原生动态模型能力

#### Scenario: 目录可读但没有调用权限证据
- **WHEN** 账号能读取模型目录，但官方 Build 访问门禁未明确允许
- **THEN** 模型不可选；门禁未知不能被描述为没有订阅，门禁拒绝不能被目录 HTTP 200 覆盖

#### Scenario: 仅原生公共候选
- **WHEN** 原生 ACP 返回候选，但账号目录请求失败或不可用
- **THEN** 模型不可选；不能将该空列表描述成账号没有模型权益的事实

#### Scenario: 账号改变或查询取消
- **WHEN** 账号在查询期间退出、切换，或用户取消查询
- **THEN** 丢弃原结果并结束 HTTP 请求和原生进程，不恢复旧登录或发起生成

#### Scenario: 请求目标与凭据隔离
- **WHEN** 当前凭据不是受支持的自身官方 Build 认证，或响应尝试跳转至另一目标
- **THEN** 不向其他服务发送凭据，不借用通用 API Key 或其他 CLI 账号查询

### Requirement: Hermes Nous 自身账号目录
Hermes 的 Nous 目录 SHALL 使用当前自身原生登录及官方认证元数据，结合账号访问范围与原生聊天能力筛选。公共 fallback、仅登录成功或默认模型配置 MUST 不独立成为可选依据；已登录却缺少服务商实现不能伪装成账号无权益。目录准入前可按同源 OAuth 续期规则恢复短期访问令牌，续期不作为模型权限或额度证明。

#### Scenario: Nous 授权已写回
- **WHEN** Hermes 当前独立账号中的 Nous 授权有效，官方元数据确认账号模型及权限
- **THEN** 展示其与原生聊天能力的模型/强度交集；无需重新登录或借其他 CLI 账号

#### Scenario: 无付费权限
- **WHEN** 当前 Nous 账号没有付费访问权
- **THEN** 只开放官方明确允许该账号访问的免费模型，未知价格或通用目录不作为免费证据

#### Scenario: 目录异常或取消
- **WHEN** 请求被拒绝、超时、重定向、返回无效数据，或用户取消
- **THEN** 不回退公共目录，不生成试探，不把目录错误作为循环刷新或切换账号的理由；结束请求并给出简短原因，原登录信息按自身证据保留

#### Scenario: 短期令牌可续期
- **WHEN** 当前访问令牌临近过期或已过期，但同一明确自身账号具备可核验的原生刷新凭据
- **THEN** 先按同源规则完成有界非交互续期，再重新认证读取目录；不能以存在刷新凭据或原生续期成功代替目录权限检查

### Requirement: Claude 自身网关配置模型
Claude 的当前自身网关若不提供模型目录，或当前自身 loopback 代理成功返回原始空目录但仍有明确角色映射，Host SHALL 仅将该路由中明确配置的有效模型作为候选，标注来自路由配置且远端可用性未核验、费用未知。原生上下文后缀 SHALL 保留在选型和执行中，目录求交仅移除原生支持的后缀。明确认证拒绝、网络失败或无效响应 MUST 不通过配置候选或官方账号回退掩盖。

#### Scenario: 网关目录未实现
- **WHEN** Claude 自身 API 或本地网关的目录返回 404/405，且当前自身 settings 明确配置了模型
- **THEN** 仅显示这些配置模型及证据说明，不将其描述为账号权益、免费模型或真实生成成功，不补入官方或公共模型

#### Scenario: 目录确认且模型带上下文后缀
- **WHEN** 当前路由确认 glm-example，而自身配置模型为 glm-example[1M]
- **THEN** 保留该原生配置标识作为选项和 argv，比较目录时按 Claude 原生后缀规则匹配，其他任意后缀不推测

#### Scenario: 目录认证拒绝或查询异常
- **WHEN** 网关返回 401/403、网络失败或无效目录响应
- **THEN** 返回简短失败原因，不开放配置候选、不切换官方账号，取消仍结束请求

#### Scenario: 选型期间切换网关映射
- **WHEN** CC Switch 在选型、排队或续聊时改变当前路由模型映射
- **THEN** 当前选择及绑定重检并失效，需要重新选择或新建任务，不能使用旧映射覆盖新配置

#### Scenario: 本地代理辅助目录成功为空
- **WHEN** 当前自身 loopback Claude 代理返回成功的原始空模型数组，且自身原生 settings 明确配置有效角色模型
- **THEN** 保留确切角色模型 ID 和原生上下文后缀，显示路由配置、远端未核验及费用未知；MODEL_NAME 仅作为标签，不成为执行 ID

#### Scenario: 权限过滤后为空或远端目录成功为空
- **WHEN** 实际目录含拒绝项而筛选后为空，或非 loopback 远端网关成功返回空目录
- **THEN** 不恢复配置候选，不把空目录等同于未实现；认证拒绝、失败和无效响应仍按既有拒绝行为处理

### Requirement: 设置模型目录持久保存与启动刷新
Host SHALL 按机器、平台、项目和 CLI 保存已核验的可选模型及其思考强度，缓存只用于选项展示，不得替代设置页保存选型或任务启动时的原生账号/路由核验；Worker 改选按专门规则允许保存缓存内偏好并延后实际核验。每次宿主启动后首次打开对应设置页 MUST 重新识别目录；本轮后续打开可复用同来源目录。目录相同不得重写缓存，变化时更新；有效的项目默认值保持不变，无效默认值要求重新选择。

#### Scenario: 重复打开与宿主重启
- **WHEN** 同一宿主中再次打开已完成识别的 CLI 设置页
- **THEN** 自动填入已核验的模型及强度列表；宿主重启后首次打开重新识别，并仅在内容变化时更新持久文件

#### Scenario: 账号或路径变化
- **WHEN** 当前账号、路由、CLI 路径改变或用户主动刷新
- **THEN** 旧目录不能继续作为新来源的选项，重新识别失败时显示错误，不回退旧目录掩盖失败

#### Scenario: 已选偏好
- **WHEN** 重新识别得到的列表仍支持已选默认模型及强度
- **THEN** 保留该默认值；失效时显示需要重新选择，目录刷新本身不保存猜测的替代模型或启动任务

#### Scenario: 查询取消与并发
- **WHEN** 多个设置请求同时到达或请求被取消
- **THEN** 同来源查询串行复用，取消结果不得写入缓存；Host 退出时清理正在执行的查询

#### Scenario: 缓存目录或祖先路径是链接
- **WHEN** 设置模型缓存目录、状态根或其非可信祖先路径是符号链接或 Windows junction
- **THEN** 在创建或写入缓存前拒绝，不在链接目标中创建目录或文件，不改变目标内容与权限，不从不安全路径恢复选项

### Requirement: Codex 当前账号模型与客户端版本
Codex 目录查询 SHALL 使用当前已解析 CLI 的原生握手版本，不能把本 CLI 查询固定到旧版本。当前账号远端目录已确认的模型和 reasoning 能力 SHALL 能更新原生 bundled/cache 的陈旧清单；模型 ID 与强度 MUST 取真实元数据，不得按模型名称推测或硬编码补项。额度、认证与账号来源仍须当前核验。

#### Scenario: 原生缓存缺少最新模型
- **WHEN** 当前账号目录确认某模型及 reasoning 能力，但 app-server 模型清单仍使用旧 bundled/cache
- **THEN** 按该账号当前确切 ID 与强度显示选项，不因旧缓存缺项而删除，不补入没有能力元数据的未知模型

#### Scenario: 实际客户端版本
- **WHEN** 原生 initialize 握手报告当前 CLI 版本
- **THEN** 本次远端目录请求使用该版本，不发送旧固定版本或猜测的 latest

#### Scenario: 账号拒绝或额度不足
- **WHEN** 当前账号认证失败、范围未知或额度已耗尽
- **THEN** 不使用原生或旧缓存清单掩盖失败，不显示未经支持确认的选项

#### Scenario: 模型介绍提示不是权限拒绝
- **WHEN** 当前账号模型具有支持证据和真实 reasoning 元数据，并附带介绍性的 availability_nux 提示
- **THEN** 不因介绍提示本身隐藏该模型；明确拒绝、未获支持或隐藏条目仍按当前账号与原生能力规则排除

### Requirement: Worker 使用保存目录延后实际选型
Worker 对话模型菜单 SHALL 优先读取本机、项目、CLI 与 Worker 原账号绑定一致的已保存目录，包含真实模型及强度；重复打开和有效缓存内改选不得调用原生账号或目录查询。缓存选择只保存该 Worker 的偏好，MUST 在消息真正执行前核验当前账号、路由及精确选型；设置页现有启动刷新和账号失效规则继续适用。

#### Scenario: 首轮后快速改选
- **WHEN** 首次派遣已发现并保存模型目录，用户再次打开模型菜单或更换强度
- **THEN** 使用保存目录，保留原生会话 ID，选择操作不触发模型进程或原生目录查询

#### Scenario: 缺失和不匹配
- **WHEN** 没有有效缓存、来源被明确失效或缓存与 Worker 原账号绑定不匹配
- **THEN** 按现有原生查询建立新证据，不能把其他账号或其他项目目录用于该 Worker

#### Scenario: 执行时模型失效
- **WHEN** 用户从保存目录选择后，当前账号、路由、模型或强度在执行时不可用
- **THEN** 明确拒绝并保留未发送内容，不静默回退旧模型、其他账号或新会话

#### Scenario: 模型变化与上下文
- **WHEN** 同一 Worker 更换模型或强度后发送
- **THEN** 仍传入原生会话 ID；若原生能力确有已证实的重建会话要求，必须在执行前明确说明并确认，不凭模型不同推定上下文必然丢失

### Requirement: OMP 订阅目录与原生执行同步
OMP 的 OpenAI 订阅模型 SHALL 根据当前自身账号支持范围和原生能力元数据更新旧目录缺项；模型 ID、容量和推理能力 MUST 有原生来源，不能硬编码新型号或只在菜单增加无法执行的模型。查询和执行使用相同来源，保留已有有效偏好，不改变账号权限或用户原生目录文件。

#### Scenario: 账号目录有新模型
- **WHEN** 当前 OMP 订阅账号确认新模型及完整可执行能力，但旧原生缓存缺项
- **THEN** 目录显示精确模型和支持强度，原生执行器通过同一受管目录可解析该模型；不替用户自动选择。

#### Scenario: 账号池或能力不完整
- **WHEN** 任一可能执行账号未支持模型、查询失败或元数据不足以确认原生执行能力
- **THEN** 不扩大候选，不静默使用另一个账号、旧缓存或猜测参数。

#### Scenario: 取消与原生状态保护
- **WHEN** 用户取消目录刷新或原生元数据失败
- **THEN** 结束本次查询并清理临时状态，不改写用户原生账号、会话和模型缓存；必要的同账号凭据正常轮换遵循既有保存规则，不启动模型生成。

### Requirement: 跨平台设置展示缓存与首次预热
macOS 和 Windows SHALL 使用同一套设置展示缓存。首次打开设置后，Client SHALL 按当前选中项优先、最多两项并发读取所有已启用 CLI 的安全登录摘要、原生模型和思考强度；禁用 CLI 不启动查询。完成的结果 SHALL 按 Gateway、Host 实例、项目和 CLI 隔离保留，关闭后再次打开先用轻量元数据核对来源代际及最新偏好，只查询缺失或已失效项。

#### Scenario: 首次打开与重复打开
- **WHEN** 同一宿主和项目首次完成所有已启用 CLI 的设置预热，用户关闭并重开设置或切换 CLI
- **THEN** 已完成的登录、模型和思考强度直接显示，不重复启动原生账号或目录查询；首次读取不修改偏好、不打开登录终端或发送 prompt。

#### Scenario: 刷新与来源变化
- **WHEN** 用户刷新账号、刷新模型、登录/退出、管理账号、修改路径或 CLI 开关
- **THEN** 仅失效或刷新对应 CLI 的有关展示结果，账号刷新先完成再读取模型；失败清除过时可选数据，不借用另一账号或旧错误前的成功目录。

#### Scenario: 关闭与缺项
- **WHEN** 首次预热尚未完成时关闭设置，或原生查询失败
- **THEN** 取消未完成请求并遵循 Host 清理，保留已经完成的展示结果；重开仅补未完成项，失败结果等待显式刷新，迟到响应不能回填。

#### Scenario: 宿主、项目与偏好变化
- **WHEN** Host 重启、Gateway 身份或项目变化，或项目默认模型/强度在别处修改
- **THEN** 不混用其他范围结果；宿主重启后重新识别，本项目偏好按轻量最新快照呈现，不保存猜测默认值。

#### Scenario: 展示与执行边界
- **WHEN** 缓存仍存在但外部 CLI 账号、认证、模型权益或路由发生变化
- **THEN** 显式刷新可取得最新展示，保存及任务执行仍重新核验当前原生来源和完整选型，展示缓存不能授权调用或恢复退出账号。

#### Scenario: 旧宿主兼容
- **WHEN** Host 未提供可确认的设置缓存代际
- **THEN** 使用既有读取路径，不跨关闭复用无法确认范围的账号或目录。

### Requirement: 非秘密能力信息有界复用
MiMo 原生能力元数据、Kimi 已核验 managed OAuth 模型能力及 Claude 已证明的命令参数能力 SHALL 在有界时效内复用，以避免一次操作重复启动相同能力查询。复用 MUST 绑定项目、原生入口、当前配置及账号来源的变化；缓存仅包含安全能力，不保存原始凭据或账号授权结论，远端权限与额度继续实时核验。

#### Scenario: 重复能力读取
- **WHEN** 同一项目与入口在配置和账号未变时短期重复查询 MiMo 能力
- **THEN** 可复用非秘密原生能力，不重复启动等价本机命令，同时继续核对当前账号可用范围

#### Scenario: 配置或入口改变
- **WHEN** 原生入口、配置、账号、来源环境变化或时效结束
- **THEN** 旧能力结果失效并重新查询，失败不恢复旧目录

### Requirement: OAuth 状态与模型目录证据一致
已确认的自身 OAuth 登录 SHALL 使用该 CLI 原生身份、模型和额度元数据核对目录；原生证据充分时不得仅因缺少 API Key 拒绝，证据不足时 MUST 保留登录状态并说明具体支持边界。

#### Scenario: OAuth 可核验目录
- **WHEN** 原生账号身份与当前账号模型范围、Worker路由均可核验
- **THEN** 展示确切模型和已证明的参数能力，不套用另一 CLI 或公共模型大全

#### Scenario: 原生能力缺口
- **WHEN** 原生协议或账号范围尚无法核验
- **THEN** 显示短而具体的限制，不显示伪造模型，也不注销或更改现有账号

### Requirement: Claude 本地代理与原生登录来源选择
Claude SHALL 在操作开始前使用可达的自身本地代理；代理关闭时使用原生 CLI 登录账号。来源选择 MUST 不改写用户设置，原生状态中的 oauth_token 字样不得单独作为订阅 OAuth 证明。每次任务绑定所选来源与账号，执行中失败不得自动切换来源或账号。

#### Scenario: 自身代理目录
- **WHEN** 自身设置仅包含明确的 Bearer API 凭据及端点，原生状态和能力一致
- **THEN** 以 Authorization Bearer 查询该端点，仅展示其已认证目录中的模型，不附加其他认证头，不凭模型别名配置推定可用性

#### Scenario: 代理关闭
- **WHEN** 自身本地代理在操作前不可达
- **THEN** 临时屏蔽该代理设置并使用原生 CLI 账号，未登录时提供原生 login；不改写已有配置或凭据，界面明确显示当前来源

#### Scenario: 代理拒绝认证或执行失败
- **WHEN** 代理已连接但拒绝凭据，或固定来源的任务在执行中失败
- **THEN** 报告该来源的错误，不把失败当成授权切换，不自动重试另一账号

#### Scenario: 官方目录尚未核验
- **WHEN** 原生登录可识别而可执行模型及额度范围尚无法核验
- **THEN** 保留登录状态并说明具体限制，不伪造目录或执行未核验任务

### Requirement: Windows 原生模型目录与强度可用
插件 SHALL 在 Windows 对已安装且已配置的 Codex、OMP、Pi 按各自原生能力读取模型与支持的思考强度，MUST 保留账号来源及执行前实时核验，不得使用另一 CLI 的目录或猜测强度。

#### Scenario: Windows 原生安装可用
- **WHEN** Windows 上所选 CLI 入口、账号及原生目录可用
- **THEN** 设置展示该 CLI 返回且当前账号允许的模型/强度，跨平台目录准备不会提前阻断查询

#### Scenario: 状态加载与权限变化
- **WHEN** 设置查询重复、被取消或账号/配置发生变化
- **THEN** 仅安全能力元数据可复用；错误和取消不写有效缓存，显示与执行继续校验当前账号，不以旧成功结果放行

### Requirement: 设置查询减少重复进程并优先当前 CLI
设置加载 SHALL 优先当前选择的 CLI，并将账号状态请求（包含当前项）的并发数限制为两个；切换仅调整待排顺序，不抢占正在执行的请求。相同 CLI/项目的可兼容账号查询 SHOULD 复用在途工作。最后一个订阅者取消后，Host MUST 等待并核验所属进程范围退出，清理失败保留失败状态；客户端 RPC 取消返回不得作为进程退出确认。模型目录查询独立进行，账号请求上限不得描述为全部子进程数量上限。性能优化 MUST 以实际冷/热耗时和进程证据核验。

#### Scenario: 首次打开与快速切换
- **WHEN** 用户首次打开设置或切换所选 CLI
- **THEN** 首次优先当前项，切换后的待排项在现有状态请求释放名额后优先开始，取消/禁用后的结果不得更新当前状态

#### Scenario: Codex 额度耗尽
- **WHEN** 原生模型能力可读且当前账号额度接口明确返回额度耗尽
- **THEN** 显示额度耗尽原因而非笼统目录错误，保持空可选目录和现有账号；认证拒绝及未知网络错误不得误标为额度耗尽

#### Scenario: 一次目录查询中的重复身份读取
- **WHEN** Windows Antigravity 同一次目录查询的前置账号绑定与原生目录前置检查需要相同身份
- **THEN** 可复用该次请求内的非秘密身份投影，最终账号绑定仍重新读取原生来源；失败、取消及请求结束后不得复用，其他请求与平台不受影响

### Requirement: 成功模型查询回收独有目录
扩展 CLI 模型查询成功且所属进程范围确认退出后，插件 SHALL 删除本次独有查询目录及原生解压缓存；失败、取消或清理未确认时 MUST 保留该目录，不触碰原生账号、共享续期目录及其他在途查询。

#### Scenario: 查询完成后删除原生缓存
- **WHEN** Pi、OMP 或其他扩展 CLI 已返回可用模型值，且该查询捕获的进程范围均确认退出
- **THEN** 模型值仍可返回，本次 query 目录被删除，原生账号文件及其他查询不变

#### Scenario: 尚未确认查询退出
- **WHEN** 模型捕获失败、取消或报告进程清理未确认
- **THEN** 不删除该查询目录，保留正在使用的路径及原生账号文件

### Requirement: Codex 自定义路由模型目录
Codex 使用自身自定义路由时，Host SHALL 直接采用 Codex 原生 `model/list` 返回的模型 ID 与强度作为候选，与 Codex `/model` 一致，费用 SHALL 标为未知；MUST 不向 OpenAI 官方或中转站查询账号范围，也不补入配置或推测的模型。该规则是「按账号与执行路由筛选」中自定义配置需账号证据的例外，与 Claude 自身网关的专门规则并列。查询前后路线版本不同 MUST 报错要求刷新，不返回混合结果。中转站不支持所选模型时，由 Codex 执行时的原生错误说明。

#### Scenario: 中转路线读取模型
- **WHEN** Codex 配置自定义中转且原生 `model/list` 返回模型
- **THEN** 设置与派遣选型显示这些模型及其原生强度，费用未知，不访问官方账号接口

#### Scenario: 原生目录含新模型推广提示
- **WHEN** 原生 `model/list` 中某模型未隐藏且有思考强度，但带有 `availabilityNux` 推广文案
- **THEN** 该模型照常显示为候选；只有 `hidden: true` 或缺少强度元数据的条目被排除

#### Scenario: 查询期间切换路线
- **WHEN** 读取模型目录期间 Codex 路由配置、密钥或 `auth.json` 发生变化
- **THEN** 本次查询失败并提示刷新，不保存这次目录

#### Scenario: 原生目录查询失败
- **WHEN** Codex `model/list` 失败、超时或格式无效
- **THEN** 返回原有的查询失败原因，不以其他 CLI 或官方目录代替

### Requirement: MiMo 本地模型缓存过期时用原生命令刷新
插件读取 MiMo 模型时 SHALL 继续禁止 MiMo 自行联网更新模型列表。当前账号模型目录可读、但其中没有任何 MiMo 本地模型列表里的候选时，插件 SHALL 调用一次 MiMo 自带的 `models --refresh`（同一可执行文件 10 分钟内最多一次，使用与其他元数据命令相同的隔离环境），清空插件的 MiMo 元数据缓存后重新读取；模型与思考强度 MUST 仍只取刷新后 MiMo 原生列表与账号目录的交集。账号目录不可读、被拒绝或已有交集时 MUST NOT 刷新。刷新失败或刷新后仍无交集时 SHALL 提示本地模型列表与账号不一致，MUST NOT 按账号目录或模型名猜测强度。

#### Scenario: 本机缓存早于账号可用模型
- **WHEN** MiMo 本地列表只有 `mimo-v2.5` 系列，账号目录只返回 `mimo-v2.6` 系列
- **THEN** 插件运行一次 `mimo models --refresh` 后重新读取，列出 v2.6 模型及 MiMo 原生给出的强度档位

#### Scenario: 账号目录不可读
- **WHEN** 账号模型目录返回 401 或无法连接
- **THEN** 插件不刷新 MiMo 缓存，按原有规则报告暂无可确认模型

#### Scenario: 刷新失败
- **WHEN** `models --refresh` 失败，或刷新后仍无交集
- **THEN** 提示「MiMo 本地模型列表与当前账号可用模型不一致」，10 分钟内不再重复刷新

### Requirement: Grok 访问凭据过期时的原生续期
查询 Grok 自身账号模型目录前，若当前官方 OIDC 账号的 access 已过期或剩余不足续期阈值，而原生记录中仍有 refresh 凭据，Host SHALL 在受控进程中运行当前安装的 Grok 本体，由 Grok 用自身机制续期并写回用户自己的原生凭据文件。之后 Host SHALL 重新读取原生来源，确认账号槽位、用户与客户端身份不变且 access 有效，才继续查询目录。设置刷新与派遣前的目录查询 MUST 共用这条路径。

插件 MUST NOT 自行发送 OAuth 刷新请求，不得读出、复制或记录 refresh 凭据，不得改写原生凭据文件，也不得发起模型生成。同一原生账号的续期 SHALL 合并为一次在途操作，并与该 CLI 的账号终端操作互斥。续期进程 SHALL 有固定时限与进程范围清理；调用方取消只结束自己的等待，MUST NOT 在 Grok 写回新凭据之前中途终止续期。无法确认清理时，按现有元数据保护规则只封锁 Grok。续期失败时 SHALL 给出与原因对应的简短提示；仅当 access 仍然有效时才可继续用它查询目录。

#### Scenario: 过期 access 自动续期后列出模型
- **WHEN** 用户刷新 Grok 模型或派遣 Grok，当前 access 已过期，原生记录含 refresh 凭据
- **THEN** Host 运行 Grok 本体完成原生续期，确认同一账号的 access 有效后再查询官方目录，并显示模型与强度交集；整个过程不发起模型生成，也不输出凭据

#### Scenario: access 仍然有效
- **WHEN** 当前 access 剩余时间超过续期阈值
- **THEN** 不启动续期进程，直接按现有规则查询目录

#### Scenario: Grok 要求重新登录
- **WHEN** 续期进程结束后原生凭据仍然过期，或 Grok 明确表示需要手动登录
- **THEN** 目录查询停止，提示用户在「账号终端」重新登录；不重试生成，也不删除或改写原生凭据

#### Scenario: 续期期间账号变化
- **WHEN** 续期完成后原生记录的账号槽位、用户或客户端身份与续期前不一致，或凭据被移除
- **THEN** 丢弃本次结果，提示账号已变化并要求刷新，不把新账号用于原有选型或任务

#### Scenario: 账号终端正在运行
- **WHEN** 需要续期时，Grok 账号终端的登录或登出流程尚未退出
- **THEN** 不启动续期进程，提示账号终端正在运行，关闭后再刷新

#### Scenario: 并发刷新与派遣
- **WHEN** 多个设置刷新或派遣同时发现同一 Grok 账号需要续期
- **THEN** 只运行一个续期进程，各调用共享结果；取消的调用立即结束等待，其他调用继续等待同一结果

#### Scenario: 续期被取消或超时
- **WHEN** 用户关闭设置或停止派遣，或续期超过固定时限
- **THEN** 取消只结束该调用的等待，续期在时限内完成写回；超过时限才终止续期进程，并在确认进程范围退出后报告。无法确认退出时只封锁 Grok 的后续查询、账号变更和任务准入

#### Scenario: 即将过期但续期暂时失败
- **WHEN** access 剩余不足续期阈值但仍然有效，续期因网络或服务原因失败
- **THEN** 本次仍用该 access 查询目录；账号已变化或 Grok 要求重新登录时不得继续

#### Scenario: 网络或服务暂不可用
- **WHEN** 续期进程因网络、代理或服务错误失败，原生记录仍保留 refresh 凭据
- **THEN** 提示续期暂时失败、请检查网络后刷新，不显示为需要重新登录，也不显示为账号没有模型权限

#### Scenario: 当前 Grok 版本无法续期
- **WHEN** 已安装的 Grok 版本缺少经过验证的续期入口，或其行为与已核实的协议不符
- **THEN** 不尝试其他非原生方式续期，提示更新 Grok 或在账号终端重新登录
