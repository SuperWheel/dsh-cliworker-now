# cli-account-isolation Specification

## Purpose

约束全部 CLI 只读取并使用自身登录或独立 API 配置，在模型发现、选择、排队与续聊中保持同一账号来源，阻止跨 CLI 凭据回退和旧快照复活。

## Requirements

### Requirement: 自身账号来源
Host SHALL 仅识别各 CLI 自身原生账号目录、插件内该 CLI 登录目录、自己配置的 API Key 和私有环境文件。Host 凭据引用、继承的通用密钥及其他 CLI 账号 MUST 不成为本 CLI 登录证据或由插件注入执行。原生登录同一服务商属于本 CLI 自身来源，不按服务商名称误判跨 CLI；插件不额外提供操作系统级文件禁读隔离。

#### Scenario: 只有其他账号
- **WHEN** 仅 Harness 或其他 CLI 有账号
- **THEN** 本 CLI 无可用模型，任何入口均不能启动模型任务

#### Scenario: 自身 API 配置
- **WHEN** 用户在该 CLI 自身配置中设置 API Key 或私有环境引用
- **THEN** 只允许当前账号确认支持且 CLI 能执行的模型；Claude 自身显式网关配置按其专门目录规则处理。通用环境及其他 CLI 文件引用无效

#### Scenario: Claude 自身配置与继承路由环境
- **WHEN** CC Switch 在 Claude 自身 settings 中写入路由，同时宿主继承了旧的凭据或模型变量
- **THEN** 当前自身 settings 决定查询及执行来源；继承变量被该进程覆盖，不单独作为账号证据，不影响其他 CLI 或改写原生配置

### Requirement: 账号绑定和执行重检
Host SHALL 以不含秘密的账号来源版本绑定目录与任务，在保存选型、启动、出队及续聊时重新检查。适用于全部 CLI：任何轮次（新派遣的首轮、已有任务的后续轮次）遇到换号时，Host SHALL 以当前登录的自身账号重新授权用户已选的模型与强度，可用即按「换号后自动续接」绑定当前账号继续，MUST 不向用户显示换号说明。当前没有可用的自身账号，或所选模型、强度在当前账号下不可用时，MUST 阻止任务，不能静默换模型或 CLI，也 MUST 不恢复旧账号凭据。同账号续期 SHALL 以当前原生来源仍存在且身份一致为前提。

#### Scenario: 选型与排队期间换号
- **WHEN** 用户回答新任务的选型期间或新任务首轮排队期间换号或切换来源
- **THEN** 以当前账号重新授权用户的选择；可用则静默继续并绑定当前账号，不可用时按模型不可用处理；退出后无账号时提示登录

#### Scenario: 续聊与旧快照
- **WHEN** 原账号已经退出或换号，当前 CLI 已登录另一自身账号，且原模型与强度在当前账号下可用
- **THEN** 按「换号后自动续接」在当前账号下继续，不恢复旧账号或覆盖当前来源，不要求新建任务

#### Scenario: 已退出且无当前账号
- **WHEN** 续聊时该 CLI 没有已登录的自身账号
- **THEN** 拒绝启动并提示登录，历史可查看，不使用旧 Worker 中残留的凭据

#### Scenario: 退出后重新登录原账号
- **WHEN** 已有任务的 CLI 原账号退出期间续聊被拒，之后再登录原账号并续聊
- **THEN** 退出期间不启动进程、保留原会话与绑定；重登后以原生续接继续同一会话，不追加改绑说明

#### Scenario: 历史任务没有账号绑定
- **WHEN** 升级前的历史任务没有可核验的原账号绑定
- **THEN** 视同换号，按「换号后自动续接」绑定当前账号续接；当前无可用账号时拒绝并提示登录

#### Scenario: 权限与强度撤销
- **WHEN** 账号未变或已改绑，但所选模型或强度在当前账号下不再可用
- **THEN** 启动前拒绝，不发送 prompt，不选择替代项，提示重新选择模型；提示只说明模型或强度不可用，不提换号

#### Scenario: 同一次启动内来源竞态
- **WHEN** 一次启动的准备阶段与实际启动之间账号来源发生 A→B→A 或其他变化
- **THEN** 按准备快照核对，不以旧准备启动；尚未启动 CLI 时静默按当前账号重新授权一次，再次变化才拒绝本次启动

#### Scenario: 模型目录读取期间换号
- **WHEN** 选型卡、任务模型菜单或设置页读取模型目录期间账号变化
- **THEN** 静默改读当前账号的目录一次，不显示换号错误；读取期间再次变化才报告失败

#### Scenario: 已保存设定遇到换号
- **WHEN** 项目或对话已保存完整设定（含关闭“调用前询问模型”后的直接派遣），之后换号
- **THEN** 当前账号目录仍提供该模型与强度时，设定继续有效、不弹出问题卡，启动时以当前账号实时授权；不提供时回退完整选型

#### Scenario: 原生续期无法保护当前账号
- **WHEN** OpenCode OAuth 等原生续期缺少版本条件写回，无法阻止退出或换号后恢复旧凭据
- **THEN** 保留真实登录状态，该模式返回空目录并拒绝执行；同一 CLI 自身 API 配置仍可按当前账号范围开放

### Requirement: 安全迁移及生命周期
升级 SHALL 停用旧 Host 路由和派生认证快照，只清理可确定由插件生成的配置；原生账号、插件登录账号、会话和偏好 MUST 保留。凭据不得返回客户端或入日志，清理未确认退出的进程前不能删除快照或放行后续任务。

#### Scenario: 旧配置升级
- **WHEN** 旧部署保留 Host 引用、自动生成 provider 或凭据快照
- **THEN** 引用不生效，派生状态按本 CLI 当前账号重建，旧偏好不静默转换

#### Scenario: 清理失败
- **WHEN** 元数据或模型进程范围退出无法确认
- **THEN** 保留相关私有状态并阻止后续任务，不报告停止成功

### Requirement: 登录与执行来源贯通
在插件内为 Hermes 建立的原生登录目录 SHALL 成为 Hermes 独立的自身来源，账号状态、模型发现及执行 MUST 使用一致的来源选择。显式切换至插件 Hermes 账号上下文后，退出不得自动回退到全局旧账号；原生全局数据保留。

#### Scenario: 独立 Hermes 登录
- **WHEN** 用户通过插件 Hermes 原生菜单建立自身账号
- **THEN** 账号状态、目录和新任务均识别该目录；只有该 CLI 真实原生登录流程或自身 API 配置被允许，其他工具导入来源仍被拒绝

#### Scenario: 插件 Hermes 账号退出
- **WHEN** 插件 Hermes 自身登录目录的账号被退出或更换
- **THEN** 状态和模型同步失效或重新核对；旧任务不能用全局账号或旧快照继续执行

#### Scenario: 全局账号保持
- **WHEN** 插件准备和关闭独立 Hermes 账号菜单
- **THEN** 不复制外部账号、不删除原生账号、不覆盖原生配置和历史；只保留该插件登录来源及必要的私有状态

### Requirement: Hermes Nous 账号绑定
Hermes Nous 的登录摘要、模型发现与执行 SHALL 使用相同的自身来源和原生认证路由。账号版本 MUST 绑定原生运行时实际使用的认证，保存、出队、启动与续聊继续执行现有重检；静态配置或过期快照不得恢复退出的账号。

#### Scenario: 当前原生运行认证
- **WHEN** 原生 Nous 账号包含网页登录令牌和运行时认证字段
- **THEN** 模型查询与绑定核对原生实际用于推理的字段、当前身份和路由，不仅检查任意非空令牌

#### Scenario: 账号改变或注销
- **WHEN** 查询过程中或已选模型后，当前自身账号退出、换号或不可用
- **THEN** 旧模型结果和选型失效，不回退全局账号、不从旧 Worker 恢复认证

### Requirement: Claude 官方账号操作独立于网关
Claude 官方登录和退出 SHALL 使用当前原生账号目录与官方认证端点，独立于当前自身网关可达性及其 API 凭据。macOS 与 Windows MUST 保留 CC Switch 路由、原生账号和会话，且拒绝无法安全隔离的账号目录重定向或强制托管覆盖。

#### Scenario: 路由关闭或旧环境仍存在
- **WHEN** 用户关闭 CC Switch 路由后从插件登录官方 Claude 账号
- **THEN** 原生官方登录流程可启动，旧的路由环境不会阻塞或把登录指向代理

#### Scenario: 登录时路由仍在运行
- **WHEN** 用户在自身 API 路由配置存在时启动官方登录或退出
- **THEN** 操作仅作用于官方账号存储，路由 settings 不变；路由开启时新任务仍使用自身选定路由

#### Scenario: 无法覆盖的托管来源
- **WHEN** 原生托管配置强制认证或账号目录来源，无法安全选择官方账号
- **THEN** 返回明确的来源错误，不启动登录或使用其他账号

### Requirement: 跨平台原生账号文件读取
Host SHALL 在 macOS 与 Windows 读取 OpenCode、Hermes、Pi 原生账号及私有元数据文件前后检查路径与已打开文件的身份，拒绝符号链接、非普通文件、多硬链接及读取期间的路径替换。平台不支持 `O_NOFOLLOW` 时 MUST 保留相同的拒绝行为；来源错误不得暴露账号内容。POSIX 私有 mode 与 Windows ACL SHALL 按平台能力分别解释，不以 Windows `stat.mode` 宣称私有 ACL 已验证。

#### Scenario: 原生账号文件是符号链接
- **WHEN** 上述 CLI 的账号或私有元数据文件路径指向符号链接，即使当前平台没有 `O_NOFOLLOW`
- **THEN** 账号状态不可用，不读取并使用链接目标中的凭据，不将目标账号视为已登录

#### Scenario: 打开或读取期间文件被替换
- **WHEN** 账号路径在初次检查后、打开或读取期间改为另一个文件或符号链接
- **THEN** 来源检查失败，不返回替换文件中的账号，不暴露其秘密

#### Scenario: 原生普通文件保持稳定
- **WHEN** 账号文件及其路径在检查、打开和读取期间保持同一普通文件身份
- **THEN** 按当前原生账号解析状态，不更改原生内容、目录或账号

### Requirement: 独占账号按账号排队
Pi/OMP 的 OAuth 账号由来源绑定的共享存储与 Host 租约独占时，任务 MUST NOT 因账号被另一任务或目录读取占用而失败。本轮进程启动前遇到占用的任务 SHALL 退回原队列位置且不占并发名额，在本 Host 中持有同一账号的任务结束后或定时重试时再次完整授权；停止排队任务 MUST 立即结束且不再尝试。派遣检查遇到占用时 SHALL 只使用同一账号最近一次已验证的目录完成选型与入队，没有时等待短暂的目录读取；账号变化 MUST 失败关闭，其他错误 MUST 照常报告。插件 MUST NOT 让同一 OAuth 账号同时运行多个进程。

#### Scenario: 并行派遣同一 OMP 账号
- **WHEN** 主 Agent 同时派遣多个使用同一 OAuth 账号的 OMP 任务
- **THEN** 所有派遣成功入队，任务逐个运行，等待中的任务显示排队，不出现「账号正被使用」失败

#### Scenario: 账号被占用时让出名额
- **WHEN** 一个 OMP 任务因账号被占用而等待
- **THEN** 其他 CLI 的任务可以使用空出的并发名额运行

#### Scenario: 等待中停止
- **WHEN** 用户停止正在等待账号的任务
- **THEN** 任务以用户停止结束，之后不再尝试授权或启动

#### Scenario: 等待期间换号
- **WHEN** 派遣检查或排队重试时账号已变为其他账号
- **THEN** 不使用旧账号的目录，按账号已变更失败

### Requirement: macOS Antigravity 账号读取系统钥匙串
在 macOS 上，Host SHALL 以系统钥匙串中 service `gemini`、account `antigravity` 的条目作为 Antigravity 登录状态与账号绑定的唯一来源，通过参数数组调用 `/usr/bin/security` 读取并在 Host 进程内解码；凭据、令牌与条目原文 MUST NOT 写入日志、事件、持久化文件或界面。条目不存在时 MUST 视为未登录，MUST NOT 回退到 `~/.gemini/jetski-standalone-oauth-token`；读取失败时 MUST 报告无法读取，不判为已登录或未登录。绑定主体 SHALL 与原文件来源的计算方式一致，同一账号的绑定版本不因来源切换而改变。

#### Scenario: 原生退出后
- **WHEN** 用户在 Antigravity 中 `/logout`，钥匙串条目已删除而遗留文件仍在
- **THEN** 设置页显示未登录；续聊拒绝启动并提示登录，原会话与绑定保留

#### Scenario: 重新登录原账号
- **WHEN** 用户重新登录同一 Antigravity 账号，钥匙串条目重新写入
- **THEN** 设置页显示已登录及邮箱；已有任务以原绑定原生续接，不追加改绑说明

#### Scenario: 在 agy 中换到另一账号
- **WHEN** 钥匙串条目对应另一账号，遗留文件仍属原账号
- **THEN** 绑定按钥匙串中的账号计算，与原账号不同，按换号处理

#### Scenario: 钥匙串不可读
- **WHEN** `/usr/bin/security` 以非「条目不存在」的状态失败、超时或输出无法解析
- **THEN** 显示无法读取 macOS 钥匙串中的 Antigravity 账号，拒绝绑定，不启动任务

### Requirement: 元数据优化不复活账号
能力元数据缓存 SHALL 不保存或复活可执行认证；每次授权与任务边界 MUST 从当前原生自身来源重读账号和配置，换号、退出、撤销以及路由变化立即使旧绑定不可用。

#### Scenario: 缓存命中但账号退出
- **WHEN** MiMo 能力缓存仍有效而当前自身账号已删除或更换
- **THEN** 拒绝旧任务或要求重新选择，不从能力缓存恢复凭据，不跳过绑定与权限重检

#### Scenario: 并发取消与失败
- **WHEN** 重复查询中某一调用取消或能力查询失败
- **THEN** 取消自身等待和受管资源，失败不发布半成品目录，不影响其他请求的账号核对

### Requirement: Antigravity Windows 原生账号来源
Windows 上 Antigravity 账号核对 SHALL 使用交互式用户会话中原生 Credential Manager 的固定凭据目标，且只向插件返回状态、稳定主体摘要和安全账号标签。凭据正文 MUST 不进入 Gateway、日志或持久化缓存。

#### Scenario: 浏览器授权与终端兑换均已完成
- **WHEN** 用户在 Windows 原生终端完成 OAuth 兑换，账号保存在 Credential Manager 而无明文令牌文件
- **THEN** Desktop 能识别同一账号并绑定目录与任务；SSH 会话无法访问凭据时报告来源不可用，不误报桌面账号退出

#### Scenario: 原生凭据不可读或格式未知
- **WHEN** 原生账号存储不可访问、格式未知或当前主体已改变
- **THEN** 返回安全诊断并拒绝旧绑定，不输出凭据，不从其他账号来源补齐

### Requirement: Hermes 同源 OAuth 自动续期
macOS 与 Windows SHALL 共用 Hermes Nous 续期逻辑。有效短期访问令牌不触发刷新；同一明确账号的访问令牌临近过期或已过期且有原生刷新凭据时，插件 SHALL 在账号、目录及任务准入检查中允许一次有界非交互原生续期，随后重读原生状态。刷新 MUST 保持账号来源、主体、组织、客户端及路由，且不得登录另一账号、创建匿名身份、打开浏览器或调用模型。

#### Scenario: 短期令牌到期而登录仍可续期
- **WHEN** 自身 Nous 访问令牌已到期或低于原生可用 TTL，原生刷新凭据存在且来源及主体可确认
- **THEN** 在原生锁内刷新并立即保存轮换凭据，再核对同一主体，账号与模型检查可继续；令牌轮换不使原有同主体绑定失效

#### Scenario: 健康令牌与并发检查
- **WHEN** 令牌仍有足够有效期，或多个同账号状态/目录/派遣检查同时到达
- **THEN** 健康令牌仅做本地读取；需要续期时同目录不并发轮换，取消和账号操作等待进程范围清理，不在退出账号后写回旧登录

#### Scenario: 原生共享状态与凭据池
- **WHEN** 刷新涉及原生共享状态或既有同源凭据池行
- **THEN** 只接受同主体同路由的可核验原生状态并按原生锁序保持轮换一致；不同主体、来源不明、已删除账号或不支持契约明确拒绝，不导入外部凭据，不清除禁用、额度、冷却或用户元数据

#### Scenario: 临时失败与必须重登
- **WHEN** 原生续期遇到网络/超时/临时服务故障，或明确返回终止鉴权错误/缺失刷新凭据
- **THEN** 前者显示暂时无法续期并可重试，后者才要求重新登录；保留现有凭据，不泄露令牌、原始授权响应或 URL

### Requirement: Hermes 原生环境记录不阻断自身账号
Hermes 原生在 `gh` 已登录时会把无令牌的环境 Copilot 记录（`copilot`/`gh_cli`/`api_key`）写入插件自身账号目录。Host SHALL 在该记录未被 `auth.active_provider` 或 `config.yaml` 任何位置选择时，不把它视为外部账号来源，自身账号的登录终端、状态、续期与执行照常进行。Copilot 一旦被选择，该记录 MUST 仍按外部账号拒绝。守卫拒绝 MUST 以固定原因显示在账号终端、状态与续期结果中，MUST NOT 被改写为安装错误或“稍后刷新”。

#### Scenario: 原生选择器写入环境 Copilot 记录
- **WHEN** 插件 Hermes 账号目录的凭据池含未被选择的 `gh_cli` Copilot 记录，且 Nous 自身登录已过期但可续期
- **THEN** 账号终端可以打开，状态查询正常续期并显示已登录，不读取或复制 `gh` 凭据

#### Scenario: 已选择 Copilot
- **WHEN** 插件 Hermes 配置在 model、auxiliary、MoA 或 fallback 中选择了 Copilot，凭据池含 `gh_cli` 记录
- **THEN** 账号终端、状态与续期均拒绝，并显示「Hermes 含外部账号来源，请使用自身登录」，不启动原生续期

### Requirement: 换号后自动续接
全部 CLI 的已有任务续聊、排队续聊、分支及子对话换模型遇到账号绑定变化时，Host SHALL 在当前 CLI 已登录自身账号、且原模型与强度经当前账号目录授权后，自动把任务改绑到当前账号并继续，MUST 不弹出确认。改绑 MUST 静默完成：时间线、过程区和错误中都 MUST 不出现换号或改绑说明，也不含凭据或账号标识。读取旧版本写入的记录时，其中的换号说明 SHALL 不再显示，旧的改接说明 SHALL 改用不提账号的文案。运行中的进程 MUST 不因换号被改绑；换号后发送的运行中引导消息 SHALL 转为排队，在下一轮于当前账号下发送。

#### Scenario: 换到另一账号后续聊
- **WHEN** 任务原绑定账号 A，用户已在该 CLI 改登账号 B，B 下原模型与强度可用，用户发送续聊
- **THEN** 不提示用户，任务改绑 B 并续接；时间线不出现换号说明

#### Scenario: 读取旧版本记录
- **WHEN** 任务记录中有旧版本写入的「账号已变更，已改用当前账号继续」或提及当前账号的改接说明
- **THEN** 时间线不显示前者，后者改为「原会话无法续接，已在新会话中继续」等不提账号的文案，附带记录条数保留

#### Scenario: 同一账号凭据格式变化
- **WHEN** 同一账号的原生凭据改写为新格式，导致绑定版本变化
- **THEN** 与换号同样自动改绑续接，不提示用户

#### Scenario: 排队中的续聊遇到换号
- **WHEN** 续聊排队期间用户换号
- **THEN** 出队时按当前账号重新授权后改绑执行，不因原绑定失效而丢弃排队消息

#### Scenario: 运行中换号并发送引导
- **WHEN** 本轮进程仍在运行，用户换号后发送引导消息
- **THEN** 该消息转为排队，本轮进程不受影响；下一轮在当前账号下发送

#### Scenario: 新账号下原模型不可用
- **WHEN** 换号后原模型或强度不在当前账号的授权目录中
- **THEN** 不改绑、不发送 prompt，按现有选型提示要求重新选择模型

### Requirement: 原生续接失败时自动改接
改绑后，Host SHALL 按 CLI 的跨账号续接方式表决定先尝试原生续接或直接改接；已确认无法续接或本地预检确认原生会话不在当前账号的会话存储中时 SHALL 直接改接，MUST 不先发起注定失败的原生续接。原生续接在产生任何回复或工具事件前失败时，Host SHALL 在当前账号下为同一任务建立新的原生会话，以插件保存的此前公开记录作为有界上下文先行发送，再发送本次消息；上下文 MUST 标明来自插件历史且不是新指令，MUST 不额外调用模型生成摘要。已产生回复、工具事件或成功的最终结果后，或本轮已向原生进程提交引导后的失败 MUST 照常报告，不改接；用户停止时 MUST 不改接。

#### Scenario: 原生续接被拒
- **WHEN** 改绑后原生续接返回错误，且尚未产生回复或工具事件
- **THEN** 自动在当前账号建立新会话，附带此前记录并发送本次消息；任务保持为同一个，时间线以「原会话无法续接，已在新会话中继续」说明已改接及附带的记录条数，不提账号

#### Scenario: 换号后分支首轮被拒
- **WHEN** 分支子任务的原生分支在首轮才创建（如 Claude 延迟分支），改绑后这一轮在产生回复或工具事件前失败
- **THEN** 按原生续接被拒同样改接一次，新会话附带分支截点前的记录；改接也未建立新会话时恢复待分支状态

#### Scenario: 已知无法续接
- **WHEN** 跨账号续接方式表标记该 CLI 无法跨账号续接，或预检发现原生会话不在当前账号的会话存储中
- **THEN** 不尝试原生续接，直接改接

#### Scenario: 已开始执行后失败
- **WHEN** 原生续接已产生回复或工具事件后失败
- **THEN** 报告本轮失败，不自动改接或重试，避免重复执行写操作

#### Scenario: 用户停止
- **WHEN** 用户在原生续接过程中停止任务
- **THEN** 等待进程范围清理确认后报告停止，不改接

#### Scenario: 历史超出上下文预算
- **WHEN** 插件保存的此前记录超过改接上下文预算
- **THEN** 保留首轮用户需求和最近的完整轮次，省略部分明确标注被省略的条数；单条记录超过上限时标注已截断

#### Scenario: 引导已提交
- **WHEN** 改绑后的续接轮次已向原生进程提交引导消息，之后在产生回复前失败
- **THEN** 报告本轮失败，不改接，避免新会话缺少已被接收的引导

### Requirement: 改接后的会话状态
改接后任务的 Token 用量 SHALL 累计此前各会话的会话级用量与新会话用量，任一方未报告的分项 MUST 保持未知而不按零计入；上下文占用 SHALL 只显示新会话自身的数值。改接也未建立新会话时，任务 SHALL 保留原会话、原有用量及待确认的改绑状态，下一轮仍可改接。改接成功后，从改接之前的消息创建原生分支 MUST 明确拒绝，不得把旧会话的截点套到新会话。

#### Scenario: 改接后的用量统计
- **WHEN** 任务改接到新会话后，新会话报告了会话级 Token 用量
- **THEN** 任务显示的 Token 用量为此前各会话与新会话之和；上下文占用为新会话自身的数值；改接未建立新会话时恢复原会话及其原有用量，不重复计入

#### Scenario: 改接失败后重试
- **WHEN** 改绑后原生续接与改接都在建立新会话前失败，用户随后再次发送
- **THEN** 仍先尝试原生续接，失败后再次改接；不会因绑定已更新而直接报告失败

#### Scenario: 从改接前的消息分支
- **WHEN** 任务已改接到新会话，用户从改接之前的消息创建分支
- **THEN** 明确拒绝并提示从改接之后的消息分支

### Requirement: Antigravity 仅含邮箱的原生凭据
Antigravity 原生凭据（Windows 凭据管理器 `gemini:antigravity` 或 `~/.gemini/jetski-standalone-oauth-token`）不含可用 `id_token` 主体但含 `id_token_email` 时，Host SHALL 在本地登录有效的前提下以该邮箱（经安全邮箱校验、小写）作为账号标签与绑定主体。存在可用 `id_token` 主体时 MUST 继续以其为准。邮箱缺失或不安全时 MUST 拒绝绑定，且凭据 blob、令牌 MUST NOT 越过帮助进程或进入投影。

#### Scenario: agy 1.4.x 新凭据格式
- **WHEN** 已登录的 Antigravity 凭据只有 `token` 与 `id_token_email`
- **THEN** 账号显示该邮箱，绑定成功，模型目录与派遣可用

#### Scenario: 同一邮箱续期与大小写
- **WHEN** 原生续期改写了访问或刷新令牌，或邮箱仅大小写不同
- **THEN** 绑定版本不变

#### Scenario: 换号
- **WHEN** `id_token_email` 改为另一邮箱，或凭据由仅邮箱格式变为含 `id_token` 主体
- **THEN** 绑定版本改变，原选型与续聊按账号改变处理

#### Scenario: 邮箱缺失、不安全或未登录
- **WHEN** 既无 `id_token` 主体也无安全邮箱，或本地登录已过期
- **THEN** 拒绝绑定并提示无法确认当前自身账号，不启动任务

### Requirement: Codex 自身自定义路由
Codex 自身配置（`CODEX_HOME/config.toml` 及项目各级 `.codex/config.toml`）启用自定义 provider、自定义地址或 profile 时，Host SHALL 把这条路线视为 Codex 的自身来源，不再因无法识别账号而拒绝。账号来源版本 SHALL 由该路线的配置文件内容、路由环境变量及配置 `env_key` 所指环境变量的值、`auth.json` 内容的 SHA-256 摘要组成，MUST 不保存、不返回或记录其原文。任一项变化 SHALL 视为换号，按「换号后自动续接」处理。插件 MUST 不解析或改写中转地址，派遣参数不追加 provider 覆盖，执行仍由 Codex 读取用户自身配置；启动 Codex 时 SHALL 只额外传入自身配置 `env_key` 所指、且宿主进程中存在的变量，不传其他继承凭据。

#### Scenario: 中转配置派遣
- **WHEN** Codex 配置 `model_provider` 指向自定义中转，且命令行直接运行 Codex 可正常使用
- **THEN** 插件派遣不再报「无法确认当前自身账号」，按 Codex 自身配置执行

#### Scenario: 中转密钥或配置变化
- **WHEN** 用户修改中转配置文件、`env_key` 所指环境变量或 `auth.json`
- **THEN** 账号来源版本改变，已有任务按换号后自动续接处理，不复用旧版本

#### Scenario: env_key 指定的密钥变量
- **WHEN** 中转配置以 `env_key` 指定密钥变量，且宿主进程中存在该变量
- **THEN** 派遣、续聊与分支启动的 Codex 进程获得该变量，其他未指定的继承凭据不传入

#### Scenario: 只有继承的路由环境变量
- **WHEN** Codex 自身配置未声明路由，只有宿主继承的 `OPENAI_API_KEY`、`OPENAI_BASE_URL` 等变量
- **THEN** 仍按继承凭据拒绝，不把它们当作 Codex 自身中转路线

#### Scenario: 官方账号路径不变
- **WHEN** Codex 未配置任何自定义路由
- **THEN** 仍只接受官方 API Key 或 ChatGPT 登录，绑定与原有实现相同

#### Scenario: 配置读取不安全或格式无效
- **WHEN** 适用的配置文件或 `auth.json` 为符号链接、多重硬链接、读取中被改动，或 `auth.json` 不是 JSON 对象
- **THEN** 仍报无法确认账号，不以部分内容生成来源版本

### Requirement: OpenCode 与 MiMo 不读入未核验配置及其他 CLI 数据
OpenCode 的模型发现、Worker 与插件内登录 SHALL 只合并插件私有配置目录、插件写入的配置和插件已核验的账号档案；用户主目录下的 `.opencode` 配置目录 MUST 不参与配置合并、命令/agent 加载或依赖安装。MiMo 的模型发现、Worker 与插件内登录 MUST 不把其他 CLI 的会话记录导入 MiMo 数据库。MiMo 自身的全局、主目录与项目配置 SHALL 保持为其账号和模型来源，不因本隔离改变。用户自己的 OpenCode 与 MiMo skill SHALL 仍可被 CLI 发现和使用。

#### Scenario: 主目录 .opencode 定义了 provider 或 MCP
- **WHEN** 用户主目录的 `.opencode/opencode.json` 为所选 provider 设置了其他 `apiKey` 或 `baseURL`，或定义了 MCP 服务器
- **THEN** OpenCode Worker 与模型发现仍按插件核验的账号档案执行，所选 provider 的地址与凭据不被覆盖，该 MCP 不被加载

#### Scenario: 主目录 .opencode 中的 skill
- **WHEN** 用户把 skill 放在主目录 `.opencode/skills` 或 `.opencode/skill`
- **THEN** 该 skill 仍出现在 OpenCode Worker 可用 skill 中，且 CLI 不在该目录写文件或安装依赖

#### Scenario: Claude Code 会话记录存在
- **WHEN** 用户主目录有 Claude Code 会话记录，插件为 MiMo 运行模型发现、派遣 Worker 或打开登录
- **THEN** MiMo 数据库不新增来自 Claude Code 的导入会话；此前已导入的会话保留不动

#### Scenario: MiMo 自身配置
- **WHEN** 用户的 MiMo 全局配置、`~/.mimocode` 或项目 `mimocode.json` 定义了 MiMo 自身 provider 与模型
- **THEN** 模型发现与 Worker 继续使用这些来源，已有的配置检查（外部引用、远程配置拒绝）照常生效

#### Scenario: Worker 中运行的命令
- **WHEN** OpenCode Worker 通过原生 shell 工具运行命令
- **THEN** 命令看到的仍是用户真实的 `HOME`，Git、SSH 等用户工具配置不受隔离影响
