# cli-account-isolation Specification

## Purpose

约束全部 CLI 只读取并使用自身登录或独立 API 配置，在模型发现、选择、排队与续聊中保持同一账号来源，阻止跨 CLI 凭据回退和旧快照复活。

## Requirements

### Requirement: 自身账号来源
Host SHALL 仅识别各 CLI 自身原生账号目录、插件内该 CLI 登录目录、自己配置的 API Key 和私有环境文件。Host 凭据引用、继承的通用密钥及其他 CLI 账号 MUST 不成为本 CLI 登录证据或由插件注入执行。原生登录同一服务商属于本 CLI 自身来源，不按服务商名称误判跨 CLI；插件不额外提供操作系统级文件禁读隔离。

#### Scenario: 只有其他账号
- **WHEN** 仅 Harness 或其他 CLI 有账号
- **THEN** 本 CLI 无可用模型，任何入口均不能启动模型任务

#### Scenario: 自身 API 配置
- **WHEN** 用户在该 CLI 自身配置中设置 API Key 或私有环境引用
- **THEN** 只允许当前账号确认支持且 CLI 能执行的模型；Claude 自身显式网关配置按其专门目录规则处理。通用环境及其他 CLI 文件引用无效

#### Scenario: Claude 自身配置与继承路由环境
- **WHEN** CC Switch 在 Claude 自身 settings 中写入路由，同时宿主继承了旧的凭据或模型变量
- **THEN** 当前自身 settings 决定查询及执行来源；继承变量被该进程覆盖，不单独作为账号证据，不影响其他 CLI 或改写原生配置

### Requirement: 账号绑定和执行重检
Host SHALL 以不含秘密的账号来源版本绑定目录与任务，在保存选型、启动、出队及续聊重新检查。账号改变、退出、模型或强度失效 MUST 阻止任务，不能静默换号、换模型或 CLI。同账号续期 SHALL 以当前原生来源仍存在且身份一致为前提。

#### Scenario: 选型与排队期间换号
- **WHEN** 用户回答选型期间或任务排队期间退出、换号或切换来源
- **THEN** 原选择不能自动用于新账号，提示重新选择或派遣

#### Scenario: 续聊与旧快照
- **WHEN** 原账号已经退出或换号，旧 Worker 中仍有凭据
- **THEN** 不恢复旧账号或覆盖当前来源；历史可查看，换号后要求新建任务

#### Scenario: 历史任务没有账号绑定
- **WHEN** 升级前的历史任务没有可核验的原账号绑定
- **THEN** 保留历史并要求新建任务，不把当前账号自动绑定到旧原生会话

#### Scenario: 权限与强度撤销
- **WHEN** 账号未变但所选模型或强度不再可用
- **THEN** 启动前拒绝，不发送 prompt，不选择替代项

#### Scenario: 原生续期无法保护当前账号
- **WHEN** OpenCode OAuth 等原生续期缺少版本条件写回，无法阻止退出或换号后恢复旧凭据
- **THEN** 保留真实登录状态，该模式返回空目录并拒绝执行；同一 CLI 自身 API 配置仍可按当前账号范围开放

### Requirement: 安全迁移及生命周期
升级 SHALL 停用旧 Host 路由和派生认证快照，只清理可确定由插件生成的配置；原生账号、插件登录账号、会话和偏好 MUST 保留。凭据不得返回客户端或入日志，清理未确认退出的进程前不能删除快照或放行后续任务。

#### Scenario: 旧配置升级
- **WHEN** 旧部署保留 Host 引用、自动生成 provider 或凭据快照
- **THEN** 引用不生效，派生状态按本 CLI 当前账号重建，旧偏好不静默转换

#### Scenario: 清理失败
- **WHEN** 元数据或模型进程范围退出无法确认
- **THEN** 保留相关私有状态并阻止后续任务，不报告停止成功

### Requirement: 登录与执行来源贯通
在插件内为 Hermes 建立的原生登录目录 SHALL 成为 Hermes 独立的自身来源，账号状态、模型发现及执行 MUST 使用一致的来源选择。显式切换至插件 Hermes 账号上下文后，退出不得自动回退到全局旧账号；原生全局数据保留。

#### Scenario: 独立 Hermes 登录
- **WHEN** 用户通过插件 Hermes 原生菜单建立自身账号
- **THEN** 账号状态、目录和新任务均识别该目录；只有该 CLI 真实原生登录流程或自身 API 配置被允许，其他工具导入来源仍被拒绝

#### Scenario: 插件 Hermes 账号退出
- **WHEN** 插件 Hermes 自身登录目录的账号被退出或更换
- **THEN** 状态和模型同步失效或重新核对；旧任务不能用全局账号或旧快照继续执行

#### Scenario: 全局账号保持
- **WHEN** 插件准备和关闭独立 Hermes 账号菜单
- **THEN** 不复制外部账号、不删除原生账号、不覆盖原生配置和历史；只保留该插件登录来源及必要的私有状态

### Requirement: Hermes Nous 账号绑定
Hermes Nous 的登录摘要、模型发现与执行 SHALL 使用相同的自身来源和原生认证路由。账号版本 MUST 绑定原生运行时实际使用的认证，保存、出队、启动与续聊继续执行现有重检；静态配置或过期快照不得恢复退出的账号。

#### Scenario: 当前原生运行认证
- **WHEN** 原生 Nous 账号包含网页登录令牌和运行时认证字段
- **THEN** 模型查询与绑定核对原生实际用于推理的字段、当前身份和路由，不仅检查任意非空令牌

#### Scenario: 账号改变或注销
- **WHEN** 查询过程中或已选模型后，当前自身账号退出、换号或不可用
- **THEN** 旧模型结果和选型失效，不回退全局账号、不从旧 Worker 恢复认证

### Requirement: Claude 官方账号操作独立于网关
Claude 官方登录和退出 SHALL 使用当前原生账号目录与官方认证端点，独立于当前自身网关可达性及其 API 凭据。macOS 与 Windows MUST 保留 CC Switch 路由、原生账号和会话，且拒绝无法安全隔离的账号目录重定向或强制托管覆盖。

#### Scenario: 路由关闭或旧环境仍存在
- **WHEN** 用户关闭 CC Switch 路由后从插件登录官方 Claude 账号
- **THEN** 原生官方登录流程可启动，旧的路由环境不会阻塞或把登录指向代理

#### Scenario: 登录时路由仍在运行
- **WHEN** 用户在自身 API 路由配置存在时启动官方登录或退出
- **THEN** 操作仅作用于官方账号存储，路由 settings 不变；路由开启时新任务仍使用自身选定路由

#### Scenario: 无法覆盖的托管来源
- **WHEN** 原生托管配置强制认证或账号目录来源，无法安全选择官方账号
- **THEN** 返回明确的来源错误，不启动登录或使用其他账号

### Requirement: 跨平台原生账号文件读取
Host SHALL 在 macOS 与 Windows 读取 OpenCode、Hermes、Pi 原生账号及私有元数据文件前后检查路径与已打开文件的身份，拒绝符号链接、非普通文件、多硬链接及读取期间的路径替换。平台不支持 `O_NOFOLLOW` 时 MUST 保留相同的拒绝行为；来源错误不得暴露账号内容。POSIX 私有 mode 与 Windows ACL SHALL 按平台能力分别解释，不以 Windows `stat.mode` 宣称私有 ACL 已验证。

#### Scenario: 原生账号文件是符号链接
- **WHEN** 上述 CLI 的账号或私有元数据文件路径指向符号链接，即使当前平台没有 `O_NOFOLLOW`
- **THEN** 账号状态不可用，不读取并使用链接目标中的凭据，不将目标账号视为已登录

#### Scenario: 打开或读取期间文件被替换
- **WHEN** 账号路径在初次检查后、打开或读取期间改为另一个文件或符号链接
- **THEN** 来源检查失败，不返回替换文件中的账号，不暴露其秘密

#### Scenario: 原生普通文件保持稳定
- **WHEN** 账号文件及其路径在检查、打开和读取期间保持同一普通文件身份
- **THEN** 按当前原生账号解析状态，不更改原生内容、目录或账号

### Requirement: 独占账号按账号排队
Pi/OMP 的 OAuth 账号由来源绑定的共享存储与 Host 租约独占时，任务 MUST NOT 因账号被另一任务或目录读取占用而失败。本轮进程启动前遇到占用的任务 SHALL 退回原队列位置且不占并发名额，在本 Host 中持有同一账号的任务结束后或定时重试时再次完整授权；停止排队任务 MUST 立即结束且不再尝试。派遣检查遇到占用时 SHALL 只使用同一账号最近一次已验证的目录完成选型与入队，没有时等待短暂的目录读取；账号变化 MUST 失败关闭，其他错误 MUST 照常报告。插件 MUST NOT 让同一 OAuth 账号同时运行多个进程。

#### Scenario: 并行派遣同一 OMP 账号
- **WHEN** 主 Agent 同时派遣多个使用同一 OAuth 账号的 OMP 任务
- **THEN** 所有派遣成功入队，任务逐个运行，等待中的任务显示排队，不出现「账号正被使用」失败

#### Scenario: 账号被占用时让出名额
- **WHEN** 一个 OMP 任务因账号被占用而等待
- **THEN** 其他 CLI 的任务可以使用空出的并发名额运行

#### Scenario: 等待中停止
- **WHEN** 用户停止正在等待账号的任务
- **THEN** 任务以用户停止结束，之后不再尝试授权或启动

#### Scenario: 等待期间换号
- **WHEN** 派遣检查或排队重试时账号已变为其他账号
- **THEN** 不使用旧账号的目录，按账号已变更失败

### Requirement: macOS Antigravity 账号读取系统钥匙串
在 macOS 上，Host SHALL 以系统钥匙串中 service `gemini`、account `antigravity` 的条目作为 Antigravity 登录状态与账号绑定的唯一来源，通过参数数组调用 `/usr/bin/security` 读取并在 Host 进程内解码；凭据、令牌与条目原文 MUST NOT 写入日志、事件、持久化文件或界面。条目不存在时 MUST 视为未登录，MUST NOT 回退到 `~/.gemini/jetski-standalone-oauth-token`；读取失败时 MUST 报告无法读取，不判为已登录或未登录。绑定主体 SHALL 与原文件来源的计算方式一致，同一账号的绑定版本不因来源切换而改变。

#### Scenario: 原生退出后
- **WHEN** 用户在 Antigravity 中 `/logout`，钥匙串条目已删除而遗留文件仍在
- **THEN** 设置页显示未登录；续聊拒绝启动并提示登录，原会话与绑定保留

#### Scenario: 重新登录原账号
- **WHEN** 用户重新登录同一 Antigravity 账号，钥匙串条目重新写入
- **THEN** 设置页显示已登录及邮箱；已有任务以原绑定原生续接，不追加改绑说明

#### Scenario: 在 agy 中换到另一账号
- **WHEN** 钥匙串条目对应另一账号，遗留文件仍属原账号
- **THEN** 绑定按钥匙串中的账号计算，与原账号不同，按换号处理

#### Scenario: 钥匙串不可读
- **WHEN** `/usr/bin/security` 以非「条目不存在」的状态失败、超时或输出无法解析
- **THEN** 显示无法读取 macOS 钥匙串中的 Antigravity 账号，拒绝绑定，不启动任务
