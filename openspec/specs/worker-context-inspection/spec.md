# worker-context-inspection Specification

## Purpose

让用户查看所属 CLI 原生会话的当前上下文占用、已核实容量及可取得的分类数据，在所有 CLI 中使用一致的原生菜单体验，并明确未知、估算和累计消耗的区别，避免将父会话或历史用量误当作当前窗口。

## Requirements

### Requirement: 所属会话上下文与累计用量分开
上下文检查 SHALL 仅使用所选 Worker、原生会话及已确认模型的证据，区分当前窗口占用、一次回复用量、本轮和会话累计用量。重复快照 MUST 覆盖而非相加，后续轮次更新当前占用，缺失字段不得当作零或沿用其他 Worker 数据。

#### Scenario: 累计数与当前窗口不同
- **WHEN** CLI 同时返回累计 token 和当前上下文窗口指标
- **THEN** 累计用量保留其范围，菜单百分比仅使用当前窗口指标，不以累计消耗填充当前占用

#### Scenario: 切换与续聊
- **WHEN** 切换 Worker、原生上下文压缩或启动同一会话的新一轮
- **THEN** 依据该会话最新有效证据更新当前值，迟到旧数据不能覆盖其他会话；重复读取不增加用量

### Requirement: 核实容量和缺失来源
上下文容量 SHALL 来自对应原生运行、已核对模型目录或该会话配置，不能按模型名称猜测。CLI 原生 UI 有可核查计算规则时可沿用并标注估算和来源。仅取得占用或容量时 MUST 保留已有真实值并说明缺失，不能显示伪造的百分比。

#### Scenario: 新协议只返回 token 数
- **WHEN** 取得当前输入证据但尚无可验证容量
- **THEN** 保留可用数值和统计范围，百分比保持未知；不能借用宿主主会话容量或常见模型上限

#### Scenario: 原生目录补全容量
- **WHEN** 同一 CLI 的已确认模型目录提供容量，并能与本轮模型身份严格匹配
- **THEN** 使用该容量和当前窗口证据计算占用，保留来源；不改变模型选择或启动额外生成

### Requirement: 原生上下文菜单和分项边界
上下文查看 SHALL 对齐 Harness 0.2.0-rc.2 原生菜单的触发、布局、字体、圆环、总量和分段条，并支持系统提示词、工具定义、对话消息等有证据的分类。未知分项 MUST 使用 `—` 明确为未提供，不以字符比例或父会话数据编造 token，不将未知当零，不为填满原生样式伪造分段。全部 CLI 的弹层 SHALL 删除重复缺失说明，保留估算标记，并在最后一项后只保留正常内边距。

#### Scenario: 有完整原生分项
- **WHEN** CLI 提供当前窗口总量、容量和可核查的提示词/工具/对话分类
- **THEN** 按原生菜单呈现相应分项与占比，分类和总量口径一致，估算值有明确标记

#### Scenario: 只有总量
- **WHEN** CLI 仅提供总占用与容量，缺少系统提示词或工具定义等分类
- **THEN** 原生菜单展示总量和未知分项，不附加“当前记录缺少部分分类统计”等段落，不宣称取得完整内部上下文或分类。

### Requirement: 私有上下文数据读取与公开投影
Host SHALL 对本轮原生元数据和只读会话记录进行有界读取、身份核对和缓存；Client 只经既有 Gateway 接收统计及必要公开数据。上下文检查 MUST 不读取其他账号、会话或凭据，不执行未授权模型任务，不提取签名、加密或 redacted 内容，不因未知分项擅自更改 CLI 行为。

#### Scenario: 链接或不完整记录
- **WHEN** 原始记录是未核实链接、读取期间变更、超限或当前帧尚未完整
- **THEN** 保留最后可核验统计或报告不可用，不误读外部目标、不伪造新统计，也不改变任务成功状态

#### Scenario: 无原生分类能力
- **WHEN** 对某 CLI 的能力核对确认当前入口没有提供可用分类
- **THEN** 文档和菜单如实记录其边界，继续展示已证实总量或未知，不借用另一 CLI 的协议字段

### Requirement: CodeBuddy 系上下文分类经只读副进程读取
CodeBuddy Code、WorkBuddy CN 与 WorkBuddy 的 ACP 只给上下文总量，分类只在原生本地命令 `/context` 中提供，而该命令的输出会作为用户消息写入会话并进入下一次模型请求。Host SHALL 只在本轮已结算（`end_turn`，或因拒绝审批而结束）、未被停止且 Worker 自身进程已退出后，另起一个带 `--no-session-persistence` 的同版本 CLI 进程，载入同一会话、切到本 Worker 已确认的模型后发送 `/context`，解析系统提示词、系统工具、MCP 工具、消息等原生分类与头部总量和容量，以原生估算（按 0.1K 取整）发出。MUST NOT 在 Worker 自身进程里执行 `/context`，MUST NOT 写回会话；副进程在有限时间内结束，失败、超时、模型不符、报告残缺或出现模型活动时什么都不发，也不改变本轮结果。

#### Scenario: 读取成功
- **WHEN** CodeBuddy 或 WorkBuddy CN 的 Worker 正常完成一轮
- **THEN** 上下文弹层的系统提示词、工具定义（系统工具与 MCP 工具之和）、对话消息三行显示 CLI 原生 `/context` 的估算值，总量与容量取同一份报告，并标记为估算

#### Scenario: 不写回会话
- **WHEN** 副进程读取分类
- **THEN** 原生会话文件不新增 `/context` 命令或其输出，Worker 下一轮的模型请求不包含这些内容

#### Scenario: 读取失败或被停止
- **WHEN** 本轮被用户停止或失败，或副进程超时、退出异常、报告残缺、头部模型与本 Worker 模型不符
- **THEN** 不发出分类，本轮结果与状态不变；用户停止时不启动副进程

#### Scenario: TRAE CN 没有分类来源
- **WHEN** TRAE CN（traecli 0.213.1）完成一轮
- **THEN** 只显示回执 `contextWindow` 的总量与容量，三行分类保持 `—`；该版本 ACP 只发 `usage_update` 的 used/size，可用命令中没有 `/context`，插件不借用 CodeBuddy 的协议，也不按总量倒推分类
