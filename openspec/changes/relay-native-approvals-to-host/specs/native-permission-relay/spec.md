## ADDED Requirements

### Requirement: CLI 权限跟随 DSH 权限预设
插件 SHALL 在每轮启动时读取父会话当前的 DSH 权限预设，并把 CLI 映射到其原生对应模式：仅可查看映射为原生只读或规划模式，工作区内修改映射为原生工作区内自动修改模式，完全权限映射为原生完全权限模式。规划模式 SHALL 优先于预设。CLI 没有对应原生模式时 MUST 使用最接近的更严模式并在任务记录中说明，MUST NOT 使用比预设更宽的模式。插件 MUST NOT 附加自己的操作系统沙箱。

#### Scenario: 完全权限
- **WHEN** 父会话为完全权限，派遣 Codex 写任务
- **THEN** Codex 以原生完全权限模式运行，不出现审批弹窗

#### Scenario: 工作区内修改
- **WHEN** 父会话为工作区内修改，CLI 在工作区内编辑文件
- **THEN** 由 CLI 原生沙箱自动放行，不出现审批弹窗

#### Scenario: 规划模式
- **WHEN** 父会话处于规划模式，无论预设为何
- **THEN** CLI 以原生只读或规划模式运行，写入请求直接拒绝，不弹窗

#### Scenario: CLI 没有对应模式
- **WHEN** 某 CLI 没有原生完全权限模式
- **THEN** 以其最接近的更严模式运行，任务记录说明实际使用的模式

### Requirement: 额外授权请求走 DSH 审批弹窗
预设为仅可查看或工作区内修改时，CLI 发出的原生授权请求 SHALL 交由 DSH 用户决定，弹窗位置按本轮来源确定：主 Agent 调用（`cliworker_start` / `cliworker_followup`）发起的轮次 SHALL 在主 Agent 页面以 DSH 原生提问卡询问；用户在 Worker 会话或侧栏中发起的轮次 SHALL 在该 Worker 的原生会话中以 DSH 原生审批面板询问，插件客户端 SHALL 在该轮运行期间保持子会话以便面板呈现，并在 Worker 卡片显示「等待审批」。弹窗 MUST 写明 Worker、CLI、请求内容与工作目录；用户批准后插件回复 CLI 允许，拒绝、关闭、无应答者、超时或任务停止 MUST 回复拒绝。预设为完全权限时 CLI 残余的授权请求 SHALL 自动放行，不弹窗，并在时间线记录决定来源为完全权限自动放行；规划模式下 MUST NOT 自动放行写入请求。每个请求 SHALL 按其发出时的当前预设决定，时间线 SHALL 记录请求内容、决定与决定来源。

#### Scenario: 主 Agent 派遣的任务申请网络
- **WHEN** 预设为工作区内修改，主 Agent 派遣的 CLI 申请网络访问以安装依赖
- **THEN** 主 Agent 页面出现 DSH 提问卡，用户选择允许一次后 CLI 继续执行，时间线记录决定来源为 DSH 用户

#### Scenario: Worker 会话中续聊的任务申请授权
- **WHEN** 用户在 Worker 会话中发送续聊消息，本轮 CLI 请求执行沙箱外命令
- **THEN** 该 Worker 的原生会话出现 DSH 审批面板，Worker 卡片显示等待审批，用户拒绝时 CLI 收到拒绝

#### Scenario: 仅可查看下的写入请求
- **WHEN** 预设为仅可查看，只读派遣的 CLI 请求写文件
- **THEN** 每次都按本轮来源出现 DSH 弹窗，拒绝时 CLI 收到拒绝

#### Scenario: 完全权限下的残余请求
- **WHEN** 预设为完全权限，CLI 仍发来一个授权请求
- **THEN** 插件不弹窗、回复允许，时间线记录该请求及决定来源为完全权限自动放行

#### Scenario: 无人处理或任务停止
- **WHEN** 弹窗未得到回答时任务被停止，或客户端没有打开对应会话而无可用应答者
- **THEN** 回复 CLI 拒绝，不视为批准，时间线记录决定来源为任务停止或无人应答，停止仍在进程范围退出后才报告

#### Scenario: 运行中切换预设
- **WHEN** 任务运行中用户把预设从完全权限改为工作区内修改
- **THEN** 之后的授权请求按工作区内修改处理，CLI 沙箱从下一轮起按新预设启动

### Requirement: 本会话始终允许使用 CLI 原生会话级授权
主 Agent 页面的提问卡 SHALL 仅在该 CLI 的授权请求原生提供会话级或始终允许回复时，提供「本会话始终允许」选项；用户选择后插件 SHALL 回复该 CLI 的原生会话级允许，后续是否再询问由 CLI 自身决定。插件 MUST NOT 自行记忆或扩大授权；CLI 没有原生会话级回复时 MUST NOT 提供该选项。Worker 会话内的 DSH 原生审批面板只提供允许一次与拒绝。

#### Scenario: Codex 命令请求
- **WHEN** 主 Agent 派遣的 Codex 请求执行命令，用户在提问卡选择本会话始终允许
- **THEN** 插件回复 Codex 原生的会话级允许，时间线记录决定为本会话始终允许

#### Scenario: CLI 没有会话级回复
- **WHEN** 某 CLI 的授权请求只有单次允许与拒绝
- **THEN** 提问卡只显示允许一次与拒绝

### Requirement: 尊重用户原生沙箱配置
插件 SHALL 不以比当前预设更严的轮次参数覆盖用户在 CLI 原生配置中设定的网络与可写目录，规划模式或预设要求更严时除外。继承配置启用网络时插件 MUST NOT 在启动前直接拒绝运行。

#### Scenario: 用户原生配置启用网络
- **WHEN** 预设为工作区内修改，用户 Codex 配置为 workspace-write 且启用网络
- **THEN** 任务沿用该网络设置运行，不在启动前报告权限未保留
