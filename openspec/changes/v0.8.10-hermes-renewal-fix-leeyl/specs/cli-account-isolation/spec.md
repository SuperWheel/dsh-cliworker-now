## MODIFIED Requirements

### Requirement: Hermes 同源 OAuth 自动续期
macOS 与 Windows SHALL 共用 Hermes Nous 续期逻辑。有效短期访问令牌不触发刷新；同一明确账号的访问令牌临近过期或已过期且有原生刷新凭据时，插件 SHALL 在账号、目录及任务准入检查中允许一次有界非交互原生续期，随后重读原生状态。刷新 MUST 保持账号来源、主体、组织、客户端及路由，且不得登录另一账号、创建匿名身份、打开浏览器或调用模型。原生持久化接口 MUST 在轮换前确认可用，支持已核验的新旧续期契约，未知契约不得消耗刷新凭据。

#### Scenario: 短期令牌到期而登录仍可续期
- **WHEN** 自身 Nous 访问令牌已到期或低于原生可用 TTL，原生刷新凭据存在且来源及主体可确认
- **THEN** 在原生锁内刷新并立即保存轮换凭据，再核对同一主体，账号与模型检查可继续；令牌轮换不使原有同主体绑定失效

#### Scenario: 健康令牌与并发检查
- **WHEN** 令牌仍有足够有效期，或多个同账号状态/目录/派遣检查同时到达
- **THEN** 健康令牌仅做本地读取；需要续期时同目录不并发轮换，取消和账号操作等待进程范围清理，不在退出账号后写回旧登录

#### Scenario: 原生共享状态与凭据池
- **WHEN** 刷新涉及原生共享状态或既有同源凭据池行
- **THEN** 只接受同主体同路由的可核验原生状态并按原生锁序保持轮换一致；不同主体、来源不明、已删除账号或不支持契约明确拒绝，不导入外部凭据，不清除禁用、额度、冷却或用户元数据

#### Scenario: 临时失败与必须重登
- **WHEN** 原生续期遇到网络/超时/临时服务故障，或明确返回终止鉴权错误/缺失刷新凭据
- **THEN** 前者显示暂时无法续期并可重试，后者才要求重新登录；保留现有凭据，不泄露令牌、原始授权响应或 URL

#### Scenario: 原生升级要求显式续期语义
- **WHEN** 已核验的原生共享存储接口要求区分续期与重新登录
- **THEN** 以续期语义保存同主体状态并重读确认，不按重新登录覆盖身份；旧版单参数接口仍可正常续期

#### Scenario: 未知持久化契约
- **WHEN** 原生共享写入函数不能绑定到已核验的续期调用方式
- **THEN** 在请求刷新、修复共享镜像或写入凭据之前返回不支持安全续期，不以捕获调用错误后重试的方式猜测协议
