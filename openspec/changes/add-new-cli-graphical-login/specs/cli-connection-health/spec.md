# Spec Delta

## ADDED Requirements

### Requirement: CodeBuddy 单入口图形账号流程
CodeBuddy Code SHALL 保持 `codebuddy` 单入口，将中国站、国际站、企业域与 iOA 作为原生账号站点。插件 SHALL 通过安装版 TUI 的 `/login` 和 `/logout` 引导登录及退出，不编造非交互登录子命令。未识别画面、企业自定义流程或未核实的站点选择 MUST 保留原生接手。

#### Scenario: 进入登录与选择站点
- **WHEN** 用户启动 CodeBuddy 登录，原生画面已显示可核对的输入就绪状态或站点菜单
- **THEN** 插件只在就绪状态输入一次 `/login`，或直接绘制已出现的站点选项；只根据用户当前选择响应匹配菜单，不默认选择中国站或国际站，不重复发起登录

#### Scenario: 无法安全定位选项
- **WHEN** 菜单不完整、重绘后高亮无法核对，或企业域/iOA 步骤尚未支持
- **THEN** 提示并转入原生终端，不凭选项顺序猜测按键，不把企业账号拆成另一 CLI

#### Scenario: 账号读取边界
- **WHEN** 图形流程确认 CodeBuddy 状态或显示站点
- **THEN** 仅沿用自身本地登录状态与获准的站点投影；认证文件内容只取 `auth.domain`，不读 token，不调用返回访问令牌的用户信息接口，不用文件修改时间或站点标签证明换号

### Requirement: TRAE CN 单账号登录方式选择
TRAE CN SHALL 保持单账号，复用两列卡片让用户明确选择个人、企业 SSO 或企业 PAT。个人方式 SHALL 使用 `traecli --enable personal_user_login login --personal`，SSO 使用 `traecli login --enterprise`，PAT 使用 `traecli login --with-trae-pat`；登录特性开关 MUST 只作用于本次个人登录，不写配置或附加到任务启动。

#### Scenario: 个人登录
- **WHEN** 用户选择个人登录并继续
- **THEN** 以个人 argv 启动，说明其依赖开发中特性；只对真实画面已核实的步骤提供浏览器、设备码或回调模板，未知画面可显示原生终端

#### Scenario: 企业登录
- **WHEN** 用户选择企业 SSO 或企业 PAT
- **THEN** 进入对应原生流程并提供原生接手；不猜测 SSO 域名或协议，不在插件中收集企业 PAT，不读取/显示其环境变量值；原生 CLI 继续按自身规则读取环境或 stdin

#### Scenario: 没有选择或方式失效
- **WHEN** 用户取消选择，或请求携带未知方式，或当前 Host 不支持方式选择
- **THEN** 不启动默认登录、不回退个人账号，显示可理解的原因

#### Scenario: 套餐或状态未知
- **WHEN** TRAE 状态报告套餐不支持、未知输出或查询失败
- **THEN** 保留对应原因，不显示登录成功，不推断个人/企业身份；登录确认以新的 `login status` 状态及对应退出结果为准

### Requirement: 新增单账号向导的自动退出与切换
CodeBuddy 和 TRAE CN 已登录时 SHALL 先显示当前账号卡片，打开卡片不启动登录进程。用户明确点击「切换账号」后 SHALL 自动执行本 CLI 已核实的退出流程，确认账号已退出并确认所属进程范围已清理后才进入新的登录向导；读取错误、未知状态或清理失败 MUST 阻止后续登录。TRAE 退出使用 `traecli logout`。

#### Scenario: 切换成功进入向导
- **WHEN** 用户点击切换，原生退出已确认且进程清理成功
- **THEN** CodeBuddy 进入新的站点/授权流程，TRAE 进入登录方式选择；旧目录结果失效，重新核对账号与模型，不自动保存新模型偏好

#### Scenario: 退出未确认
- **WHEN** 原生退出码为零但账号仍登录，或查询不可用/未知/读取被拒绝
- **THEN** 显示未确认原因及重试/原生接手，不以终端文字、零退出码或非 authenticated 的泛化判断认定退出

#### Scenario: 原生信任或未知确认屏
- **WHEN** 自动退出遇到未授权的 trust/条款或未识别菜单
- **THEN** 保留用户决定或原生回退，不自动同意、不无限补 Enter，也不删除原生账号文件

### Requirement: WorkBuddy 桌面端账号图形引导
`workbuddycn` 与 `workbuddy` SHALL 提供复用步骤窗口的桌面账号管理指引。用户点击打开桌面端后，Host MUST 只打开与当前 CliId 身份一致的已安装应用；登录、退出和换号由用户在该桌面应用完成。插件 MUST 不运行虚构的 CLI login/logout、不提供伪账号终端、不删除凭据或自动退出桌面账号。

#### Scenario: 未登录打开桌面端
- **WHEN** 用户在 WorkBuddy 引导页点击打开桌面端
- **THEN** 打开已核实版本的应用，显示等待用户登录及状态刷新操作；打开成功本身不表示已登录

#### Scenario: 已登录管理账号
- **WHEN** 用户查看已登录的 WorkBuddy 账号页或点击桌面管理
- **THEN** 显示可确认的当前状态与站点，明确在桌面端退出或换号；不展示“插件将先自动退出”的承诺，不提供凭空生成的账号邮箱

#### Scenario: 安装不匹配或打开失败
- **WHEN** 应用缺失、安装身份不符、路径属于另一版或打开失败
- **THEN** 保留原因及重试/手动打开指引，不回退另一版、PATH CodeBuddy 或任意外部程序

### Requirement: WorkBuddy 有界状态观察
WorkBuddy 图形管理页 SHALL 在显式打开后以单个在途查询、有限间隔和总时限观察本版原生元数据状态，允许手动刷新。查询 MUST 不发模型 prompt、不新增凭据读取或持久化，不把安装/站点绑定当作账号主体。仅确定的认证缺失可证明退出，普通探测失败 MUST 保持不可用；观察结束或关闭后不得继续自动查询。

#### Scenario: 桌面登录后自动确认
- **WHEN** 同一引导会话先确认未登录，用户在桌面端登录后元数据查询成功
- **THEN** 窗口自动显示当前已登录并刷新相关目录，停止自动观察；不得宣称真实模型任务已验收

#### Scenario: 同站点换号不可辨认
- **WHEN** 元数据在操作前后都为已登录且没有稳定账号主体
- **THEN** 只显示当前已登录，保留手动刷新或继续观察，不报告“已切换到新账号”；若观察到确定退出再登录，可报告这一状态转换但不捏造新身份

#### Scenario: 退出、失败和超时
- **WHEN** 用户在桌面端退出，或探测失败，或观察到达时限
- **THEN** 确定未登录时显示当前未登录；普通错误保留失败类别；超时停止自动查询并允许手动刷新，不把错误或超时当作已退出

#### Scenario: 查询副作用和清理
- **WHEN** 状态观察触发原生空会话查询或用户关闭窗口
- **THEN** 账号和模型复用同一周期的查询，不重叠启动；关闭取消本次观察并确认插件查询进程/助手退出，不关闭用户桌面应用，不声称原生空会话已删除

### Requirement: 新图形引导的呈现与链接边界
新增账号引导 SHALL 复用 480px 窄窗口、主题 token、淡色提示、浅灰账号卡片、两列选择和右对齐操作，状态文字与相应按钮同排；提供中英文固定文案。CLI 文本 MUST 作为不可信终端内容处理，浏览器链接必须为本 CLI 已核实的 HTTPS 主机且无 userinfo。桌面管理页 SHALL 隐藏不存在的终端回退按钮。

#### Scenario: 非白名单或企业地址
- **WHEN** 终端给出相似恶意域名、未核实子域、含 userinfo 或非 HTTPS 地址
- **THEN** 图形页不提供打开/复制该地址的登录按钮，保留原生接手，不通过扩大企业域通配来绕过校验

#### Scenario: 原生终端回退
- **WHEN** CodeBuddy 或 TRAE 出现未知步骤
- **THEN** 登录与退出 MUST NOT 自动展开原生终端：窗口只显示“无法识别当前步骤”、「显示原生终端」及关闭后重新登录的提示；只有需要用户在终端里作答的已录制步骤（企业域地址、iOA、TRAE 企业流程等）才自动展开并聚焦；结果页不被迟到关闭消息覆盖

#### Scenario: CodeBuddy 授权未完成
- **WHEN** 浏览器授权超时（5 分钟，TimeoutError）、无法打开或被取消，CodeBuddy 显示 `Failed to login. Press esc to return to login`，或在已输入过 `/login` 后回到输入界面
- **THEN** 窗口 SHALL 显示警告与「重新登录」，不显示原生错误原因；点击后分别按 Esc 回到站点菜单或重新输入 `/login`，不自动重复发起登录

#### Scenario: 桌面管理与旧 Host
- **WHEN** WorkBuddy 没有 PTY，或旧 Host 未声明桌面管理能力
- **THEN** 前者显示桌面管理/刷新操作而无终端按钮；后者只保留原有指引，不发送未知 RPC 或创建虚假运行状态

### Requirement: 新引导的权限与会话生命周期
新增账号操作 SHALL 沿用父会话归属、CLI 启用检查、宿主执行权限与同 CLI 互斥。取消、关闭、父会话结束或插件卸载 MUST 中止写键、观察和订阅，并回收插件拥有的进程范围；清理未确认时保持阻塞，不自动重启登录。所有敏感输入 MUST 不进入引导帧、Worker 日志或持久化。

#### Scenario: 权限拒绝或任务占用
- **WHEN** 父会话不能执行账号动作，或同 CLI 有活动任务/账号操作
- **THEN** 拒绝启动登录、退出或桌面管理动作，保留现有账号与会话，不自行放宽权限

#### Scenario: 取消与迟到结果
- **WHEN** 用户取消等待中的启动/查询，随后旧请求返回终端或状态
- **THEN** 回收迟到资源并丢弃旧结果，不写入新的 CLI 窗口或开始下一步登录

#### Scenario: 清理失败后恢复
- **WHEN** 进程范围清理无法确认
- **THEN** 保留明确失败与既有清理保护，不能将停止报告为成功或放行新的冲突操作；按已有解除暂停流程恢复

### Requirement: 新图形登录的证据分层
该变更的交付记录 SHALL 分开列出文档、Host、Client、模拟测试、未提交授权的真实画面采集及 Desktop 验收。新 marker MUST 来自可核查的安装版画面；不能取得的步骤保留未完成。规格严格校验、模拟状态和构建通过 MUST 不替代真实登录/退出、Windows 或 Desktop 证据。

#### Scenario: 只完成文档
- **WHEN** 方案与指南通过严格规格校验，但没有实施代码或采集屏幕
- **THEN** 只勾文档及实际校验，Host/Client/测试/采集/Desktop 任务保持未完成，不归档隐藏缺口

#### Scenario: 采集不提交授权
- **WHEN** 在隔离 HOME 中采集新 CLI 的授权前画面
- **THEN** 不提交账号凭据、浏览器授权或模型请求；必须经过真实授权才能看到的后续画面记为缺失，模拟夹具明确标为模拟
