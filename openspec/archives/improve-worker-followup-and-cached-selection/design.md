# Design

## Context

现有 runtime 单会话互斥、进程范围清理和 launch 的权限验证是队列的执行基础。当前 stdin 被忽略；本次采用用户明确选择的轮后排队，不修改各 CLI 传输协议。Worker 改选目前重复 querySelection，SettingsCatalogCache 已有私有持久目录但不作为新 Host 展示来源。

## Goals / Non-Goals

**Goals:** 输入不因当前运行而锁定；可靠保存并顺序发送后续消息；缓存降低菜单等待；显示确有来源的公开摘要。

**Non-Goals:** 不实现即时 steer、隐式停止、原生后台上下文改造、隐藏推理提取或新账号/模型实测。不增加版本或部署 Desktop。

## Decisions

1. Host 管理待发送队列和持久文本，Client 展示快照并调用入队、取消、显式恢复。逐条复用正常 launch 验证与 runtime 互斥；只有 completed 和清理完成才能自动下一条。失败、停止、uncertain、重启暂停，用户可取消或明确重试。用 Worker/run 身份与提交标识防过期及重复请求。取消与启动以 Host 同步状态转换为准。
2. 输入草稿与已接受待发送项分开。成功入队才清空对应草稿；输入请求进行时允许打字但禁止重复提交。输入区右下角仅有一个动作按钮，运行中无正文为停止，有正文切换发送，不并排显示。发送按钮明确“本轮结束后发送”，队列项显示真实等待/暂停原因和取消操作；使用现有主题、Button 和紧凑布局。
3. 缓存读取与执行授权拆开。首次已授权发现存目录，Worker 原绑定选择只能读精确来源的保存目录；缺失才查询。configureWorker 基于缓存合法组合保存，launch/runtime 启动仍实时验证。缓存不成为调用权限证明，失效明确拒绝。保持设置页的实时检查。
4. 原生 session 参数已贯穿各适配器，配置更改不会清 session。先测试传参及同会话保护；无证据不显示“必然丢上下文”警告。各供应商后台完整语义保留为未做真实调用的边界。
5. 公开摘要按协议中明确可读字段白名单接入，用稳定 step 身份更新，过程区单独呈现。不读 redacted/signature/encrypted 或私有缓存。不将摘要当最终回复或成功证据。

## Risks / Trade-offs

- 队列引入后台执行 → 入队显式说明轮后自动发送，停止和异常暂停，重启不自动重放；关闭面板不取消已接受消息。
- 保存目录可能过期 → 菜单快选只记偏好，发送时真实验证，拒绝后保留文本。
- 厂商公开事件不同 → 只实现有当前原生资料证据的结构并做合成协议验收，不泛化所有 CLI。

## Migration Plan

新增待发送私有持久文件向后兼容；旧 Worker 无队列。先关联测试、类型检查、隔离构建及实际组件渲染。正式更新需沿既有无活动任务规则进行；本轮不更新已安装包。回退时保留队列文件与原生会话，不自动提交其中内容。
