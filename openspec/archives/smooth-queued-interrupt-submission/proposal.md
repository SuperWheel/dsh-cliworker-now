# Proposal

## Why

待发送卡片的插队操作仍通过 `panel.tsx` 的全局等待流程，必须等当前 CLI 停止后才响应；Host 暂停、提升队列的连续快照导致卡片闪动。上一轮即时消息反馈仍包含用户明确不需要的“正在发送…”文字。

## What Changes

- 插队点击立即在所属子对话显示消息，所选卡片平滑退场，不阻塞继续编辑。
- 以稳定队列身份保持本地提交状态，避免后台停止和准备快照让卡片反复出现；真实拒绝或准备失败恢复可操作的待发消息。
- 移除用户消息下例行的发送中、等待同步文字，保留真实错误及结果不确定的必要操作。
- 条目及最后一张卡片退场遵循减少动态效果偏好，保留现有主题、折叠及单发送按钮。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `worker-conversation-interaction`：插队的即时展示、平滑退场与失败恢复。

## Impact

主要修改 Client 提交状态、对话面板及队列动效；必要时为既有 Host 插队路径补充可核对的身份回执。停止清理、原生会话互斥、权限校验与队列持久化规则不变。不修改模型、账号、安装协议和 Harness 核心。保持 v0.7.9，仅关联最小验收及 macOS Desktop 验证，不推送 GitHub。
