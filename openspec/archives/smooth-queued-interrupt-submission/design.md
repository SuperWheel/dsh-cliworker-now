# Design

## Context

参见 proposal.md。现有 message-submissions 管理新消息的本地状态，队列卡片插队却仍使用全局 perform，且后端返回表示队列已提升，不等于下一轮已启动。

## Goals / Non-Goals

**Goals:** 点击时立即转移消息展示，保持后续草稿可编辑；按队列身份对账并处理失败；退出动画稳定可中止。

**Non-Goals:** 不加速或绕过真实进程停止、权限与原生模型校验；不伪造 CLI 接收；不改持久化消息文本或外部 CLI 协议。

## Decisions

1. 新增队列插队的本地提交路径，使用已有队列 ID 关联并暂时隐藏对应卡片；不经全局 busy。成功受理仍等待真实新轮事件；不能因原队列仍含同 ID 就当作确认。Host 在用户事件和时间线中透传可选的 queuedFollowupId；插队回执返回 queuedId 和 revision，以区分临时停止暂停与受理后失败，避免同文消息错误匹配。
2. 明确拒绝、准备失败与停止保留未发送文本；不确定回执继续核对而不自动重发。后续发送按所属 Worker 串行准入，切换 Worker 不传播等待。
3. pending/accepted 的用户消息不渲染额外状态文字；真实错误保留操作说明。
4. 独立 presence 组件以稳定 ID 保留退出行至过渡结束，grid 高度和 opacity 过渡 220ms/180ms；最后整体同步收起。退场内容 inert，减少动态效果立即移除；新快照不重建退出项，快速失败恢复可取消退出。

## Risks / Trade-offs

- 接口受理后后台准备仍失败 → 继续观察持久队列及真实事件，恢复卡片而非静默消失。
- 同文、重复点击及快照延迟 → 队列身份、事件水位及单 Worker 准入约束共同防重。
- 浏览器和桌面动效差异 → 标注模拟的真实组件浏览器检查，加 macOS Desktop 实际插队检查。

## Migration Plan

无存储迁移。先关联测试、类型检查和隔离预览，再确认无活动任务后更新 Desktop 链接构建；失败可恢复上一版构建。保持 v0.7.9，记录其他平台及 CLI 未验证边界。
