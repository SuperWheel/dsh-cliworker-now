# Spec Delta

## MODIFIED Requirements

### Requirement: 显式插队发送
插队 SHALL 将新消息或所选待发送卡片优先送入原会话下一轮。当前运行须先停止并确认进程范围退出，然后重新验证权限、账号及选型。其余待发消息保留，原已暂停队列不被无意恢复。点击卡片插队 SHALL 立即在所属对话展示本地用户消息并平滑移出卡片，不等待停止或准备完成；后台状态变化不得使卡片闪回。同一 Worker 的插队请求 MUST 串行；显式停止、取消、过期请求及清理不确定不得造成额外派遣或丢消息。

#### Scenario: 队列卡片插队
- **WHEN** 用户对第二条待发消息选择插队
- **THEN** 当前轮停止并清理后先执行该消息，其余消息文本保留且顺序不变；不会同时运行两轮

#### Scenario: 插队中停止或失败
- **WHEN** 插队等待清理期间用户停止或取消所选消息，或清理和再次授权失败
- **THEN** 不启动该消息，仍未发送的文本保留或按明确取消移除，显示原因并允许用户重新操作

#### Scenario: 即时插队与退场
- **WHEN** 用户点击插队而后台停止及准备尚未完成
- **THEN** 用户消息立即显示，所选条目高度与透明度平滑退场；最后一条退出时整个待发送区域平滑收起；用户仍能编辑后续消息，已退出项不可再次操作，减少动态效果时立即完成过渡

#### Scenario: 插队受理后准备失败
- **WHEN** 插队已受理但后续准备失败，或收到明确拒绝
- **THEN** 未执行消息恢复为可操作卡片并显示真实原因，其他卡片保留原顺序；未知传输结果须核对或停止，不自动重复执行

### Requirement: 立即提交反馈
用户消息下 SHALL 不显示例行的“正在发送”或“已提交，等待同步”文字；本地展示不代表 CLI 已经接收。用户提交有效文本时界面 SHALL 立即清空该次草稿并显示待确认用户消息，排队模式显示待发送卡片；不等待 CLI 准备、metadata 或原生回执才反馈。待确认不是已送达，确认后 MUST 对账避免重复。输入仍可编辑；同一 Worker 的准备和发送保持串行，不能因解除界面等待而并发启动。失败文本可恢复或重试且不得覆盖后来输入。

#### Scenario: 慢速准备与再次输入
- **WHEN** 发送后后台尚未完成准备，用户继续输入或发送
- **THEN** 第一条立即显示并清空原草稿，后续草稿和提交保留；同一 Worker 串行准入，单按钮支持停止准备，不把同一消息重复执行

#### Scenario: 确认和失败
- **WHEN** Host 确认、拒绝或连接中断
- **THEN** 确认消息仅显示一次；拒绝文本可恢复或重试且不覆盖新草稿；不确定状态不声称成功或无条件重发

#### Scenario: 切换 Worker
- **WHEN** 用户发送后切换 Worker，再收到成功或失败
- **THEN** 仅更新原 Worker 的提交状态和草稿，当前 Worker 的输入与提交能力不被全局等待锁住
