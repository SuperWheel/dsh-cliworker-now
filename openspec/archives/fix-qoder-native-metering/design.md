# Design

## Context

动机见 proposal.md。现有 ACP 执行和精确 userMessageId/parentUuid 读取可保留。原生投影已经支持只有比例的上下文；用量入口目前只接受 token 桶或 token 报告，因此不能携带独立积分。参考 Codingns4DSH 固定提交 `27b4c95065e9f3ae01d513c60673a871487257f3` 的数据来源，独立实现，不复制其末条记录选择、仅替换斜线的路径算法或上下文冒充输入桶的兼容方式。

## Goals / Non-Goals

**Goals:**
- 增量传递数字积分，精确关联本轮，隐藏 token 与零积分分别处理。
- 原生 UI 独立展示积分与 token 未公开；上下文有比例即可打开，可靠容量存在时补估算。
- 保留 Windows 异步 ACL、取消、缓存失效和 POSIX 私有读取路径。

**Non-Goals:**
- 不切换 SDK、不启动补充模型请求、不修改账户或原生会话、不用默认模型窗口。
- 本次不做全量发布验收，真实 Windows 账户及付费模型结果不在本次自动检查结论中。

## Decisions

1. 原生 JSONL 继续按会话、项目、模型、原生 user UUID 和 parent 链限定轮次。Credits 按原生 message.id/最终记录去重后求本轮和；多段同请求没有可核对身份时不推算总积分。终态缺比例时有效积分仍可独立发布。
2. ACP 主回执和 quota 各自验证完整输入输出及总和；优先有效主回执，否则取一致扩展回执，不逐桶混合。全零仍隐藏。
3. 窗口仅来自同轮 runtime-config 或有明确会话和轮次时间边界的 CLI 日志，日志有界读取、无符号链接并复用私有文件校验；日志失败不清除已验证积分和比例。估算不进入账单用量。
4. 共享遥测增加独立本轮积分；现有 Qoder 数字观测、历史补读和缓存同时传递它。原生用量投影通过可选独立积分元数据扩展，普通原生会话及其他 CLI 保持既有行为，积分不进入 token 算术。
5. 只调整已存在的 rc.2 四包 UI 扩展源码与可核对补丁，使用冻结依赖构建隔离候选，再更新仓库 runtime-host 供 preview；安装构建受空闲门禁约束。
6. Windows 实际 Qoder 文件由 Administrators 拥有，当前用户有直接完全控制 ACE，另含继承只读 ACE。仅 Qoder 数字读取显式允许此原生布局：每一路径要求当前用户所有权，或 Administrators 所有权并同时具备当前用户直接适用的完全控制；其他主体只能读，不能写、删除或变更权限。通用读取器默认所有者/私有 ACL 策略不变，POSIX 记录仍需 0700/0600；不修改原生 ACL。此判断结合链接、路径、前后描述符及稳定快照校验，保证数字来源不能被不可信写入替换。

## Risks / Trade-offs

- 日志版本差异 → 无法核对窗口时显示比例及未知容量，不猜模型窗口。
- 多段重复、恢复重放或后续轮次 → 精确身份链和请求去重；历史读取使用该轮原始绑定。
- Windows ACL 读取延迟 → 保持异步有限预算与取消，失败回退已有数字，不轮询 CLI。
- 原生 UI 合同变化 → 增量可选字段，关联渲染回归和四包类型/构建检查；不修改 Harness 核心。

## Migration Plan

无需改写原生存储。旧 raw 仍由精确补读恢复新数字；旧比例观测继续兼容。失败可回退本次源码及 runtime-host 构建产物，原始会话、凭据与用户设置不变。最小验收保留模拟平台检查与实机账户验证的边界。
