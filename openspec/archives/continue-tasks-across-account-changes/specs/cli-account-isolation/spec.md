## MODIFIED Requirements

### Requirement: 账号绑定和执行重检
Host SHALL 以不含秘密的账号来源版本绑定目录与任务，在保存选型、启动、出队及续聊时重新检查。适用于全部 CLI：任何轮次（新派遣的首轮、已有任务的后续轮次）遇到换号时，Host SHALL 以当前登录的自身账号重新授权用户已选的模型与强度，可用即按「换号后自动续接」绑定当前账号继续，MUST 不向用户显示换号说明。当前没有可用的自身账号，或所选模型、强度在当前账号下不可用时，MUST 阻止任务，不能静默换模型或 CLI，也 MUST 不恢复旧账号凭据。同账号续期 SHALL 以当前原生来源仍存在且身份一致为前提。

#### Scenario: 选型与排队期间换号
- **WHEN** 用户回答新任务的选型期间或新任务首轮排队期间换号或切换来源
- **THEN** 以当前账号重新授权用户的选择；可用则静默继续并绑定当前账号，不可用时按模型不可用处理；退出后无账号时提示登录

#### Scenario: 续聊与旧快照
- **WHEN** 原账号已经退出或换号，当前 CLI 已登录另一自身账号，且原模型与强度在当前账号下可用
- **THEN** 按「换号后自动续接」在当前账号下继续，不恢复旧账号或覆盖当前来源，不要求新建任务

#### Scenario: 已退出且无当前账号
- **WHEN** 续聊时该 CLI 没有已登录的自身账号
- **THEN** 拒绝启动并提示登录，历史可查看，不使用旧 Worker 中残留的凭据

#### Scenario: 退出后重新登录原账号
- **WHEN** 已有任务的 CLI 原账号退出期间续聊被拒，之后再登录原账号并续聊
- **THEN** 退出期间不启动进程、保留原会话与绑定；重登后以原生续接继续同一会话，不追加改绑说明

#### Scenario: 历史任务没有账号绑定
- **WHEN** 升级前的历史任务没有可核验的原账号绑定
- **THEN** 视同换号，按「换号后自动续接」绑定当前账号续接；当前无可用账号时拒绝并提示登录

#### Scenario: 权限与强度撤销
- **WHEN** 账号未变或已改绑，但所选模型或强度在当前账号下不再可用
- **THEN** 启动前拒绝，不发送 prompt，不选择替代项，提示重新选择模型；提示只说明模型或强度不可用，不提换号

#### Scenario: 同一次启动内来源竞态
- **WHEN** 一次启动的准备阶段与实际启动之间账号来源发生 A→B→A 或其他变化
- **THEN** 按准备快照核对，不以旧准备启动；尚未启动 CLI 时静默按当前账号重新授权一次，再次变化才拒绝本次启动

#### Scenario: 模型目录读取期间换号
- **WHEN** 选型卡、任务模型菜单或设置页读取模型目录期间账号变化
- **THEN** 静默改读当前账号的目录一次，不显示换号错误；读取期间再次变化才报告失败

#### Scenario: 已保存设定遇到换号
- **WHEN** 项目或对话已保存完整设定（含关闭“调用前询问模型”后的直接派遣），之后换号
- **THEN** 当前账号目录仍提供该模型与强度时，设定继续有效、不弹出问题卡，启动时以当前账号实时授权；不提供时回退完整选型

#### Scenario: 原生续期无法保护当前账号
- **WHEN** OpenCode OAuth 等原生续期缺少版本条件写回，无法阻止退出或换号后恢复旧凭据
- **THEN** 保留真实登录状态，该模式返回空目录并拒绝执行；同一 CLI 自身 API 配置仍可按当前账号范围开放

## ADDED Requirements

### Requirement: 换号后自动续接
全部 CLI 的已有任务续聊、排队续聊、分支及子对话换模型遇到账号绑定变化时，Host SHALL 在当前 CLI 已登录自身账号、且原模型与强度经当前账号目录授权后，自动把任务改绑到当前账号并继续，MUST 不弹出确认。改绑 MUST 静默完成：时间线、过程区和错误中都 MUST 不出现换号或改绑说明，也不含凭据或账号标识。读取旧版本写入的记录时，其中的换号说明 SHALL 不再显示，旧的改接说明 SHALL 改用不提账号的文案。运行中的进程 MUST 不因换号被改绑；换号后发送的运行中引导消息 SHALL 转为排队，在下一轮于当前账号下发送。

#### Scenario: 换到另一账号后续聊
- **WHEN** 任务原绑定账号 A，用户已在该 CLI 改登账号 B，B 下原模型与强度可用，用户发送续聊
- **THEN** 不提示用户，任务改绑 B 并续接；时间线不出现换号说明

#### Scenario: 读取旧版本记录
- **WHEN** 任务记录中有旧版本写入的「账号已变更，已改用当前账号继续」或提及当前账号的改接说明
- **THEN** 时间线不显示前者，后者改为「原会话无法续接，已在新会话中继续」等不提账号的文案，附带记录条数保留

#### Scenario: 同一账号凭据格式变化
- **WHEN** 同一账号的原生凭据改写为新格式，导致绑定版本变化
- **THEN** 与换号同样自动改绑续接，不提示用户

#### Scenario: 排队中的续聊遇到换号
- **WHEN** 续聊排队期间用户换号
- **THEN** 出队时按当前账号重新授权后改绑执行，不因原绑定失效而丢弃排队消息

#### Scenario: 运行中换号并发送引导
- **WHEN** 本轮进程仍在运行，用户换号后发送引导消息
- **THEN** 该消息转为排队，本轮进程不受影响；下一轮在当前账号下发送

#### Scenario: 新账号下原模型不可用
- **WHEN** 换号后原模型或强度不在当前账号的授权目录中
- **THEN** 不改绑、不发送 prompt，按现有选型提示要求重新选择模型

### Requirement: 原生续接失败时自动改接
改绑后，Host SHALL 按 CLI 的跨账号续接方式表决定先尝试原生续接或直接改接；已确认无法续接或本地预检确认原生会话不在当前账号的会话存储中时 SHALL 直接改接，MUST 不先发起注定失败的原生续接。原生续接在产生任何回复或工具事件前失败时，Host SHALL 在当前账号下为同一任务建立新的原生会话，以插件保存的此前公开记录作为有界上下文先行发送，再发送本次消息；上下文 MUST 标明来自插件历史且不是新指令，MUST 不额外调用模型生成摘要。已产生回复、工具事件或成功的最终结果后，或本轮已向原生进程提交引导后的失败 MUST 照常报告，不改接；用户停止时 MUST 不改接。

#### Scenario: 原生续接被拒
- **WHEN** 改绑后原生续接返回错误，且尚未产生回复或工具事件
- **THEN** 自动在当前账号建立新会话，附带此前记录并发送本次消息；任务保持为同一个，时间线以「原会话无法续接，已在新会话中继续」说明已改接及附带的记录条数，不提账号

#### Scenario: 换号后分支首轮被拒
- **WHEN** 分支子任务的原生分支在首轮才创建（如 Claude 延迟分支），改绑后这一轮在产生回复或工具事件前失败
- **THEN** 按原生续接被拒同样改接一次，新会话附带分支截点前的记录；改接也未建立新会话时恢复待分支状态

#### Scenario: 已知无法续接
- **WHEN** 跨账号续接方式表标记该 CLI 无法跨账号续接，或预检发现原生会话不在当前账号的会话存储中
- **THEN** 不尝试原生续接，直接改接

#### Scenario: 已开始执行后失败
- **WHEN** 原生续接已产生回复或工具事件后失败
- **THEN** 报告本轮失败，不自动改接或重试，避免重复执行写操作

#### Scenario: 用户停止
- **WHEN** 用户在原生续接过程中停止任务
- **THEN** 等待进程范围清理确认后报告停止，不改接

#### Scenario: 历史超出上下文预算
- **WHEN** 插件保存的此前记录超过改接上下文预算
- **THEN** 保留首轮用户需求和最近的完整轮次，省略部分明确标注被省略的条数；单条记录超过上限时标注已截断

#### Scenario: 引导已提交
- **WHEN** 改绑后的续接轮次已向原生进程提交引导消息，之后在产生回复前失败
- **THEN** 报告本轮失败，不改接，避免新会话缺少已被接收的引导

### Requirement: 改接后的会话状态
改接后任务的 Token 用量 SHALL 累计此前各会话的会话级用量与新会话用量，任一方未报告的分项 MUST 保持未知而不按零计入；上下文占用 SHALL 只显示新会话自身的数值。改接也未建立新会话时，任务 SHALL 保留原会话、原有用量及待确认的改绑状态，下一轮仍可改接。改接成功后，从改接之前的消息创建原生分支 MUST 明确拒绝，不得把旧会话的截点套到新会话。

#### Scenario: 改接后的用量统计
- **WHEN** 任务改接到新会话后，新会话报告了会话级 Token 用量
- **THEN** 任务显示的 Token 用量为此前各会话与新会话之和；上下文占用为新会话自身的数值；改接未建立新会话时恢复原会话及其原有用量，不重复计入

#### Scenario: 改接失败后重试
- **WHEN** 改绑后原生续接与改接都在建立新会话前失败，用户随后再次发送
- **THEN** 仍先尝试原生续接，失败后再次改接；不会因绑定已更新而直接报告失败

#### Scenario: 从改接前的消息分支
- **WHEN** 任务已改接到新会话，用户从改接之前的消息创建分支
- **THEN** 明确拒绝并提示从改接之后的消息分支
