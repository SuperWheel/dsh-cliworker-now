## Why

用户切换 CLI 账号后（包括同一账号的凭据格式变化，如 issue #7 中 agy 1.4.x 去掉 `id_token`），旧任务全部无法续聊，只能新建任务，原有上下文中断。现行规格 `cli-account-isolation`「账号绑定和执行重检」规定账号改变 MUST 阻止任务、换号后要求新建任务；实现中有五处按绑定拦截：

- 续聊与排队续聊：`src/host/runtime.ts` 准备阶段 `previousBinding !== admitted` → `ACCOUNT_CHANGED`（约 2142 行）；
- 运行中引导：`runtime.ts` 约 522 行；
- 分支：`runtime.ts` 约 1250 行；
- 子对话查看与更换模型：`src/host/index.ts` 约 2145、2261 行；
- 无绑定的旧记录：`LEGACY_ACCOUNT_RECORD_NOTICE`（`runtime.ts` 约 1551、1355 行）。

各 CLI 的会话记录大多保存在本地，插件也保存了每个任务完整的公开历史，所以换号后续接在技术上可行。用户 2026-10-26 决定：无论同一账号还是不同账号，旧任务都自动续上、不打扰用户；原生续接失败时自动改为新会话并附带此前记录，并尽量提前避免失败。

## What Changes

- **换号自动续接**：续聊、排队续聊、分支、子对话换模型和旧记录续聊时，若当前 CLI 有已登录的自身账号，且任务原有模型与强度在当前账号下仍可用，Host 自动把任务改绑到当前账号继续，不弹确认。不显示任何换号说明（2026-10-26 用户要求全部 CLI 静默续接，原先的时间线说明已移除）。
- **仍会拦截的情形**（这些不属于「换号」）：
  - 当前没有可用的自身账号（已退出、未配置）；
  - 原模型或强度在新账号下不可用——按项目规则不得猜测或静默换模型，此时沿用现有选型提示；
  - 同一次启动内账号来源出现 A→B→A 竞态，仍按现有快照核对拒绝。
- **运行中换号**：本轮已在运行的进程不受影响；这时发送的引导消息改为排队，到下一轮在当前账号下发送，不注入旧账号进程。
- **原生续接失败自动改接**：原生续接在产生任何回复或工具事件前失败时，Host 自动在当前账号下为同一任务建立新的原生会话，把插件保存的此前对话记录（有界、确定性摘录，不额外调用模型）作为上下文发送，再发送本次消息。任务仍是侧栏中的同一个，时间线说明已改接。已产生事件后的失败照常报告，不自动重试，避免重复执行写操作。
- **提前避免失败**：
  - 按 CLI 维护「跨账号续接方式」表，由真实账号实验确定。已知无法续接的情形直接改接，不先试一次失败的原生续接；
  - 启动前做不调用模型的本地预检，例如原生会话是否存在于当前账号将使用的会话存储中（Hermes 会话随 `HERMES_HOME`）。
- 修改 `cli-account-isolation` 的「账号绑定和执行重检」；新增「换号后自动续接」「原生续接失败时自动改接」「改接后的会话状态」三项要求。

## 范围外

- 新派遣任务时已保存的项目级选型遇到换号：仍按现有规则核对，不在本变更内放宽。
- 不恢复、不复制旧账号凭据；不修改 CLI 原生账号文件；不把会话文件复制进用户原生账号目录。
- 不为改接生成模型摘要（避免额外费用与编造）。

## Capabilities

### Modified Capabilities

- `cli-account-isolation`：修改「账号绑定和执行重检」，新增「换号后自动续接」「原生续接失败时自动改接」「改接后的会话状态」。

## Impact

- Host：`src/host/runtime.ts`（准备阶段改绑、引导转排队、分支、改接）、`src/host/index.ts`（子对话目录与换模型的绑定核对）、`src/host/storage.ts`（绑定更新及改绑/改接事件、原会话 ID 记录）、新增跨账号续接方式表与历史摘录模块、各适配器的本地预检。
- Client：时间线说明文本、去掉旧记录的 `resumeBlockedReason` 拦截提示；需新增多语言词条。
- 协议：`WorkerSnapshot` 的 `resumeBlockedReason` 语义收窄；时间线新增改绑、改接两类说明项。
- 隐私：换号后，旧对话内容会发送给当前账号的服务商。这是用户的明确选择，需写进 README。
- 并行会话冲突：`src/host/index.ts` 正由 `no-ask-dispatch` 会话修改（`chooseDispatch`）；Client 多语言词条与 `cliworker-i18n` 分支存在同处追加。实施前需与这两处合并。
