# Proposal

## Why

Desktop 已识别 Qoder 登录，但原目录查询先 close 后 delete 空 ACP 会话触发 -32602。最终 preview 又确认原生目录初始化会改写共享 `.models/default` 缓存，且 CLI 捕获我们发出的 SIGTERM 后以 143 退出，被误判为查询失败。

隔离修复安装后，用户进一步要求优化设置页加载速度。通用目录链将 Qoder 的账号绑定变为重复原生进程启动：冷开设置需要 4 次账号查询及 1 次目录查询，显式刷新需要 3 次账号查询及 1 次目录查询。

## What Changes

- 目录改为同一已安装 CLI 的 SDK 控制元数据接口，一次读取完整模型与强度；实际任务继续使用 ACP，不增加 SDK runtime 依赖。
- 账号与目录查询共用只读认证和私有配置根，保留自身用户、项目设置及自定义模型来源，禁止查询改写共享账号、缓存和用户选型。
- 拒绝会在原项目自动迁移写回的旧设置；只接受确认 end_session、属于本次正常收尾的退出，并核验进程范围及临时文件清理。
- 在单次授权目录操作中合并账号和模型元数据，前后严格复读来源指纹；Qoder 冷目录与显式刷新直接使用自证授权的结果，热缓存仍查询当前绑定。目标冷开 5→2 个原生进程，刷新 4→1；不跨操作缓存登录身份，实际用时单独测量。
- 范围外：模型任务、登录/切换账号、迁移用户配置、其他 CLI。构建和 Desktop 由统一合并任务完成。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `qoder-cli`：补充元数据查询的配置隔离、原生结束回执和退出归属要求。

## Impact

- Host：`src/host/qoder-accounts.ts` 及授权目录、设置目录缓存的 Qoder 接入点；复用现有 SDK 控制传输，目录不再创建 ACP 会话。
- 验证：`tests/qoder-accounts.test.ts`、协议记录和私有只读探针证据。
- Client、共享协议、任务执行、安装入口和依赖不变；版本保留 v0.8.1。
