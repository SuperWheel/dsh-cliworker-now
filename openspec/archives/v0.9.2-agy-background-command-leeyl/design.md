# Design

## Context

ACP 运行器（`runNativeAcp`）在本轮结束后按以下顺序判定：原生轮次未以 `end_turn` 结束 → 失败；有工具未到 `completed`/`failed` → 失败「CLI 工具缺少终态」；停止 → 失败；其后才是拒绝结束、后台子 Agent 待核实、空正文待核实与工具结果汇总。

agy 1.5.x 的 `run_command` 有必填参数 `WaitMsBeforeAsync`：命令在该时长内没结束就转入后台，模型可在之后用 `command_status` 查看。转后台时 ACP 上没有任何更新；插件每轮结束都关闭 agy 进程，后台命令随之中止，下一轮加载时 agy 把它记为 `failed`、输出为空（2026-11-20 raw 证据见 proposal）。

## Goals / Non-Goals

- 目标：命令被 agy 转后台、本轮正常结束时，如实告诉主 Agent 与用户「命令未完成、已随会话中止、结果需核实」，而不是笼统的 CLI 错误，也不是成功。
- 非目标：让后台命令跑完（保持进程并自动跟进），以及 Antigravity stream 后备的同类情形。

## Decisions

### 1. 用工具入参作为识别信号，不读模型正文

agy 不给「已转后台」的状态值或输出；模型正文（「已启动后台……请稍候」）语言与措辞都不可靠。`run_command` 的 `WaitMsBeforeAsync` 是 agy 自己的 schema 参数，含义就是「超时转后台」，所以「带该参数、本轮 `end_turn` 时仍未终态」足以认定是 agy 转入后台，而不是协议丢失终态。

识别放在 CLI 适配层（`native-agy-acp.mjs` 的 `backgroundCommand`），ACP 运行器只提供默认关闭的钩子，其他 ACP CLI 不受影响。识别结果记在工具状态上（首次出现时判定），后续不带入参的更新也能保留。

### 2. 判待核实（UNCERTAIN），不判失败或成功

- 不是成功：用户要的结果（命令输出、全部写入）没有拿到。
- 不笼统判失败：CLI 本轮正常结束，问题是命令被中止，主 Agent 需要的是「命令没完成、去核查产物或要求前台重跑」，而不是排查 CLI 故障。待核实在任务卡显示「结果待核实」并保留本轮正文，与后台子 Agent 超时（`backgroundUnconfirmed`）一致。
- 说明文本：`Antigravity ACP 把命令转入后台后结束了本轮：命令在本轮结束时仍未完成，Worker 关闭会话后随之中止，没有结果。请核查实际产物；需要结果时续聊并要求在前台运行。命令：…`。「随之中止」有实证（ticks 文件停在转后台前、agy 下一轮自报 failed）。
- 工具行收尾为失败，输出写「已转入后台，本轮结束时仍未完成，随会话关闭中止」，不在 Worker 窗口留一个永远运行中的步骤；不计入工具失败汇总（整轮已是待核实）。

### 3. 边界保持原判

- 还有任何不可转后台的未终态工具 → 仍判「CLI 工具缺少终态」。
- 原生轮次不是 `end_turn`、用户停止、其他失败 → 按原规则，后台命令不改变结果。
- 同一轮内 agy 补发了完成更新 → 工具已终态，按原规则汇总。
- 与后台子 Agent 待核实同时出现时，两条说明合并。

## 未采用

- 保持进程并自动发送 `command_status` 跟进直到命令完成：会多次调用模型、让一轮无限延长，且用户本次只要求如实表达；如需可另立变更。
- 按正文关键词（「后台」「background」）识别：不可靠，也可能误把真正丢失终态的工具改判。

## Risks

- agy 改名或移除 `WaitMsBeforeAsync` 时识别失效，回到原来的「缺少终态」失败（不会误报成功）。
- 未来 agy 在进程关闭后让后台命令继续运行时，「随之中止」会不准确；届时需按新证据改说明。
