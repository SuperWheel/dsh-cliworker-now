## Why

「更新 CLI」页（`v0.8.10-cli-update-page-leeyl`）上线后，用自带更新器的 CLI 暴露出两个问题：

- **没有进度条。** 官方更新器在非终端下只输出阶段文字。用户看不出下载走到哪里、是不是已经卡住。
- **代理下会卡死。** 2026-11-14 Windows 实机经 Clash 代理更新，长下载在 18–153 MB 处断流，之后不再恢复。官方更新器都不续传，一直挂到插件的 10 分钟上限。任务 W 让插件接管了 Windows 上 Claude、Antigravity、OMP、TRAE CN 的下载，但这只是逐个 CLI 写死的代码，每加一个 CLI 都要重新适配一遍。

用户 2026-11-14 定下的方向：

1. 所有自带更新的 CLI 都显示进度条。
2. 同时保留官方渠道和插件接管。官方渠道不可用时，改用插件接管。
3. 插件接管做成一套统一的下载方式，各 CLI 只补一份小描述，以后只维护一个下载器。
4. 「改，但记住失败」：所有 CLI 都先走官方渠道，包括已经在 Windows 上验收过接管的四项。某个 CLI 的官方渠道在某台机器上失败后，之后一段时间（暂定 7 天）直接走接管，过期后再先试官方。

四份只读调研报告见 `.cache/cli-update-research/task-p/report-*.md`（不入 Git）。调研结论是：十个自带更新的 CLI 里，八个能观察到官方下载的真实字节进度（方法是轮询暂存文件，对照清单或 HEAD 给出的总量）；九个可以由插件接管，其中三个有附加条件；Hermes 两条路都拿不到字节进度。

## What Changes

- **官方优先，加看门狗。** 更新时先执行官方命令，同时按每个 CLI 的「官方进度探针」显示进度：
  - 能观察字节的 CLI，显示真实字节进度；
  - 只能观察阶段的 CLI，显示真实阶段文字和已用时间；
  - 两者都观察不到的，只显示阶段文字和已用时间。

  看门狗出现以下任一情况，就判定「官方渠道不可用」：非零退出、出现下载中断的特征文字、暂存文件停止增长、暂存文件大小回落、速度过低、预计会撞上官方的硬时限、超出总预算。
- **切换前先清理。** 判定不可用后，插件先发 TERM，再终止整个进程树。确认进程范围已经退出后，只删除本次运行产生的暂存文件，然后启动插件接管。
- **记住失败。** 官方渠道失败的记录按「CLI × 本机 × 安装布局」保存 7 天，记录期内直接走接管。以下情况不计为失败：用户取消、「已是最新」、锁冲突、插件接管自身失败。
- **统一下载器。** `download.ts` 改为接受一份工件描述，各 CLI 不再各写一段下载代码。描述包括：
  - 源地址列表；
  - 长度，取自清单或 HEAD；
  - 摘要，支持 sha256、sha512，以及响应头里的 md5；
  - 压缩方式：none、gzip 或 zstd，压缩时解压结果另做一次校验；
  - 预签名地址过期时重新取清单；
  - 多文件聚合进度。

  放置方式收敛为五类：
  - (a) 交官方本地入口；
  - (b) 原地替换单个可执行文件；
  - (c) 写版本文件再更新链接或启动器；
  - (d) 解压出唯一成员后替换；
  - (e) 不接管，只显示阶段。
- **迁移现有接管。** Windows 上的 Claude、Antigravity、OMP、TRAE CN，以及 macOS 上的 MiMo、OpenCode、OMP，改用统一描述，行为保持不变。Windows 这四项由「接管优先」改为「官方优先 + 失败记忆」。
- **新增接管**：Kimi（三平台）、Qoder 与 Qoder CN、MiMo（Windows 与 Linux）、Antigravity 与 Claude（macOS 与 Linux）、TRAE CN（macOS 与 Linux）、Codex 独立安装（macOS 与 Linux）。Grok（md5、长度、冒烟测试、平台签名）和 Pi 托管布局（环回 registry 交官方命令）也在本版接管（2026-11-14 用户定，见设计决定 7）。
- **Hermes 阶段进度条与慢速接管**：进度条按回执的 6 个真实阶段显示「第 N/6 步」，同时显示已用时间。2026-11-14 用户改定「hermes我允许接管，只要下的太慢就接管」：git 拉取慢时由插件分段预取并校验目标提交，再交回 `hermes update` 完成；依赖段停滞时停掉重跑（设计决定 8）。
- **前端**：
  - 进度区分「官方」和「插件接管」两种来源；
  - 多文件下载显示合计进度；
  - 拿不到字节时显示阶段文字和已用时间；
  - 修正长主机名单独换行的问题（13.5 的发现）。

## Out of Scope

- Homebrew、WinGet 等包管理器安装的进度条；npm 主包及本平台 optionalDependencies 下载、缓存预置和安装核验纳入决定 9。
- 桌面应用：ZCode、WorkBuddy CN 与 WorkBuddy 已由插件下载。
- 复用官方已下载的部分。第一版一律删除后从零下载，复用以后作为描述里的可选字段。
- OpenCode 在 Windows 上的接管，以及 CodeBuddy 原生更新的接管。这两项还没有调研，单列为后续调研项。
- 修改用户的 shell 配置、PATH 或 CLI 自身的自动更新设置。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `cli-update`：新增「官方优先与看门狗」「官方失败记忆」「统一下载器与工件描述」「接管放置方式」「官方进度显示」五项要求。下列现有行为保持不变：维护锁、版本核对、取消以进程范围退出为准、10 秒停滞续传与换源。

- **Host**：
  - `src/host/cli-management/`：`download.ts` 与 `download-sources.ts` 改为描述驱动；
  - 新增 `artifacts/`：各 CLI 描述与放置实现；
