# Design

## Context

Qoder 独立数字积分已有精确来源，本次只调整显示单位，不改变计费数字采集。Windows Hermes 原生日志与状态均显示网关已监听，但 Host 等待就绪直到超时；先用本次隔离网关复现并核对实际进程，再实现最小兼容修复。

## Goals / Non-Goals

**Goals:** 积分组件文案和单位一致；Hermes 正确识别本次原生网关；Windows 关联、无模型调用的网关及桌面证据可核查。

**Non-Goals:** 不混合积分与 token，不恢复缺失 token；不绕过鉴权或进程归属；不更换 CLI/账号/模型，不迁移历史、不做全量发布验收或 Mac 测试。

## Decisions

1. 在既有遥测可用性投影中增加可选积分计费单位。原生用量入口据此显示积分用量，数值有效时显示积分，缺失时显示积分未知；已保留的 token 桶不影响积分模块。普通 CLI 没有该元数据时保持既有行为。
2. Windows venv 的 python.exe 是启动器，实际网关位于其 Python 子进程；原生只写文件日志，没有 stdout 就绪行。旧版仅接受启动器 PID，因此拒绝了正确的原生状态。本次只对精确自有 Python 入口传入每次随机 nonce，入口在自身原生安装/账号核验完成后，经自有 stdout 管道报告当前 PID 并移除 nonce。Host 用该 PID 同时核对新鲜状态的 pid、writer_pid、精确监听地址，再请求鉴权能力；其他入口保持原有 PID/原生监听证明。磁盘 PID、错误 nonce、错误写入者、旧状态和错误端口均不足以发送鉴权秘密。
3. 保持原生权限、单次启动、不重试生成、取消及清理边界；启动和能力检查不提交 prompt。安装前保存原插件和顶层状态基线，确认无活动任务后只更新 Windows 正式 Desktop。

## Risks / Trade-offs

- 其他启动器版本 → 不猜进程，不接受无归属的回执；保留明确失败。
- 积分缺失 → 显示积分未知，不能按 token 或估算补积分。
- Windows 实际网关检查不代表模型生成、续聊或运行中取消已验收；保留边界。

## Migration Plan

不迁移账号或会话。构建隔离候选后执行 Windows 最小验收；失败可回退已备份同版本插件，原始数据不覆盖。
