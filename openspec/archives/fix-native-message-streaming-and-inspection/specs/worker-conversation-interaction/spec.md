# Spec Delta

## MODIFIED Requirements

### Requirement: 展示原生公开过程
过程区 SHALL 按 Harness 0.2.0-rc.2 原生展开体验展示已支持协议明确公开的思考摘要、计划和工具记录，复用可用原生组件与主题，保持折叠行、Markdown、工具树、结果及状态的格式、交互和键盘体验；注明来源与内容性质，摘要留在过程区而非最终回复。未公开、redacted、签名或加密内容 MUST 不被提取或当作可读思考，不生成替代内部推理。

#### Scenario: 公开摘要与重复快照
- **WHEN** 受支持 CLI 提供公开摘要事件及其完成快照
- **THEN** 过程区展示同一摘要的当前内容而不重复，最终正文和任务成功判定不受摘要影响

#### Scenario: 没有公开摘要
- **WHEN** CLI 仅提供工具、状态或没有可读摘要
- **THEN** 展示实际已有记录并简短说明未提供公开思考摘要，不显示伪造内容或把私密字段当摘要

#### Scenario: 思考和工具使用原生展开体验
- **WHEN** 用户展开有公开思考、计划或工具调用的 Worker 过程
- **THEN** 内容按真实顺序呈现，思考使用原生 Markdown 格式，工具调用和结果支持原生样式展开，状态和耗时继承本轮真实值；不保留替代原生内容的大段原始 JSON 卡片或英文内部状态标签

#### Scenario: 工具参数和结果不可信
- **WHEN** 原生工具返回命令、路径、结构化参数、终端结果、差异或 HTML 字符串
- **THEN** 按已确认类型使用安全的原生展示组件及折叠规则，未知内容作惰性文本或结构化数据，不执行 HTML，不捏造工具层级、文件差异或调用关系

#### Scenario: 中断、恢复和窄栏
- **WHEN** 过程流式更新、正常停止、重开历史或在窄侧栏及减少动态效果设置下查看
- **THEN** 保持真实展开/收起与滚动边界，停止不把未完成工具改写为成功，回复正文不被过程碎片或状态说明撑开，既有排队与独立引导行为不变
