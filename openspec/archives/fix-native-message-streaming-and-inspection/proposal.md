# Proposal

## Why

用户实际截图及最近 OpenCode 原生记录确认：同一消息的 22 个无 step 增量被折成独立回复，且新协议的上下文占用没有完整接入现有遥测。过程展开仍是插件自己的卡片，和 Harness 0.2.0-rc.2 原生思考/工具链及上下文菜单体验有明显差异；需要对全部 11 CLI 集中核对并修复。

## What Changes

- 对新原生协议统一使用真实消息、part、block 或原生连续段边界聚合增量与完成快照；修复 OpenCode/MiMo 和已识别的其他风险，不把不同回复、工具前后阶段或运行混为一条。
- 有原始协议边界可核查的既有碎片历史只读重新投影；保留原文与原始文件，不凭相邻时间猜测合并，不重跑用户任务。
- 审核 11 CLI 的真实用量、当前上下文及原生模型容量链路，修复字段丢失和口径错误，区分累计消耗与当前窗口占用。
- 按原生组件/样式和交互实现过程展开：公开思考的 Markdown、工具调用及结果、状态与链路；保持真实顺序、运行及停止状态，不制造未公开推理或工具调用。
- 复用 Harness 原生上下文菜单的视觉和交互，展示可核验的系统提示词、工具定义、对话消息等分类；未提供分类时明确未知，不能借用父会话数据或猜造比例。

## Capabilities

### New Capabilities

- `worker-context-inspection`: 所属 CLI 上下文占用、容量、来源和分项的可靠投影，以及与原生一致的查看体验与缺失边界。

### Modified Capabilities

- `worker-run-outcomes`: 原生流增量身份、快照去重、不同回复边界及有证据的历史恢复。
- `worker-conversation-interaction`: 公开过程/工具链的原生显示与交互，保留既有输入、排队、独立引导和消息操作规则。

## Impact

涉及独立 native runner、Host 原始数据读取/遥测/时间线、共享数据、Client 过程和统计菜单及相应测试；优先使用当前 Harness 已导出的组件，不修改宿主核心或全局 CLI。遵循 v0.7.10 开发约定，先定向回归与隔离预览，再于 Desktop 空闲时更新并核对实际 UI。真实验收沿已有保存选型授权，订阅/容量及 Windows 缺口明确保留；不发布或推送。
