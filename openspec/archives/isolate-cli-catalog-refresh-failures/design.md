# Design

## Context

见 proposal.md。设置与首次选型通过 Host 查询入口调用非模型元数据；实际任务另由 Runtime 管理完整进程范围。两者当前共用全局清理标记，无法隔离已知 CLI 的目录故障。

## Goals / Non-Goals

**Goals:** 在查询边界绑定确切 CLI，保持同 CLI 拒绝、跨 CLI 可用及冷恢复。排队中的同 CLI 不得绕过后续保护。

**Non-Goals:** 不忽略或伪造 waitForExit，不放宽任务进程管理，不自动修复旧未知标记，不改附件、登录协议或用户模型。

## Decisions

- 私有标记复用现有严格格式与 no-follow 读取，增加固定 CLI 文件名；未知旧标记仍按原全局语义读取。文件名只接受 CLI 枚举，无原始错误、账号、路径或凭据。
- Runtime 分开维护全局保护与 CLI 元数据保护；共用准入检查覆盖查询、账号、管理、提交和队列启动。已运行的其他 CLI 不被中断。
- Host 在目录、选型及路径查询的已知 CLI 边界记录作用域；Runtime 明确的账号/选型元数据准备同步使用同一边界。真实任务进程等待、工具/账号执行收尾仍保留全局保护。
- 普通异常不生成保护记录；缓存仅使失败 CLI 的结果失效，既有其他 CLI 目录和偏好不变。

## Risks / Trade-offs

- 元数据进程可能仍存活 → 保留对应 CLI 的持久拒绝及临时文件，不把异常当成功。
- 老记录无法归属 → 保留全局拒绝；现场恢复须完整退出并留存证据，不做自动迁移猜测。
- 同目录队列中的已拒绝任务阻塞其他 CLI → 准入和 drain 均处理该 CLI 的排队任务，不改变真实写任务串行约束。
- 真实账号过期或订阅不足 → 实机刷新可报告独立失败，不能宣称所有账号可用或所有模型调用成功。

## Migration Plan

先跑十二 CLI 隔离回归、类型检查和 preview；确认 Windows 无活动任务并备份后，以官方安装器更新同版本包。逐项刷新账号与目录，检查其他 CLI 的准入和持久文件。回退只还原备份插件，不覆盖账号或会话；新旧保护记录保留供核验。
