# Design

## Context

`OpenSettingsDialog` 卸载时丢弃账号 state；`CliSettings` 仅对当前 CLI 读取模型。Host 的 SettingsCatalogCache 已缓存完整目录，但命中前仍可能执行原生账号查询。Mac 已安装包与 Windows 使用相同实现，没有完整的“第一次打开后重用全部展示结果”。

## Goals / Non-Goals

改善重复打开和 CLI 切换，覆盖已启用 CLI；禁用项不探测。保留账号、目录各自失败状态和偏好。避免重新设计授权、账号存储或原生协议，不扩大付费验收。

## Decisions

1. Host 的现有 cliSettings JSON 增加可选版本元数据：随机宿主实例、项目摘要、每 CLI 来源版本、当前项目偏好及本 Host 是否保留该目录的账号绑定。读取不启动 CLI，不公开凭据；来源操作递增版本，Host 重启自然换代。同项目切换父会话时，Host 从本实例已核验目录为新父会话保留原账号绑定；若已丢失该证明，Client 失效该目录，不能让旧展示绕过保存时的账号比对。
2. Client 使用按 API 对象隔离且有项目数量上限的内存池。仅保存已完成的安全账号摘要及目录；源版本变化只清除对应 CLI。旧 Host 没有元数据时保留既有按页读取路径，不盲目复用缓存。
3. 预热沿用有界队列，同 CLI 的账号和目录顺序执行，总并发不超过两项；当前选中 CLI 优先。关闭取消未完成工作，已经完成的结果保留，迟到和跨 CLI 响应不能入缓存。重开恢复缓存并补充取消的缺项。
4. 登录/退出/账号终端、CLI 路径和开关变化使对应缓存失效；账号刷新后再查目录，模型刷新独立执行。轻量快照同步项目最新默认值；只有用户选择才保存偏好。
5. 展示摘要是最后确认的状态。外部 CLI 中的账号或路由变化仍通过显式刷新和保存/执行前原有实时重检确认；不以展示缓存作为当前认证、额度或执行权限。
6. 模型与强度的明确选择先进入内存草稿，不执行保存查询。当前 CLI 页面卸载（切换 CLI、角色页、关闭或外部卸载）时提交最新完整组合，不等待写入再导航。草稿与每 CLI 串行保存队列共享缓存范围；重开恢复未完成草稿，旧回执不覆盖新选择，未离页的新草稿不因旧请求结束而提前发送。关闭取消展示探测，但不取消已授权的偏好写入；成功或失败后释放请求控制器，无常驻计时器。错误保留到重开对应页，下一次离页可重试；账号、目录、路径或开关失效时取消该来源的旧草稿与写入，Host 仍实时核对账号与选型。

## Risks / Trade-offs

首次读取全部已启用 CLI 仍需原生查询预算；有界并发与取消防止进程风暴。缓存驻留于 Client/Gateway 生命周期，不跨 Host 重启信任旧账号。各原生系统钥匙串不能用统一文件时间戳替代，所以不建立猜测账号指纹或自动 TTL。

## Migration Plan

元数据为 JSON 可选字段，无磁盘迁移。Windows 用隔离回归、现有账号的只读设置加载和重复打开验收，确认后安装候选；Mac 不执行运行验收。失败可回退安装前插件备份。

轻量设置读取在发出时记录 Client 保存回执代次。若读取结果迟于其后完成的保存回执返回，保留该回执与新选择，不让旧快照覆盖；保存完成后发起的新读取仍接受外部最新默认值。该代次只用于本地响应排序，不表示 Host 授权或账号来源。
