# Spec Delta

## Purpose

为全部 CLI 提供可查看、可修正的本机入口设置，减少重复发现，同时避免陈旧路径或旧请求覆盖用户选择。

## ADDED Requirements

### Requirement: 本机 CLI 路径保存与复用
Host SHALL 对每个活跃 CLI 的首次成功自动识别保存绝对路径及来源，按机器、平台、CLI 隔离，以私有文件持久化。后续查询、登录、模型目录及任务 SHALL 优先复用已保存路径并继续核验原生入口。UI 手动路径 MUST 优先于部署配置，部署显式路径 MUST 优先于自动缓存，账号、模型偏好与会话不得被路径保存覆盖。

#### Scenario: 首次发现与重启
- **WHEN** 首次自动识别到有效 CLI 后重启插件或切换项目
- **THEN** 复用同一台机器及平台已保存的入口，无需重复 metadata 搜索

#### Scenario: 自动缓存失效
- **WHEN** 自动保存的文件因卸载或移动已不存在
- **THEN** 重新运行该 CLI 的发现逻辑并保存新的有效入口；未找到时明确报错

#### Scenario: 手动路径失效
- **WHEN** 用户手动指定的绝对路径不存在或不是可用 CLI
- **THEN** 保留该手动路径并报告错误，不静默采用自动或部署路径

### Requirement: 独立且默认折叠的高级设置
每个 CLI 设置页 SHALL 在“项目默认设置”之外设置同级“高级设置”大标题，默认折叠。“CLI 路径管理” MUST 位于展开后的高级设置中，自动预填已发现路径并展示来源；未发现时留空，允许用户输入完整文件路径并点击“刷新”，校验、保存并更新 CLI 状态。路径设置 SHALL 为本机跨项目共享，不归入项目模型和思考强度设置。

#### Scenario: 页面初始状态
- **WHEN** 首次打开或切换 CLI 设置页
- **THEN** 高级设置保持折叠，展开后显示当前 CLI 自身路径，不显示其他 CLI 或其他平台的保存路径

#### Scenario: 手动刷新
- **WHEN** 用户输入绝对 CLI 路径并点击刷新
- **THEN** 保存手动来源并重新校验账号/模型状态，校验失败保留输入且展示错误，不显示旧的成功状态

#### Scenario: 恢复自动识别
- **WHEN** 用户点击恢复自动识别
- **THEN** 清除 UI 手动来源及定位缓存并重新发现；部署显式配置仍保留，失败时明确提示未找到

### Requirement: 路径变更并发与安全边界
路径更新 SHALL 拒绝同 CLI 的运行/排队任务和账号终端占用；自动发现结果 MUST 不覆盖之后的手动更新。保存文件 SHALL 使用既有私有目录和原子写入规则，拒绝损坏或重定向的配置文件。Client 请求 MUST 随页面关闭/切换取消，迟到结果不得覆盖新输入；路径不得作为 shell 命令拼接执行。

#### Scenario: 用户修改期间的旧探测
- **WHEN** 自动探测或 UI 读取完成前用户已提交新路径或编辑输入
- **THEN** 旧结果不覆盖保存的新选择或当前输入，不启动旧路径任务

#### Scenario: 使用中修改
- **WHEN** 相应 CLI 有运行/排队任务或账号终端
- **THEN** 路径变更被拒绝并保留原设置，避免运行中切换入口

#### Scenario: 私有与跨平台
- **WHEN** 读取其他机器/平台的数据或损坏/链接配置
- **THEN** 不将其路径作为本机入口使用；损坏配置报告错误，不覆盖账号与其他 CLI 数据
