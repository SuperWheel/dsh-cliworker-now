## MODIFIED Requirements

### Requirement: 询问并发和取消隔离
相同主对话、项目和 CLI 的并发派遣 SHALL 顺序共享已确认结果，不重复询问；不同主对话 SHALL 独立确认。已有本对话设定、无需询问的并发派遣 MUST NOT 在询问顺序中逐个等待模型目录检查，SHALL 并行完成检查；目录不再提供该设定时 SHALL 重新排队，按顺序询问。未询问问题的派遣以本次新读取的目录为检查，询问过问题的派遣 MUST 在写入设定前重新读取目录；提交前的授权检查 MUST 保留。等待者取消 MUST 及时结束且不取消其他调用的询问；询问发起者取消后其他等待者 SHALL 能重新取得选择机会。插件关闭 MUST 清理等待和询问状态。

#### Scenario: 同对话并发
- **WHEN** 同一对话在首次选型未完成时再次触发相同 CLI
- **THEN** 同时仅一套问题，完成后两个请求均使用同一完整设定

#### Scenario: 已确认设定并行派遣
- **WHEN** 同一对话已有有效设定，主 Agent 同时派遣多个相同 CLI 任务
- **THEN** 各派遣同时检查模型目录、均不询问，任务按并发上限同时进入运行，而非按目录读取耗时逐个创建

#### Scenario: 已确认设定失效
- **WHEN** 同一对话已有设定，但当前目录不再提供该模型或强度，且多个派遣同时到达
- **THEN** 仅出现一套重新选择问题，完成后这些派遣使用同一新设定

#### Scenario: 不同对话并发
- **WHEN** 不同主对话同时触发同一项目和 CLI
- **THEN** 各自完成自己的选型或沿用确认，不共享未确认答案

#### Scenario: 等待或选择取消
- **WHEN** 某等待者或当前问题发起者取消
- **THEN** 对应调用结束，未完成设定不写入，其他调用可以继续，等待状态最终清理
