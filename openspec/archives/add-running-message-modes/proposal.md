# Proposal

## Why

当前 `panel.tsx` 与 `runtime.ts` 将所有运行中消息送入轮后队列，用户无法选择原生引导或提前处理紧急消息。高级设置已有统一折叠布局，可按项目与 CLI 保存发送偏好。

## What Changes

- 在各 CLI 高级设置增加“运行中发送”下拉框，选项文字为“引导、插队、排队”；有已接入原生引导能力的 CLI 默认引导，其余默认排队且禁用引导选项。
- 引导将消息交给当前 CLI 原生 steer 通道；插队先停止当前轮并确认进程清理，再沿原会话优先发送；排队沿用现有正常完成后发送行为。
- 待发送卡片增加“插队”操作，所选消息提前，其他待发送消息保留；标题下增加分隔线，列表可折叠并有展开/收起动效。继续保持输入框单一动作按钮。
- 保存失败、原生拒绝、过期轮次、停止竞争或清理不确定均明确反馈，不静默换模式或丢弃文本。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `worker-conversation-interaction`：按项目与 CLI 选择运行中发送方式，原生引导与队列插队，保护现有单按钮、草稿和生命周期约束。

## Impact

影响共享发送方式协议、Host 设置持久化和运行时、Pi/OMP 原生桥接、Gateway 入口、Client 高级设置及队列卡片。复用现有 argv、权限、账号和清理机制，不修改 Harness 核心、不增加依赖、不升级版本。最小验收包括关联回归、必要类型检查、隔离构建和模拟界面；真实模型、Windows 实机、Desktop 安装与全量发布验收不在本轮范围。
