## MODIFIED Requirements

### Requirement: 原生输入提交规则
可续聊的输入框 SHALL 按 Harness 0.2.0-rc.2 的 Enter、Shift 和修饰键规则提交或换行，并保护组合输入及原生确认后的短窗口，重复按键不得重复发送。空闲时提交 SHALL 经过现有 Worker 续聊入口；运行时 SHALL 按当前项目与 CLI 的运行中发送偏好处理，允许继续编辑输入。输入框右下角 SHALL 仅有一个动作按钮：运行中无正文时为停止，有待发正文时为发送，停止中继续显示禁用的停止。保持空白、断连、权限和草稿保留规则。

#### Scenario: 发送与换行
- **WHEN** 可续聊 Worker 的输入框含有文本，用户按普通 Enter 或原生支持的 Ctrl/Cmd+Enter
- **THEN** 空闲时提交一次，运行时按选择的引导、插队或排队处理；Shift+Enter 保留换行，原生不支持的组合键不提交

#### Scenario: 中文输入法与长按
- **WHEN** 按键处于组合输入、原生确认后的保护窗口或为重复键事件
- **THEN** 不发送消息；组合输入完成后正常 Enter 可以提交

#### Scenario: 不可续聊与失败
- **WHEN** Worker 断连、停止中、空闲但缺少会话、文本为空或提交失败
- **THEN** 不通过快捷键绕过限制，未成功提交的草稿保留，不向主聊天发送文本

### Requirement: 当前轮结束后自动发送
以排队方式提交的消息 SHALL 按顺序保存在所属 Worker 的待发送队列，可查看、取消和插队；标题下有分隔线，列表支持带动效折叠，关闭侧栏或折叠不影响等待。仅在上一轮正常完成且进程范围清理确认后 SHALL 沿原生会话逐条执行，并重新验证当前权限、账号、模型及强度。队列不是即时引导，不得显示为已送达 CLI。

#### Scenario: 多条消息与关闭侧栏
- **WHEN** 用户在当前轮期间排队两条消息并关闭侧栏
- **THEN** 显示为待发送，Host 仍按先后顺序在每轮正常完成后启动下一条，不并发运行同一会话

#### Scenario: 异常与停止
- **WHEN** 前轮失败、结果待核实、停止、缺少会话或清理未确认
- **THEN** 保留未发送消息并暂停自动执行，明确显示原因，必须经用户再次操作才允许继续；用户本次明确发起的插队可在停止清理确认后发送所选消息

#### Scenario: 重启与取消
- **WHEN** Host 重启或用户取消待发送消息
- **THEN** 重启恢复未发送文本但不自动执行；取消成功的消息不再执行，已开始的消息只能使用停止操作

#### Scenario: 归属与重复请求
- **WHEN** 请求属于其他父会话、过期运行或是同一提交的重复请求
- **THEN** 拒绝越权和过期动作，重复请求不产生重复轮次；派发和停止竞争时不能绕过停止

#### Scenario: 折叠待发送列表
- **WHEN** 用户展开或收起待发送列表
- **THEN** 保留标题与数量，列表高度和透明度平滑过渡；收起后内部操作不可键盘聚焦，减少动态效果偏好下无过渡，实际队列继续按原规则执行

## ADDED Requirements

### Requirement: 运行中发送偏好
高级设置 SHALL 通过原生下拉框提供“引导、插队、排队”，按项目与 CLI 独立保存，选后自动保存。已接入原生引导的 CLI 默认引导，其余默认排队且禁用引导；显式保存优先于默认。打开设置 MUST 不启动 CLI 或写入偏好，保存失败显示错误并允许重试，现有设置与历史数据兼容。

#### Scenario: 能力默认与持久化
- **WHEN** 用户首次打开 Pi 或 OMP 的高级设置，或其他不支持引导的 CLI 设置
- **THEN** 分别显示引导或排队，保存插队后重新打开同一项目与 CLI 保持插队，其他项目与 CLI 不受影响

#### Scenario: 不支持和失败
- **WHEN** 当前通路不支持原生引导或保存失败
- **THEN** 不允许选用不支持的引导，保存失败保留选择及错误；不会静默执行其他模式

### Requirement: 原生运行中引导
引导 SHALL 将消息交给当前原生 CLI 运行，并在明确接收回执后显示为已提交的用户消息，不停止或重启当前轮；同一请求不重复投递。通路尚未准备、已结束、原生拒绝或确认超时 MUST 反馈真实状态并保留草稿，不静默改为排队或插队。接收回执不代表模型已执行指令。

#### Scenario: 原生接收
- **WHEN** Pi 或 OMP 的当前运行接受引导消息
- **THEN** 当前运行和原生会话保持不变，消息按原生语义处理，重复同一提交只显示一次

#### Scenario: 权限与运行竞争
- **WHEN** 引导请求来自其他父会话、过期轮次、已停止任务，或当前权限及账号校验不通过
- **THEN** 拒绝投递并保留草稿，不发送给其他运行或账号

### Requirement: 显式插队发送
插队 SHALL 将新消息或所选待发送卡片优先送入原会话下一轮。当前运行须先停止并确认进程范围退出，然后重新验证权限、账号及选型。其余待发消息保留，原已暂停队列不被无意恢复。同一 Worker 的插队请求 MUST 串行；显式停止、取消、过期请求及清理不确定不得造成额外派遣或丢消息。

#### Scenario: 队列卡片插队
- **WHEN** 用户对第二条待发消息选择插队
- **THEN** 当前轮停止并清理后先执行该消息，其余消息文本保留且顺序不变；不会同时运行两轮

#### Scenario: 插队中停止或失败
- **WHEN** 插队等待清理期间用户停止或取消所选消息，或清理和再次授权失败
- **THEN** 不启动该消息，仍未发送的文本保留或按明确取消移除，显示原因并允许用户重新操作
