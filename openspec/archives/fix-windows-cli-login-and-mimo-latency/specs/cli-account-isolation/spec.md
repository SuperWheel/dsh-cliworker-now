# Spec Delta

## ADDED Requirements

### Requirement: 元数据优化不复活账号
能力元数据缓存 SHALL 不保存或复活可执行认证；每次授权与任务边界 MUST 从当前原生自身来源重读账号和配置，换号、退出、撤销以及路由变化立即使旧绑定不可用。

#### Scenario: 缓存命中但账号退出
- **WHEN** MiMo 能力缓存仍有效而当前自身账号已删除或更换
- **THEN** 拒绝旧任务或要求重新选择，不从能力缓存恢复凭据，不跳过绑定与权限重检

#### Scenario: 并发取消与失败
- **WHEN** 重复查询中某一调用取消或能力查询失败
- **THEN** 取消自身等待和受管资源，失败不发布半成品目录，不影响其他请求的账号核对

### Requirement: Antigravity Windows 原生账号来源
Windows 上 Antigravity 账号核对 SHALL 使用交互式用户会话中原生 Credential Manager 的固定凭据目标，且只向插件返回状态、稳定主体摘要和安全账号标签。凭据正文 MUST 不进入 Gateway、日志或持久化缓存。

#### Scenario: 浏览器授权与终端兑换均已完成
- **WHEN** 用户在 Windows 原生终端完成 OAuth 兑换，账号保存在 Credential Manager 而无明文令牌文件
- **THEN** Desktop 能识别同一账号并绑定目录与任务；SSH 会话无法访问凭据时报告来源不可用，不误报桌面账号退出

#### Scenario: 原生凭据不可读或格式未知
- **WHEN** 原生账号存储不可访问、格式未知或当前主体已改变
- **THEN** 返回安全诊断并拒绝旧绑定，不输出凭据，不从其他账号来源补齐


### Requirement: Hermes 同源 OAuth 自动续期
macOS 与 Windows SHALL 共用 Hermes Nous 续期逻辑。有效短期访问令牌不触发刷新；同一明确账号的访问令牌临近过期或已过期且有原生刷新凭据时，插件 SHALL 在账号、目录及任务准入检查中允许一次有界非交互原生续期，随后重读原生状态。刷新 MUST 保持账号来源、主体、组织、客户端及路由，且不得登录另一账号、创建匿名身份、打开浏览器或调用模型。

#### Scenario: 短期令牌到期而登录仍可续期
- **WHEN** 自身 Nous 访问令牌已到期或低于原生可用 TTL，原生刷新凭据存在且来源及主体可确认
- **THEN** 在原生锁内刷新并立即保存轮换凭据，再核对同一主体，账号与模型检查可继续；令牌轮换不使原有同主体绑定失效

#### Scenario: 健康令牌与并发检查
- **WHEN** 令牌仍有足够有效期，或多个同账号状态/目录/派遣检查同时到达
- **THEN** 健康令牌仅做本地读取；需要续期时同目录不并发轮换，取消和账号操作等待进程范围清理，不在退出账号后写回旧登录

#### Scenario: 原生共享状态与凭据池
- **WHEN** 刷新涉及原生共享状态或既有同源凭据池行
- **THEN** 只接受同主体同路由的可核验原生状态并按原生锁序保持轮换一致；不同主体、来源不明、已删除账号或不支持契约明确拒绝，不导入外部凭据，不清除禁用、额度、冷却或用户元数据

#### Scenario: 临时失败与必须重登
- **WHEN** 原生续期遇到网络/超时/临时服务故障，或明确返回终止鉴权错误/缺失刷新凭据
- **THEN** 前者显示暂时无法续期并可重试，后者才要求重新登录；保留现有凭据，不泄露令牌、原始授权响应或 URL
