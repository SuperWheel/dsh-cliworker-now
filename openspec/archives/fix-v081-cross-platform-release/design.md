# Design

## Context

见 proposal。根目录现存 SDK 与当前锁定的 0.2.1-rc.2 不同，旧图通过不能替代新图。当前开发 Desktop 已装四包扩展，但公开 bundle 仅注册插件自身。Windows 的 POSIX mode 不表达 NTFS DACL；新版官方 node-pty 使用自带 OpenConsole，旧逻辑仅接受系统 conhost。

## Goals / Non-Goals

Goals：让同一公开包在两平台按文档安装后可用；修复已复现兼容问题，保存失败与重验记录。Non-Goals：不迁移其他产品账号，不修改宿主应用文件，不解除模型/订阅限制，不把所有第三方服务均已验证作为未有证据的声明。

## Decisions

- 四包保留原生模块身份和嵌套清单，通过官方 bundle 的相对文件入口交付。使用经真实 Loader 验证的覆盖层语义，卸载由宿主撤回该层；已有额外覆盖不能可靠合并时拒绝而不破坏配置。源码、预构建、manifest 与许可一起可复核，不依赖安装时联网构建宿主。
- 仅使用公开的接口能力检查，实际验证版本写入报告，不新增人为宿主版本白名单。发布资产按对应官方源码构建；未知未来接口仍保留能力失败。
- Windows 文件保护以实际当前身份与原生访问控制证明私有性；POSIX 保留原 UID/mode 规则。读前身份、读后同一文件和目录检查不撤除；失败返回未知。不能将 Windows chmod 的模拟结果作为放行依据。
- ConPTY 优先使用 SDK 明确支持的可核验实现；如接纳包内控制台，仅接受实际固定依赖路径和原有进程归属组合，禁止仅按名字扩白名单。
- 正式 Electron Desktop 的 `node-pty/package.json` 位于 `app.asar`，实际控制台与 DLL 位于 `app.asar.unpacked`，PowerShell 不能把逻辑清单当作普通文件读取。仅该当前 Host 可验证的固定布局启用一次 nonce 握手：所有者从 HostImage 和实际控制台路径确定精确 archive/root，并持有物理 archive 的只读防替换句柄；Host 用 Electron 只读 fs 验证逻辑清单，同时用 original-fs 验证物理路径无链接。回执须匹配 nonce、archive、root、包名和固定版本；随后仍验证既有 helper/DLL 摘要、原始来源副本、控制台父 PID、创建时间和 Job 完整退出。其他布局及其他 Host 不从该握手获得授权。
- 测试夹具适配真实模块导出和必要服务；平台不同用各自可观察结果验收，不为通过而删除安全或生命周期断言。最终全量在固定源码和实际 0.2.1-rc.2 运行图执行。
- Windows Qoder 按实际安装的 `~/.qoder/bin/qodercli/qodercli.exe` 和官方 `@qoder-ai/qodercli` 包声明的 `qodercli`/`qoder` bin 发现；原生 PE 与 npm 包身份分别校验。独立 `qodercli` PATH 优先于可分发到 IDE 的 `qoder` 别名，只有独立命令缺失才兼容旧别名，并将已证明的 npm dispatcher 归一到实际 qodercli bin；所有自动来源（含缓存）须通过独立 PE 或官方 package bin 身份门，IDE/未知入口拒绝；显式或损坏入口不兜底，不枚举 IDE 或任意安装目录。
- Qoder 元数据完成必须有成功的原生控制回执、`end_session` 确认和完整范围退出。官方 Windows SDK 通过 `TerminateJobObject(job, 1)` 主动回收范围，只有本方正常收尾且未取消时接纳该 `1/null` 回执；不将自然退出 1、协议失败、取消或未确认退出改作成功。实机账号及 17 个模型控制目录已在旧逻辑下成功返回，但被收尾误拒；修复后另保留原生复验，不以本地文件存在宣称登录成功。
- Codex 恢复时的累计用量未增长不能证明本轮已经结算为零；不生成此类派生零回执，读取旧记录时只排除有明确未结算派生标记的同轮零快照。保留明确原生结算零、其他 CLI 零值和已知累计用量，不迁移或修改用户原始历史。
- Hermes 输入明确含缓存时直接以该输入作为分母，已知缓存读取即可计算命中率；未缓存输入仍须完整缓存类别才能组成分母，未知写入不补零，报告口径不明仍保留未知。

## Risks / Trade-offs


- 已有 profile 额外覆盖可能优先于 bundle → 只读预检，必要时对本插件已知旧项做带备份的精确迁移，其他项不猜测。
- 四包源码映射可能含机器路径 → 发布前规范化已识别构建路径并重新计算完整摘要，逐文件验证无私人路径。
- Windows 文件和终端差异可能是实际保护拒绝 → 区分夹具错误与生产兼容缺口，两者分别给实机证据。

## Migration Plan

先冻结隔离候选，修复并分别定向验证；再固定最终候选，运行两端全量和干净 profile 安装/卸载及原生界面，正式 Desktop 更新前确认空闲并备份，复查历史/账号保留。用户已授权通过后提交 GitHub/npm；任一发布门槛失败不发布。市场 npm 元数据自动同步，固定 tarball 备用更新另记录官方入口。已授权的 npm 官方登录使用本次新建私有配置，不复用被拒绝的旧凭据。
