## Context

见 proposal.md 的根因。所有原生运行器的公开事件共用 `createNativeIO.output()`；其帧上限包含 JSON 包装与换行。当前工作区已有其他修改，必须保留。

## Goals / Non-Goals

- 保证可容纳最小摘要时，超大非 assistant 展示事件不导致整轮失败。
- 不改变 CLI 参数、工具执行、审批、进程生命周期或终态规则，不把展示截断当作 CLI 成功。

## Decisions

- 第一层复用 `cutBytes` 将 text 与 toolCall 的字符串字段截至 4096 字节，保留普通调用身份及数值元数据。只裁剪 command 会遗漏其他可变长字符串。
- 第二层使用 kind/step/state/text/truncated 白名单，逐次减半文本字节预算，并用现有 `write()` 检查完整 JSON 行；这样覆盖控制字符转义膨胀及小帧配置，不依赖估算包装长度。极小预算下移除可选 step/state，再尝试空文本最小摘要。
- assistant 保持严格帧检查：其文本参与最终回复累积，静默摘要会使流式回复与终态正文不一致；回复分片属独立协议变更。
- 不新增持久化字段或迁移。完整工具命令仍由原生 CLI 自己处理；界面摘要带 truncated。

## Risks / Trade-offs

- 超长调用 ID 被截断可能失去完整身份 → 常规长度原样保留，步骤编号继续用于时间线聚合；更强降级明确丢弃 toolCall。
- 极小预算可能只显示空文本截断标记 → 优先保留步骤和状态，最小摘要也放不下才沿用帧错误。
- 图片 base64 仍占用展示预算 → 仅报告后续改为真实 savedPath 与字节大小摘要的范围，本次不实施。

## Migration Plan

本次仅源码、测试和文档交付，不构建或更新运行中的 Desktop。回退仅撤回本次 output() 分支及关联新增内容，不覆盖工作区其他修改。
