# Proposal

## Why

现有 Worker 使用自绘对话和独立存储，无法直接继承 Harness 原生对话体验。用户已确认保留 CLI Agent 与现有通信协议，接入真实 Harness 会话、原生界面和受控工具桥，模型生成不回退至 DSH API。

## What Changes

- 2026-10-18 继续接入 Antigravity：参考 codex-host 的本轮附加目录和原生 Hook 生命周期、Codingns4DSH 的 AGY 输入及权限边界，验证临时 `.agents/mcp_config.json` 与精确桥工具 Hook。配置仅写插件私有运行目录，不修改用户全局或项目设置，不加入跳过全部权限的参数；保留原生显式规则和 Harness 真实审批。Mac/Windows 共用实现，桌面最小验收仍仅在 Windows。

- 2026-10-18 用户授权参考 Codingns4DSH 补齐附件输入，复用既有 Harness Skill/MCP 桥逐 CLI 核对；macOS/Windows 共用适配，桌面验收仅在 Windows 进行。附件沿宿主公开存储解析并转换为原生输入，重试身份包含附件，运行中附件留在原生队列。最小验收区分协议模拟、安装版无模型核验及真实 Desktop，不以可配置代替执行成功。

- 2026-10-17 用户手动升级至 DSH 0.2.1-rc.2 后，重新核对实际 SDK、完整原生侧栏四包及安装协议。按用户在「调整功能」确认并要求同步的最终方案，保留 DSH peer 声明但不以宿主版本号拒绝加载；开发 SDK 精确固定用于可复现构建，运行时继续检查必需接口，发布记录只列实际验收版本。原生四包扩展仍按对应官方源码与哈希校验，不能跨版本强行套补丁。

- 2026-10-17 后续五张真实截图：修复同一 CLI 会话续聊时累计用量/上下文被初始化零覆盖，补 Grok 原生状态订阅和 ZCode 精确请求分类；核对 OMP/AGY 真实请求公开摘要设置及最终持久记录。数据必须经实际协议/请求身份验证，原生整视图和原有权限保持。

- 2026-10-17 验收截图追加：所有 CLI 原生上下文弹层不展示“分类来源／数据来源”及重复英文分类项；只保留原生三类明细、进度与缺值原因，底层来源字段继续用于校验。

- 2026-10-17 用户要求其余十 CLI 对齐目前 Hermes 的完整原生侧栏效果；复查所有协议到原生视图的数据链，修复漏接事件和缺失/迟到快照处理，保留各 CLI 未公开字段的真实限制。

- 2026-10-17 Hermes-2 截图要求完整核查上下文统计：共享原生 ContextMeter 的小占用不能被整数格式化画成零；底部、弹层和图形使用同一已验证数值。补齐可证明的 CLI 分类来源，分类缺失时在原生明细中明确未知，不用只显示来源替代分类，也不伪造历史。

- 2026-10-17 用户进一步授权参考两个项目及其他相关官方实现，补齐剩余数据接口并在 DeepSeek Harness 安装测试。本阶段优先利用当前 CLI 的公开查询、官方生命周期观察扩展及精确只读持久化数据补齐账单/缓存/上下文/公开过程；不因现有 transport 没字段就直接认定整个 CLI 不支持。完成隔离验收后于空闲窗口安装候选并验证真实 Desktop，区分模型实测、模拟和上游限制。

- 2026-10-16 Hermes 实际旧 stream-json 会话暴露统计口径与数据接线缺口；用户追加要求由 GPT-6.1-sol 复查其余 10 个 CLI 并修复遗漏。逐 CLI 同时核对保留的旧协议与当前原生协议，覆盖累计用量/缓存、上下文、单轮用量、公开过程和引导；完整原生视图复用不等于这些后端数据均已接通。
- 2026-10-16 用户确认进一步收敛范围：CLI Worker 父级管理页面、导航和侧栏顶部保持原样，仅单个子 Agent 的对话区域直接挂载 DSH 官方完整侧栏对话入口；正文、输入、队列与状态逻辑由同一个原生视图管理，插件后端负责 CLI 数据与动作适配。
- 新增真实直接子会话绑定和原生生成流适配，在 CLI Worker 右侧栏内通过宿主公开渲染契约复用 DSH 原生对话内容、消息、输入、排队、队列编辑和停止交互；主页面保留父会话，不以全页导航代替侧栏。顶部沿用原 CLI Worker 的返回、标题和任务操作，不加入原生主页面包头、面包屑或对话/轨迹页签。Host 层桥接实际子会话执行。
- 子 Agent 保持所属主对话和 `origin: subagent`，不进入普通会话列表；CLI Worker 面板保留任务管理与旧历史。原生输入按逐消息持久回执去重，包括合批后冷恢复的单条重试。
- 原生输入区的模型与强度按既有 CLI 目录和 Worker 保存逻辑可选，权限选择按宿主边界与 CLI 原生保护执行；运行统计、用量/缓存和上下文三模块使用原生组件，缺失值遵循原生呈现且不伪造。
- 增加按 Worker/run 隔离的 DSH 工具、已配置 MCP 与 skill 桥，能力不足时禁用相关操作并悬停说明。
- 保留账号、原生会话、停止清理、普通排队与独立引导边界；原生控件无法忠实适配时不得谎报支持。
- 迁移版为 v0.8.1；迁移前 v0.7.10 的源码及构建已独立备份并校验。

## Capabilities

### New Capabilities

- `native-cli-conversations`: 真实 Harness 会话绑定、CLI 生成路由、原生界面及能力降级。
- `harness-cli-tool-bridge`: 受控工具、技能与资源转发及 CLI 临时接入。

### Modified Capabilities

- `development-workflow`: 用户明确将本次开发版本从已备份的 v0.7.10 调整为 v0.8.1，保持正式提交前冻结。

## Impact

影响 Host 生命周期、Gateway、Client 原生侧栏渲染、CLI 临时配置、相关测试与文档。继续使用 rc.2，不升级宿主、不覆盖历史记录、凭据或用户 skill。参考 Codingns4DSH 与 CodexHost 的接入机制，自主实现；此前局部页面和冻结协议预览是历史证据，当前完整侧栏、真实账号、平台和辅助生成功能必须以对应实际验收记录为准。

### 2026-10-17 七张真实截图回归

用户实际运行出现ZCode RPC断开、Grok参数错误；Pi/AGY/OMP过程不可展开；Pi/MiMo/OpenCode上下文三分类未知。第15阶段协议与模拟视图通过不能替代这些实际运行的回归。续用本change逐个追踪精确原始事件、实际版本接口、官方只读请求组成及显示投影，修复已证实缺口并按保存选型隔离验证。用户历史不重写，所有来源说明继续不显示；不改父级管理、原生整视图与CLI权限/模型边界。
