# Design

### 2026-10-17 连续多轮与协议订阅遗漏

同一会话下一轮开始前保留已证实累计用量及最近上下文快照；初始化空数据不是结算零。新请求明确未知仍清对应字段，CLI/session/model变化不得借旧上下文。Grok仅自身开启官方statusLine能力并接收当前session原生状态，容量随精确所选模型事件更新；不将输入账单当上下文。ZCode分类以该Worker专属storage的精确model-io main_turn完整请求为输入，用已安装CLI公开估算规则独立估各section，只向遥测发布数字。读历史不改raw或DB，retention/delta/身份冲突均拒绝。OMP/AGY先验证真实安装的摘要请求默认与事件字段；不凭推理token、签名或状态构造过程。当前Desktop可能已升级，安装前重新读取版本及扩展契约，保留其他插件和用户配置。

## Context

参见 proposal。当前 WorkerRuntime、WorkerStorage、原生 runner 和停止屏障已落实。此前 Client 自绘 Panel 和局部 conversation.content 嵌入均不满足完整原生界面目标。用户补充明确要求对话继续位于 CLI Worker 右侧栏，不能通过 openSession 替换父会话主页面；应使用公开 Renderer/slot 契约复用原生对话内容；最新截图明确顶部沿用原 CLI Worker 管理栏，去掉原生主页面包头。真实子会话 Provider 与 llm/stream waterfall 负责底层桥接。Codingns4DSH、CodexHost 仅作为机制参考，不复制其界面或内部交互实现。

## Goals / Non-Goals

**Goals:** 原生会话与界面，现有 CLI Agent 执行，受控 DSH 工具/技能桥，明确不可用能力，v0.8.1 可回退。

**Non-Goals:** 除用户 2026-10-16 明确批准的两个可选宿主扩展外修改 Harness 核心、复制 GPL 项目源码、静默升级旧原生会话、绕过宿主权限或自动审批、假造缺失的上下文和公开思考。批准范围与验收/安装顺序见 doc/native-conversation-host-extension.md，覆盖本次原先不修改核心的限制，不扩大为任意核心变更授权。

## Decisions

### 2026-10-18 Antigravity 本轮工具接入

使用 `--add-dir` 把只含本轮 MCP/Hook 配置的私有目录加入 AGY；不把整个私有请求目录作为工作区，不改 HOME、用户设置、项目 `.agents` 或模型/会话绑定。MCP 载体沿用现有 stdio carrier，连接凭据只经进程环境传递。原生 PreToolUse Hook 仅对结构化报告的当前专属服务器及实时目录精确匹配的工具申请 `auto_approve`，保留 AGY 显式 deny/ask 规则并仍由 Harness 逐次审批。其余调用不提升权限；目录撤销、会话冲突、停止和失败均拒绝准入。临时目录与原生进程一同清理。参考项目实现和当前安装版实际验证分开记录。

### 2026-10-18 附件与逐 CLI 工具桥

附件保留 DSH 原生上传、历史和消息身份；Host 通过公开 attachments 与 fs 服务解析路径，各 runner 根据自己的协议发送图片块、资源链接或可读取路径。输入去重包含附件身份；不将已提交附件的运行中消息降为纯文本引导。私有临时副本跟随受管进程清理，不改原附件。Skill/MCP 使用既有真实 child scope、临时注入、tools.execute 和取消链，按安装版能力逐项准入；无可靠入口者明确受限。macOS 与 Windows 共用模块，路径使用 node:path/node:url；桌面验收仅 Windows，最小关联检查不扩展为全量测试或发布。

11. 显示恢复有独立显式入口。错误页“修复显示会话”经 Gateway 调用 `repairHarnessConversation`，传入失败的精确显示身份；Host 在所属项目、Worker 空闲与互斥准备占用下，用官方只读查询确认 `SESSION_QUERY_CORRUPT_SESSION`，复核原 run 与归属后才 CAS 换绑。旧日志不改写，旧 Session 引用保留，新 child 只投影已有运行，不调用 CLI。可读取记录或未知/权限/网络错误不触发修复，普通查看不自动修复；新发准备阶段的明确 `subagent/not-resumable` 恢复仍保留独立入口。Client 取消等待并忽略切换后的迟到结果，不让旧快照撤销已确认的新显示绑定。

## Risks / Trade-offs

- rc.2 原生 InputBar 对 continuable 子 Agent 固定显示独立 Stop，主会话采用主按钮切换；公开参数没有选择此呈现规则的开关。真实子 Agent 身份和不修改 Harness 核心的现有约束下，此差异必须保留为未完成项，不能隐藏按钮、复制输入逻辑或伪造根会话。若用户仍要求主会话按钮规则，须提供可审阅的宿主扩展方案后另行确认核心修改范围。
- 原生每轮用量依赖真实模型响应/step 及 assistant settlement，不能将显示行人为拆成模型调用，也不能把 CLI 会话累计值写成单次 usage。真实 reasoning、text 和工具须按协议证据归组；外部工具仅展示已执行结果，不能由原生 AgentLoop 二次执行。
- 新 run 暂无用量时，应继续展示同一 CLI 会话已确认的累计快照；新身份不得继承旧会话统计。CLI 未公开的思考、上下文分类或用量继续未知，不为显示原生组件而编造。
- 原生控件没有全部细粒度公开接点 → 通过公开 Renderer/slot 在侧栏组合宿主原生结构，叶子能力精确绑定实际 CLI 动作；不能用全页跳转、禁用全部模型/权限选择或隐藏指标来宣称完成。
- 分段投影与原生step不同 → 同一run事件只消费一次，真实工具边界分段，恢复不重执行。
- 长任务、取消、MCP回执竞争 → 稳定call ID，停止拒新请求并取消/等待在途，结果不明不重发。
- Hermes安全模式和AGY配置注入未解决 → 明确不可用，不导入用户全局配置。

新增独立的完整 run checkpoint，在同 CLI/session 新轮尚无数值时保留原 runId/scope，原生 StatsPills 详情注明范围；不把该值升级成 session 累计。旧 turn/run 关系仅允许通过已接收请求ID与原生闭合turn/step精确恢复，读取时内存投影，不改历史。

### 2026-10-17 补充数据接口与 Desktop 验收

本阶段保持十一 CLI 的真实 Agent、模型选择、原生保护及既有 transport。依次检查协议原始事件、只读查询、CLI 官方扩展生命周期和精确会话持久化；只接受同一 Worker/run/session/model 身份对应的数据。参考实现与本机安装版本分别验证，不执行参考仓库代码，不将旧版 Wire 等接口直接套给新版 CLI，不修改用户全局配置或现有 skill。

对 Hermes 等有官方生命周期 observer 的 CLI，允许在本轮私有运行目录注入本插件自有只读观察扩展，观察原 Agent 的已发生 provider 响应。观察文件/回环通道必须绑定随机 nonce、精确 session/run 和原生 request 身份，限制大小/字段、去重并核对顺序；不改模型输出、工具结果、权限或请求，不触发额外模型/计数API。只投影数值与公开过程，凭据、完整请求和内部隐藏推理不进入日志或公开DTO；停止/失败释放监听和临时文件。缺少 hook/版本合同明确回退到既有执行通路的数据能力，不能重复提交任务。

系统提示、工具定义和历史消息分类只有当前 CLI 自己公开的估算/实测才能接入；区分 reported 与 native_estimate。仅有占用与容量时保留已知总值，不能把未知分类补零。账单总量超过可解释分类时保留原始总量与缺失范围，是否能进入 DSH 原生来源按其实际类型合同决定，不裁减账单。身份冲突、序列断裂、不完整或跨进程迟到数据不得提升为完整 run/session 累计。

安装沿用已授权的宿主可选扩展和四包构建，不改普通 DSH 默认行为；先最小回归、typecheck、隔离 preview 与实际完整原生视图验证，再协调共享 Desktop，核空闲、备份、正式 build、更新精确扩展条目并冷启动。安装前后核对用户持久数据，新增实测只在独立明确标注测试会话中进行，使用已保存获授权选型；无订阅/不明选型不试探或静默换模型。保留 Windows 和未完成真实账号验证。

可选原生投影补充 `tokenUsage.externalUsage` 与每轮 `externalUsage`：完整 run 的已知总量与可选明细分开，输入口径明确 inclusive/uncached，OMP 编排桶只认实际上报值，未知缓存不显示命中率；未分类余量不生成新桶。`contextPressure.externalContext` 保留来源、估算标记与 CLI 原始分类，分类非闭合时原生 ContextMeter 不伪造比例。已有原生投影无该字段时行为保持。

### 2026-10-17 完成回复空白回归

同一无响应身份的 CLI 叙述段中，正文和晚到的公开推理保持同一原生请求的独立 block；等待进程清理不产生额外空步骤。真实工具、用户输入或确定的 CLI 响应边界仍分开。错误或中断保留已完成前缀，遵循 AgentLoop 的落盘规则。

旧版本已保存的末尾推理/空步骤采用可选 externalTurnAnswer 投影修复显示。Host 根据精确 Worker/父子会话、turn/run、成功结果与连续原生事件证明既存答案位置，只提供 seq、step、messageId、turnEndSeq，不传入替代正文。原生 ChatView 再核对闭合轮次与全部后续节点，统一调整过程和答案位置；普通 DSH 会话维持原策略。工具、真实用户输入、新正文、未闭合或证据不足均拒绝覆盖。原会话日志不重写，同一子会话历史映射在续聊时继续有效，绑定变化立即清除。

用户后续截图证明仅恢复答案锚点仍不足：晚到过程沿事件顺序排在正文下方。验收因此继续保持未完成。原生 ChatView 在已二验的 turn 内调整有效呈现条目顺序，将对应公开过程放在既存答案上方；沿用原 node/group key、组件和展开 store，不靠 CSS 重排或复制正文。模拟与真实历史验收必须检查纵向顺序，不能只检查元素存在或可点击。上下文另核精确 used/limit 与源头，百分比为原生格式化结果，不能因视觉上显示 0 就补造非零数据。


### 2026-10-17 十 CLI 同标准复查

### 2026-10-17 七个实际样本驱动的后端适配修复
