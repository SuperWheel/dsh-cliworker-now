# Spec Delta

## Purpose

将多 CLI Worker 的会话身份接入 Harness 原生会话和界面，同时保留 CLI Agent 的执行、账号、原生协议及既有调度契约，避免界面复用造成重复执行、历史覆盖或模型回退。

## ADDED Requirements

### Requirement: 原生附件输入适配

系统 SHALL 通过宿主公开附件存储和路径映射解析本会话上传的图片及文件，并按所选 CLI 的真实协议提交；MUST 保留原生历史、消息身份、权限和取消清理，不修改用户源文件。macOS 与 Windows SHALL 使用同一能力判定和转换逻辑。

#### Scenario: 文件与图片提交
- **WHEN** 用户在支持附件的 CLI 子会话中提交文本、图片或文件
- **THEN** 解析真实附件并传入该 CLI 的原生内容块或可读取路径；纯附件消息也可执行，失效或不支持的输入在启动前明确拒绝

#### Scenario: 复用原生桌面引用与图片上传
- **WHEN** 用户从 macOS 或 Windows Desktop 的 CLI 加号菜单选择附件
- **THEN** 普通文件通过宿主公开路径桥和输入引用接口进入原生草稿，图片调用原生 File action 并保留原生上传生命周期；缺少真实桌面路径时不得伪造文件引用，浏览器普通文件回执不受支持时明确保留限制

#### Scenario: 路由图片输入不代表模型视觉能力
- **WHEN** 原生子会话图片经私有 CLI 转发路由准入
- **THEN** 路由按真实 transport 的附件转换能力声明图片输入，不进入主模型目录、不猜测实际模型视觉；ACP 仅在明确公布 image prompt 能力时发送图片块，其他情况传入验证后的可读取路径

#### Scenario: 附件重试及运行中排队
- **WHEN** 相同消息身份重试、附件身份改变，或生成期间提交附件
- **THEN** 相同内容最多执行一次，附件不同则拒绝复用旧回执；生成期间保留原生队列，不能丢弃附件转为纯文本引导

#### Scenario: 取消与平台路径
- **WHEN** 附件读取、启动或执行被取消，或文件路径含空格、中文及 Windows 盘符
- **THEN** 不拼接 shell 命令，使用原生路径/URI 转换，等待受管执行结束再清理本轮副本，原生附件保留

### Requirement: 当前官方宿主版本的原生兼容

系统 SHALL 为已安装的 DSH 0.2.1-rc.1 使用该版本官方完整视图和真实子 Agent 生命周期，保留已授权可选呈现与数据接口，MUST NOT 把旧版原生 bundle 覆盖到新版宿主或修改普通对话的默认行为。

#### Scenario: 新版子 Agent activation
- **WHEN** 宿主提供 startActivation/drainChildren 接口
- **THEN** 使用 caller delivery 并维持父级 catalog 归属；结果只观察一次，停止与卸载释放精确 activation 句柄，工具仍通过真实 child scope 的官方权限执行；不启动额外 DSH 模型

#### Scenario: 旧版与新版构建隔离
- **WHEN** 本地已有 rc.2 依赖而验收目标为 rc.1
- **THEN** 选择完整、固定版本的独立 rc.1 依赖图完成类型检查、代码生成和构建，拒绝混用版本，不改共享依赖或用户 Desktop；兼容旧版须有其真实 API 回归证据

### Requirement: 连续运行的真实统计保持

系统 SHALL 在同一CLI/session的下一轮尚未产生有效统计时保留已确认累计用量与最近上下文；MUST 区分初始化占位、当前真实零和明确未知。上下文 MUST 精确绑定模型，旧会话或不相干模型不得继承。

#### Scenario: 续聊等待及生成初期
- **WHEN** 同一会话提交新消息且原生CLI只发初始化零或尚无新统计
- **THEN** 原生底部不清成0，已有账单和有效上下文保持；新的有效回执到达后更新，不把上一轮run用量变成session累计

#### Scenario: 明确未知或身份切换
- **WHEN** 新请求明确报告缺失、模型或原生会话已改变、旧回执迟到
- **THEN** 清除不再有效的上下文或分类，拒绝旧回执；不以保留显示为由污染当前数据

### Requirement: 当前版本原生状态与请求组成补充

系统 SHALL 使用Grok自身声明的状态订阅和ZCode精确原生请求组成补全可核验数值；MUST 保持账单、上下文压力和分类估算独立。

#### Scenario: Grok状态能力及模型更新
- **WHEN** 当前Grok支持官方statusLine能力并报告同session状态及所选模型容量
- **THEN** 初始化协商该能力并持续接收对应状态，原生上下文估算和容量进入同一视图；不增加模型或计数API请求

#### Scenario: ZCode完整请求分类
- **WHEN** 当前或历史main_turn可通过session/turn/request/model精确绑定其专属model-io完整请求
- **THEN** 用同CLI已验证估算规则分别计算真实system/tools/messages，仅发布数值，不以字符占比拆账单、不改历史、不保存请求副本

#### Scenario: 分类请求证据不完整
- **WHEN** 仅有delta、记录过期、文件过大、身份不符或无法确认原生估算规则
- **THEN** 保留已知总量，分类为未知；不能读取其他会话或发新任务补算

### Requirement: 单个子对话整体复用官方视图
系统 SHALL 保留 CLI Worker 父级管理页及侧栏顶部，仅在单个子 Agent 的对话区域挂载 DSH 官方完整侧栏对话入口。正文、输入、排队与状态逻辑 MUST 由原生视图统一管理，CLI 适配层只提供有证据的数据及实际后端动作，不自行拼装或重写对话状态机。

#### Scenario: 从管理页打开子对话
- **WHEN** 用户在原 CLI Worker 父级页面选择一个 Worker
- **THEN** 原管理导航、返回、标题与任务操作保持原状，官方完整侧栏对话运行在其下方；主页面继续显示父会话，子 Agent 不进入普通列表

#### Scenario: 运行期间统计连续
- **WHEN** 同一 CLI 会话开始下一轮但暂未提供新用量
- **THEN** 原生统计保留该会话已确认的累计快照，不因切换 run 隐藏已有数据，不重复累加累计值；CLI 会话身份改变时不沿用旧值

#### Scenario: 原生过程和每轮用量
- **WHEN** CLI 提供可核验的模型响应边界、公开 reasoning、工具过程或单次调用 usage
- **THEN** 适配成同一次响应的原生事件与结算，由原生过程和消息尾组件呈现；不把每条显示行造为独立调用，不把会话累计写为单次用量，不补造未公开思考，已执行工具不二次执行

#### Scenario: 宿主公开接口存在交互差异
- **WHEN** 官方完整视图仍因真实子 Agent 身份显示与目标主会话不同的行为，且公开接口无法调整
- **THEN** 保留可审阅的差异与源代码证据，不能以隐藏控件或伪造身份宣称完成；超出独立插件范围的宿主核心变更另行确认

### Requirement: 真实原生子会话
系统 SHALL 为迁移后的 Worker 绑定真实 Harness 直接子会话，并独立保存 Worker、Harness 会话与 CLI 会话身份。子会话 MUST 关联所属主对话并沿用原生 `origin: subagent` 的普通会话列表排除规则，由 CLI Worker 打开管理，不创建独立根会话入口。Client MUST 在 CLI Worker 右侧栏复用原生对话内容与交互，顶部沿用原 Worker 返回、标题和任务操作，不额外显示主页面包头、父面包屑或对话/轨迹页签；主页面继续显示父会话；使用真实子会话身份与公开 Renderer/slot 契约，不复制参考项目界面或借用父会话草稿。

#### Scenario: 打开及恢复
- **WHEN** 用户打开已绑定 Worker 或重开历史
- **THEN** 核对真实子会话身份及读取状态后在右侧栏显示原生消息、输入与原 Worker 返回管理入口，保持父会话主页面；不产生新的 CLI 请求，不覆盖旧记录

#### Scenario: 返回主对话
- **WHEN** 用户关闭侧栏子对话或返回 Worker 管理列表
- **THEN** 主页面始终保留父会话，CLI Worker 管理面板不自动重新打开该子会话；子 Agent 仍不出现在普通会话列表

#### Scenario: 显式修复损坏的显示会话
- **WHEN** 原生显示读取失败，用户点击“修复显示会话”，且 Host 确认原项目、精确归属、同一 run、Worker 空闲、原 child 无活动 Agent 或投影，并在互斥准备占用下通过官方只读查询收到明确的 `SESSION_QUERY_CORRUPT_SESSION`
- **THEN** CAS 更换同父会话下的内部显示绑定，保留旧 Session 引用与 Worker 历史，仅投影已有运行；不启动 CLI、不重新提交原 prompt，也不改变 CLI 会话、账号或保存选型

#### Scenario: 拒绝不满足条件的显示修复
- **WHEN** 用户只查看或重新打开记录，或显式修复时发现记录可正常读取、身份已变化、任务仍忙、原 child 仍活动，或查询失败并非明确损坏
- **THEN** 不自动轮换显示绑定、不重跑任务；显式操作失败时显示实际原因，迟到旧快照不能覆盖已经确认的新绑定

### Requirement: CLI 生成与唯一执行
迁移会话 SHALL 使用明确选择的 CLI 和保存选型生成回复；原生会话创建、重开和消息重放 MUST 不重复执行。既有互斥、权限、停止清理、排队及独立引导契约持续生效。

#### Scenario: 完整原生交互
- **WHEN** 用户打开 Worker 子对话并发送、连续发送、编辑或移除待发消息
- **THEN** 在右侧栏使用真实原生 Session/Agent inbox 行为；不替换内部输入组件、键盘合同或会话投影，不维护第二套新消息队列；Host 按真实子会话领取的输入只启动一次 CLI 运行

#### Scenario: 合批输入的冷恢复重试
- **WHEN** 多条原生消息合批接收后重建 Host 或会话桥，客户端单独重发其中一条原 RPC 身份
- **THEN** 根据持久的逐消息正文摘要、批次身份及接收回执去重；不重复执行或写入用户消息，不阻断后续不同输入，同身份不同正文被拒绝

#### Scenario: 接收结果未确认
- **WHEN** 原生批次的接收回执尚未确认且无法从 Worker 证据核对
- **THEN** 明确报告状态不明，禁止自动重发，并把已领取的消息按原 ID 放回真实原生队列，保留编辑和移除能力

#### Scenario: 运行中原生排队
- **WHEN** CLI 正在运行时原生输入向 next-turn 队列提交多条消息
- **THEN** 保留真实待发消息及编辑/移除能力，不在收到消息后静默删除；当前轮结束后按宿主原生规则消费

#### Scenario: 运行中 next-step 输入
- **WHEN** 用户在 CLI 运行时提交原生 next-step 消息
- **THEN** 对当前 CLI/transport 已确认支持的原生引导，保持原 RPC 身份交给现有运行并等待实际接收回执；不支持时保留真实 Inbox，在当前完整 CLI run 及清理结束后消费。不能用停止重启冒充引导，结果不明不得自动转为下一轮或重复发送

#### Scenario: 未支持的原生能力
- **WHEN** 某 CLI 尚未接通附件、next-step 引导或模型辅助操作
- **THEN** 仅对该能力原位标注具体不可用原因，不以 Worker 自绘输入或停止重启冒充原生交互；主发送、排队和停止不因此整体禁用

#### Scenario: 停止与竞争
- **WHEN** 用户停止或原生输入与旧回执竞争
- **THEN** 停止仍等待受管范围退出，旧回执不启动或取消新轮

#### Scenario: 工具中断与恢复
- **WHEN** 用户在工具运行时停止 CLI，随后明确继续对话
- **THEN** 原生投影完整结算已公开工具记录并显示用户停止；无效旧投影只可轮换其严格所属内部绑定并保留旧引用，CLI 会话和 Worker 历史不改写且旧提示词不重跑

### Requirement: 不可用能力明确禁用
系统 SHALL 按真实能力显示原生控件。参考项目亦无可用接法或尚未安全接通时 MUST 禁用操作并提供鼠标悬停及键盘可达的中文原因，不用假按钮或静默改道。限制 MUST 以 Host 登记的精确 CLI 子会话身份为边界，不因同项目或父关联影响普通 DSH 会话。

#### Scenario: 不支持功能
- **WHEN** 用户悬停不可用附件、分支、模型操作或调度控件
- **THEN** 显示具体不可用原因且点击不产生调用

#### Scenario: 普通父会话不受能力限制
- **WHEN** 主页面或其他面板显示未登记为 CLI 子会话的普通父会话或其他会话
- **THEN** 保留其原生模型、权限、规划和上下文控件行为，不沿用 CLI 子会话 guard

### Requirement: 无 DSH 模型回退
迁移会话的模型路由 SHALL 明确归属 CLI；恢复、主生成和辅助请求 MUST 不静默回退至 DSH 真实模型 Provider。尚未接通的辅助生成保持不可用，其他普通 DSH 会话不受影响。

#### Scenario: 路由丢失或辅助生成
- **WHEN** CLI 绑定缺失、停止后失效或请求尚未支持的辅助生成
- **THEN** 明确失败或禁用，不调用 DSH 真实模型，不转投其他 CLI

### Requirement: 原生位置的 CLI 设置与统计
系统 SHALL 直接复用 DSH 原生组件和交互，不绘制视觉近似替代品；在侧栏原生输入区提供可选择的模型/强度和权限入口，复用既有 CLI 目录、Worker 设置和宿主授权边界；MUST 不以只读文字或统一禁用替代已可用的选择能力。输入区下方 SHALL 保留运行统计、用量/缓存、上下文三个模块。

#### Scenario: 小占用与真实零
- **WHEN** 已知上下文占用大于0且不足1%，或实际值恰为0
- **THEN** 共享原生组件在底部、详情标题和无障碍名称一致显示最多两位小数，小于0.01%的正值显示<0.01%，仅真零显示0%；圆环和进度条使用精确比例，不因文字取整消失。非有限值、负数或无有效容量保持未知

#### Scenario: 原生上下文分类缺失
- **WHEN** CLI已提供上下文总占用和容量，但当前记录缺少完整的系统提示、工具、消息三分类
- **THEN** 原生详情保留分类位置、未知读数及明确缺失说明，不将未知补零或把累计账单拆成分类；已提供的原生CLI额外分类保留真实标签和估算来源，不伪装为闭合三桶

#### Scenario: 保留旧协议的实际会话
- **WHEN** 已有 Worker 继续使用其保存的旧 transport，而新 Worker 默认采用另一原生协议
- **THEN** 按实际协议解释缓存桶、统计作用域、响应边界和公开过程；不静默迁移会话、不把新协议支持情况当成旧会话已接通，不把 run 合计伪装为最后一次模型响应的用量

#### Scenario: 跨 CLI 数据接线验收
- **WHEN** 核查完整原生侧栏在某 CLI 缺少统计或过程入口
- **THEN** 对该 CLI 实际公开协议及保留旧协议逐项追踪到原生状态来源，修复已提供但漏接的数据，记录没有公开来源的字段；不生成隐藏思考、不猜上下文容量，也不以单个 CLI 或模拟数据通过宣称全部 CLI 验收

#### Scenario: 选择模型与强度
- **WHEN** Worker 空闲且原生与旧兼容队列没有待处理消息，用户打开模型入口并选择该 CLI 真实目录中的模型/强度
- **THEN** 按当前 Worker 账号和项目保存选择，后续同一 CLI 会话使用新选择；不启动任务、不切换 CLI、不调用 DSH 模型

#### Scenario: 权限选择与忙碌边界
- **WHEN** 用户打开权限入口并选择当前 CLI 支持且不超过宿主授权的模式
- **THEN** 将选择保存到该 Worker 后续运行的真实权限配置；运行中、待处理消息或不支持的模式明确锁定并说明原因，不改变父会话权限

#### Scenario: 原生权限外观
- **WHEN** CLI 的规划和编辑模式接入原生 PermissionSelect
- **THEN** 仅在公开控件数据中映射为原生 read-only/workspace-write preset，由原生组件绘制图标、菜单和窄栏布局；保存反向映射 CLI 模式，不增加全权限选项或自绘按钮

#### Scenario: 历史子会话的规划状态
- **WHEN** 已结束的历史 Worker 子 Agent 未驻留，用户在空闲侧栏切换规划或编辑模式
- **THEN** 系统通过宿主公开的会话持久化与投影接口同步该子会话的真实规划和权限状态，原生输入状态随之更新；不创建输入、不启动 Agent、CLI 或模型，持有写锁期间互斥，结束或失败时释放资源，原生日志有未结束轮次或待发输入时拒绝修改

#### Scenario: 三个统计模块
- **WHEN** 用户打开任一 Worker 子对话
- **THEN** 侧栏输入区下方使用 DSH 原生运行统计、用量/缓存、上下文三个组件及其弹出详情；值来自当前 CLI 的实际遥测，不取父会话统计或 DSH 投影估算。未知数据不伪造，遵循原生组件对缺失值的呈现，并明确缺失边界

#### Scenario: AGY 真实统计口径与宿主环境
- **WHEN** AGY 会话具有实际输入、输出、缓存读取和本地上下文元数据
- **THEN** 将其互不重叠的 Token 桶交给原生组件汇总，保留 CLI reported total 不含缓存的事实；上下文从同一 CLI 会话只读获取，跨 JavaScript realm 的合法二进制数据仍可解析，不因类型识别错误隐藏组件，不放宽路径、归属或数值校验

#### Scenario: SQLite 只读连接的共享内存更新
- **WHEN** 读取同一 AGY 会话的上下文时，仅 SQLite 共享内存文件的修改时间因读锁发生变化
- **THEN** 保留已成功解码的上下文，不把共享内存读锁变动当成消息内容变化；仍核对数据库、WAL 的内容文件戳和全部文件安全属性，读取期间数据库或 WAL 变化时拒绝不稳定结果


### Requirement: 补充数据来源与原生可观察性
系统 SHALL 在当前协议之外核查同版本 CLI 的公开查询、官方观察扩展和精确只读持久化来源，接通可证明的用量、缓存、上下文和公开过程；MUST 保留原 Agent、保存选型、权限与会话身份，不为统计触发额外模型调用或静默切换执行协议。

#### Scenario: 首轮尚未返回统计
- **WHEN** 新子会话首次运行尚无账单、已结算步骤或上下文数据
- **THEN** 完整原生视图通过显式 availability 显示原生三个统计模块的未知态与原因；不得填零、制造速度或从父会话继承，真实数据到达后由原生组件更新。未提供扩展 projection 的普通 DSH 会话保持原行为

#### Scenario: 上游错误但 SSE 静默
- **WHEN** 官方请求观察接口记录真实请求或错误，而运行流暂未产生新消息
- **THEN** 有界串行观察仍更新当前 run 的原生请求状态，下一次实际请求证明重试开始；不猜测重试倒计时、策略、账单、思考或工具。观察结束、切换、取消不向其他 run 发布迟到状态

#### Scenario: Hermes 原生服务计划停止
- **WHEN** 已完成 Hermes HTTP 运行后插件清理其受管服务进程
- **THEN** 使用该 CLI 官方计划停止合同并等待退出，不以被官方视为意外中止的信号覆盖成功结果；自然崩溃、非零退出或无法确认退出仍报告错误，其他 CLI 停止方式不变

#### Scenario: Hermes 默认缓存零缺少原始证据
- **WHEN** HTTP、legacy、observer、数据库或旧快照中的缓存零来自 Hermes canonical 归一化，缺少提供方字段存在证据
- **THEN** 只读投影保留已报告总量、输入、输出及正缓存计数，把无证据零视为未知，使用原生部分用量详情；不改写历史、不冒称完整四桶，其他 CLI 的已知零不受影响

#### Scenario: 当前协议缺少数据而官方观察接口可用
- **WHEN** 同版本 CLI 在原 Agent 生命周期公开响应 usage、容量或上下文来源
- **THEN** 通过本轮隔离的只读观察通道接收并核对 session/run/request 身份后送入原生视图，不新建用于统计的 Agent、不改用户全局扩展/配置

#### Scenario: 不支持或不完整的补充接口
- **WHEN** 当前版本缺接口、观察初始化失败、字段缺失或身份不符
- **THEN** 保持原执行的真实结果，拒绝不可信数据并记录具体原因；不自动重发、不补零、不把旧版本实现当成当前能力证明

#### Scenario: 数据范围与生命周期
- **WHEN** 多响应、重试、压缩、停止或后续运行产生观察事件
- **THEN** 每请求最多结算一次，run/session/context 范围独立，原生估算保留来源，停止等待观察与进程清理，旧回执不污染新运行

#### Scenario: Desktop 验收
- **WHEN** 最终隔离候选通过验收且共享 Desktop 无活动任务
- **THEN** 备份并安装候选，冷启动在真实完整原生侧栏验证已知统计、未知边界、运行中保留和过程展开，保持父管理页、主会话及历史身份；真实模型、模拟与未验证平台分别记录

### Requirement: 完成正文不得被桥接空尾步骤隐藏

桥接层 SHALL 在无独立响应身份的同一 CLI 叙述段中保持正文和公开推理的原生 block，等待进程退出 MUST NOT 产生新的空答案步骤。已保存的受影响对话 SHALL 通过严格验证的可选答案位置投影恢复原生显示，MUST NOT 改写历史、伪造正文或改变普通 DSH 会话规则。

#### Scenario: 正文先于公开推理和进程清理
- **WHEN** CLI 先返回正文，再返回同一叙述段公开推理及完成事件，随后退出
- **THEN** 原生折叠过程之外仍显示最终正文，并保留原生推理展开和消息用量；展开的原生过程位于最终正文上方，保持原生呈现次序

#### Scenario: 历史受影响的成功轮次
- **WHEN** Host 已证明父子会话、Worker、成功 run、闭合 turn 与既存正文位置，后续仅有桥接 continuation 和推理或空步骤
- **THEN** 原生视图对精确 seq、step、messageId 和 turnEndSeq 二次核对后显示该既存正文；对应公开过程使用原生节点和状态位于正文上方，历史记录保持原字节

#### Scenario: 不可信或过期答案位置
- **WHEN** 映射跨身份、事件有缺页或后续存在真实输入、工具、新正文、未闭合轮次
- **THEN** 宿主拒绝该映射并使用原生默认规则，不展示来自其他轮次的答案


### Requirement: 十 CLI 同标准的运行态数据链

系统 SHALL 对所有当前 CLI 使用同一完整原生侧栏，按各自已验证协议保留公开过程、用量和上下文；MUST 将初始化占位、当前已确认数据及显式未知分开。可取得的只读运行态统计 SHALL 进入共享数据源，不等待整个 CLI 运行结束才更新。

#### Scenario: 运行态统计与进程结束竞争
- **WHEN** 原生 CLI 公开同进程只读统计且一轮中存在多次响应
- **THEN** 可在确认会话后及响应边界有界读取，同一次快照不重复相加，晚到/外来会话回执不覆盖当前结果；查询失败不得重发任务或阻止正常结束

#### Scenario: 缺数据不借用其他 CLI
- **WHEN** 某 CLI 只有上下文总量、容量或部分分类
- **THEN** 同一原生组件显示其已知字段和缺失原因，内部保留来源与估算标记；不借用 Hermes 分类算法、模型窗口或其他 CLI 账单口径

### Requirement: 原生上下文弹层只展示必要统计

原生 ContextMeter SHALL 对所有 CLI 统一保留上下文占用、容量、进度条及系统提示词/工具定义/对话消息三行；MUST NOT 渲染“分类来源／数据来源”说明或重复的原始分类列表。来源元数据 SHALL 在内部继续保留，未知与真零仍须分开。

#### Scenario: 完整或部分外部分类
- **WHEN** CLI 返回来源名称和完整、部分或额外分类
- **THEN** 弹层只展示原生三行及必要缺值原因，来源名称、重复英文项不出现；已知数值、比例和估算标记不变

#### Scenario: 等待或未提供上下文
- **WHEN** CLI 的上下文为等待、不可用或连接断开
- **THEN** 弹层显示相应缺值原因，不显示来源说明，也不把未知画为零

### Requirement: 实际 CLI 样本的完整协议和公开数据回归

系统 SHALL 对实际CLI运行的启动失败、公开过程和上下文分类使用精确会话与请求身份；SHALL 在存在官方数据通路时接入，不以模拟夹具已通过取代真实样本验证。

#### Scenario: 原生启动协议被拒绝或进程退出
- **WHEN** ZCode或Grok在初始化、会话配置或提交阶段拒绝协议或退出
- **THEN** 适配器保留可核验阶段和安全错误原因，按本机版本修复参数与生命周期，不自动换模型、放宽权限或重试任务

#### Scenario: 可取得的原生公开过程
- **WHEN** Pi、OMP或Antigravity原始会话含显式公开思考/工具事件
- **THEN** 转换为真实原生过程并在正文上方按原生交互展开，不因消息终态或分段漏掉；无公开数据不得生成占位推理

#### Scenario: 可取得的原生请求组成分类
- **WHEN** Pi、MiMo或OpenCode提供同会话请求组成的官方统计或估算原语
- **THEN** 绑定请求后投影系统提示词、工具定义和对话消息分类，保留估算语义、未知字段与来源内部校验，不添加来源说明行或从总账单摊分

#### Scenario: 请求观察隔离与未知失效
- **WHEN** 通过官方 hook 或本轮原生 provider 回环转发观察请求组成
- **THEN** 系统 MUST 保持原 CLI 身份、权限、HOME 与请求响应语义，仅发布经过精确请求校验的有界数值；无法分类的新请求清除旧分类，结束和停止后清理监听与进程，不能增加模型任务或保存凭据及完整请求


### Requirement: 宿主兼容采用能力检查

插件 SHALL 保留 DSH SDK peer 声明但 MUST NOT 仅按宿主版本号拒绝加载或设置最低版本；开发 SDK SHALL 精确固定用于可复现构建。系统 SHALL 检查执行所需的原生接口，Release SHALL 只记录实际验证过的宿主版本，不把放宽元数据称为所有版本已验收。

#### Scenario: 升级或降级但接口仍可用
- **WHEN** 宿主版本变化而所需接口仍满足当前能力合同
- **THEN** 插件不因版本号本身拒绝加载，按实际接口选择生命周期通路并保留原有会话归属

#### Scenario: 必需能力或扩展来源不匹配
- **WHEN** 宿主缺少必需接口，或可选原生四包扩展与验收源码及哈希不匹配
- **THEN** 相应能力或安装明确拒绝并说明缺失原因，不跨版本强套补丁、不改用户会话或借用其他CLI执行
