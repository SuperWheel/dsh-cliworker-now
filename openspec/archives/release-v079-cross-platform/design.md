# Design

## Context

参见 proposal.md。当前 HEAD 已包括 v0.7.9 行为修复；根 lib 链接至用户 Desktop。工作区另有不属于本次的素材与历史文档修改。

## Goals / Non-Goals

以相同冻结 tgz 在两个原生系统证明测试、安装和生命周期结果，再核对公开下载的一致性。不将模拟 CLI、旧版安装或既往真实模型结果表述为本轮全提供商实测。

## Decisions

- 使用 build:preview 构建并在隔离 profile 验收，避免更新正在被 Desktop 使用的根 lib。
- 隔离安装通过不代表正式 Desktop 已更新。用户要求可见桌面验收后，先检查活动任务，再以同一冻结包更新 Windows 正式 Desktop；保留原账号和会话，核验实际加载来源与最新交互，不以测试计数替代 UI 证据。
- 双平台分别跑完整测试，记录平台跳过原因；受限沙箱造成的环境失败保留原始记录，在已授权的正常环境重跑。
- 公开包由 package-release 脚本生成并审计边界，两个平台与三个渠道统一 SHA256。测试维护不改变 runtime 源码。
- 发布按 GitHub 提交/CI/Release、npm、既有 dshmarket PR 更新顺序执行；npm 传播延迟只轮询，不重复发布同版本。
- 定向暂存本次文件，历史文档只暂存新附录，不带入其他修改。

## Risks / Trade-offs

- npm 登录失效 → 使用正常网页登录，凭据仅留私有配置。
- pnpm 新版本等待期 → 保留官方限制并核对实际版本，提供固定 GitHub tgz。
- 原生账户与订阅范围有限 → 清楚列出自动、合成和真实执行证据及未覆盖边界。
- 发布渠道不可原子完成 → 记录每个阶段实际状态，失败时修复后续步骤，不覆写已发布版本。

## Migration Plan

先完成双平台门禁，再创建 v0.7.9 tag/Release、发布冻结 npm 包并更新既有 market PR。用户 profile 不批量迁移；紧急回退可安装已发布 v0.7.8 固定包，保留用户记录。
